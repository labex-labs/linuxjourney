Дистрибутивы Linux обычно предоставляют инструменты учётных записей из набора shadow, но значения по умолчанию и высокоуровневые оболочки различаются. Перед изменением локальной учётной записи убедитесь, что она не управляется централизованно, изучите локальную справочную страницу команды и сохраните путь восстановления.

Команды этого урока изменяют состояние аутентификации и владения. Практикуйтесь только в разрешённой одноразовой среде, а не на рабочем сервере.

## Проверка параметров создания учётных записей

`useradd` создаёт локальную учётную запись на основе параметров команды и настроек площадки. Проверьте встроенные и настроенные значения:

```bash
$ useradd -D
```

На поведение могут влиять `/etc/default/useradd`, `/etc/login.defs` и содержимое каталога-шаблона, но их роли зависят от дистрибутива. Может существовать высокоуровневая команда `adduser`, однако её интерфейс не стандартизован для всех систем Linux.

## Явное создание локальной учётной записи

В контролируемой среде задавайте важные свойства, а не полагайтесь на неизвестные значения по умолчанию:

```bash
$ sudo useradd -m -s /bin/bash -c "Bob Example" bob
```

- `-m` запрашивает создание домашнего каталога.
- `-s /bin/bash` выбирает оболочку входа после подтверждения, что путь разрешён и установлен.
- `-c` задаёт поле GECOS/комментария.

Новая учётная запись обычно не может пройти аутентификацию с пригодным локальным паролем до его установки, но точное начальное состояние пароля и блокировки зависит от локальных инструментов и политики. Проверяйте записи, а не предполагайте:

```bash
$ getent passwd bob
$ sudo passwd -S bob
$ id bob
```

## Установка или изменение пароля

Обычный пользователь интерактивно меняет собственный локальный пароль командой:

```bash
$ passwd
```

Авторизованный администратор может установить пароль другой локальной учётной записи:

```bash
$ sudo passwd bob
```

Вводите пароли только в защищённом приглашении, а не в аргументах команд, истории оболочки, заметках урока или чате. Политика PAM может отклонять слабые или повторно используемые пароли. Для учётных записей службы каталогов может требоваться другой инструмент.

::option[`useradd`]{#user-tools-add-not-password explanation="`useradd` создаёт запись учётной записи и не является обычной интерактивной командой смены пароля."}
::option[`userdel`]{#user-tools-delete-not-password explanation="`userdel` удаляет локальную учётную запись и не связана со сменой пароля вызывающего."}

## Изменение свойств и групп учётной записи

`usermod` изменяет поля локальной учётной записи. Примеры:

```bash
$ sudo usermod -s /bin/zsh bob
$ sudo usermod -d /srv/home/bob -m bob
$ sudo usermod -aG developers bob
```

Перед переносом домашнего каталога проверьте назначение, владельцев, свободное место, работающие процессы, точки монтирования и службы. Для дополнительных групп `-aG` означает добавление к текущему списку. `-G` без `-a` заменяет весь список и может неожиданно удалить доступ.

Изменения групп обычно влияют на новые сеансы входа, а не на уже запущенные процессы со старым набором учётных данных.

:::single-choice{#user-tools-append-group} Какая команда добавляет `bob` в дополнительную группу `developers`, не заменяя другие его дополнительные членства?

::option[`usermod -G developers bob`]{#user-tools-replace-groups explanation="Без `-a` параметр `-G` заменяет список дополнительных групп и может удалить существующее членство."}
::option[`usermod -aG developers bob`]{#user-tools-append-groups .correct explanation="Параметр `-a` добавляет группу, указанную через `-G`, сохраняя остальные дополнительные членства."}
::option[`groupdel developers bob`]{#user-tools-delete-group explanation="`groupdel` удаляет определение группы и не добавляет пользователя."}
:::

## Блокировка локального пароля

Администратор может заблокировать локальный хеш командой `passwd -l USER` и проверить состояние через `passwd -S USER`. Разблокировку `passwd -u USER` выполняйте только после выяснения причины блокировки и наличия допустимого хеша.

Блокировка пароля не обязательно останавливает ключи SSH, токены, запланированные задания, уже работающие процессы и аутентификацию отдельных служб. Чтобы комплексно отключить учётную запись, определите угрозу и пути доступа, затем примените согласованную политику, которая может включать истечение записи, оболочку входа, доступ служб, ключи и завершение сеансов.

::option[Все файлы, которыми сейчас владеет UID Bob.]{#user-tools-lock-files explanation="Состояние пароля не меняет владение файлами и не делает принадлежащие данные недоступными автоматически."}

## Осознанное удаление локальной учётной записи

Обычная `userdel bob` удаляет локальные записи, но обычно оставляет домашний каталог. `userdel -r bob` также пытается удалить домашний каталог и почтовый spool, поэтому является разрушительной операцией.

Перед удалением:

1. Подтвердите точную учётную запись через `getent passwd bob` и `id bob`.
2. Найдите работающие процессы, запланированные задания, службы, ключи и делегированный доступ.
3. Проведите инвентаризацию файлов, принадлежащих UID, в предполагаемых файловых системах.
4. Решите, нужно ли передать, архивировать, сохранить или безопасно удалить данные.
5. Убедитесь, что UID не будет назначен повторно, пока остаются файлы без учётной записи.

`userdel -r` не гарантирует удаление файлов за пределами настроенных домашнего и почтового расположений. После удаления могут остаться числовое владение файлами, права баз данных, идентичности приложений и записи удалённых каталогов.

:::single-choice{#user-tools-userdel-r-scope} Какое дополнительное удаление запрашивает обычная `userdel -r bob` по сравнению с `userdel bob`?

::option[Каждый файл с UID Bob во всех смонтированных файловых системах.]{#user-tools-delete-all-owned explanation="Инструмент не обнаруживает и не стирает универсально все принадлежащие UID файлы на всём хранилище."}
::option[Каждую удалённую учётную запись с именем `bob`.]{#user-tools-delete-remote explanation="`userdel` работает с применимыми локальными базами и не удаляет несвязанные идентичности служб каталогов."}
::option[Домашний каталог и локальный почтовый spool Bob вместе с записями учётной записи.]{#user-tools-delete-home-mail .correct explanation="Параметр рекурсивного удаления нацелен на настроенные домашний каталог и почтовый spool, но не на каждый объект Bob в других местах."}

## Итоги

Теперь вы можете управлять локальными учётными записями с явной областью и проверкой.

1. Проверяйте настройки `useradd` перед созданием.
2. Явно задавайте домашний каталог, оболочку и метаданные.
3. Меняйте пароли только через защищённые приглашения.
4. Добавляйте дополнительные группы, не заменяя существующий список.
5. Инвентаризируйте зависимости идентичности перед разрушительным удалением.
