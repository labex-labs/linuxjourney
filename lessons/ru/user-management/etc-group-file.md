`/etc/group` хранит локальные записи групп. Он сопоставляет имена групп числовым GID и перечисляет явных участников, обеспечивая общий доступ для нескольких учётных записей.

## Локальные и разрешённые группы

Файл является лишь одним из возможных источников групп. NSS может разрешать группы из локальных файлов, служб каталогов и других настроенных баз. Покажите локальные записи командой:

```bash
$ cat /etc/group
```

Запросите разрешённую базу групп через `getent`:

```bash
$ getent group
$ getent group developers
```

Списки групп могут раскрывать внутренние имена учётных записей и ролей, поэтому проверяйте вывод перед передачей.

:::single-choice{#group-query-resolved-database} Какая команда запрашивает разрешённую через NSS базу групп?

::option[`getent group`]{#group-getent-all .correct explanation="`getent` обращается к настроенным источникам записей групп NSS."}
::option[`cat /etc/group`]{#group-cat-local explanation="Эта команда читает только локальный файл и может пропустить группы из других источников."}
::option[`groups /etc/group`]{#group-groups-file explanation="`groups` ожидает имена пользователей и сообщает членство; путь локальной базы не является запросом NSS."}
:::

## Чтение четырёх полей

Локальная запись содержит четыре поля, разделённых двоеточиями:

```text
developers:x:1500:alice,bob
```

1. **Имя группы**: `developers`.
2. **Поле пароля**: обычно `x`, `*` или другой заполнитель; защищённые данные группового пароля могут храниться в `/etc/gshadow`.
3. **GID**: числовая идентичность группы, здесь `1500`.
4. **Список участников**: разделённые запятыми имена явных участников, здесь `alice` и `bob`.

Групповые пароли — устаревшая возможность, используемая инструментами вроде `newgrp` в некоторых конфигурациях. Это не обычный механизм предоставления авторизации sudo, и его не следует вводить ручным редактированием полей.

:::single-choice{#group-gid-field} Какое поле в `developers:x:1500:alice,bob` содержит GID?

::option[Второе поле, `x`]{#group-second-password explanation="Поле 2 — заполнитель группового пароля, а не числовая идентичность."}
::option[Четвёртое поле, `alice,bob`]{#group-fourth-members explanation="Поле 4 перечисляет имена явных участников, а не GID."}
::option[Третье поле, `1500`]{#group-third-gid .correct explanation="Третье поле, разделённое двоеточиями, является числовым идентификатором группы."}
:::

:::single-choice{#group-explicit-member-field} Как представлены имена явных участников в локальной записи группы?

::option[Как разделённый запятыми список в поле 4.]{#group-members-field-four .correct explanation="Последнее поле содержит имена явных дополнительных участников, разделённые запятыми."}
::option[Как разделённый пробелами список в поле 2.]{#group-members-field-two explanation="Поле 2 предназначено для связанных с паролем данных или заполнителя, а не списка участников."}
::option[Как числовые UID, встроенные в имя группы.]{#group-members-in-name explanation="Имя группы и имена участников находятся в разных полях; обычные записи участников — имена входа, а не встроенные числа UID."}
:::

## Учёт первичного членства

Список участников `/etc/group` обычно не повторяет пользователей, у которых этот GID указан как первичный в записи passwd. Поэтому пользователь может входить в группу, даже если его имя отсутствует в поле 4.

Например, если первичный GID Alice равен 1500, она входит в `developers`, даже когда локальная запись группы оканчивается пустым полем участников:

```text
developers:x:1500:
```

Поэтому разбор только поля 4 даёт неполное представление о членстве.

:::single-choice{#group-primary-membership-visibility} В записи passwd Alice первичный GID равен 1500, но её имя отсутствует в поле 4 группы 1500. Является ли она участником этой группы?

::option[Нет, каждое членство обязано находиться в поле 4 `/etc/group`.]{#group-field-four-only explanation="Это игнорирует членство по первичному GID и занижает число участников."}
::option[Да, первичное членство задаётся полем GID записи passwd.]{#group-primary-from-passwd .correct explanation="Явный список группы в основном предназначен для дополнительных участников; первичное членство хранится вместе с учётной записью."}
::option[Только если поле пароля группы содержит её имя.]{#group-password-member explanation="Поле пароля не связано с объявлением первичного членства."}
:::

## Проверка групп пользователя

Для разрешённого представления учётной записи используйте `id USER` или `groups USER`:

```bash
$ id alice
$ groups alice
```

Для текущего процесса обычный `id` сообщает группы, действительно присутствующие в его учётных данных. Вновь настроенное дополнительное членство обычно не появляется в уже работающем сеансе входа; начните новый аутентифицированный сеанс или при необходимости используйте намеренно настроенный механизм вроде `newgrp`.

:::single-choice{#group-current-process-credentials} Какая команда сообщает UID, первичный GID и дополнительные группы текущего процесса?

::option[`id`]{#group-current-id .correct explanation="Без операнда пользователя `id` сообщает учётные данные идентичности текущего процесса."}
::option[`cat /etc/group`]{#group-current-cat explanation="Локальный файл перечисляет записи, но не показывает, какие разрешённые группы активны в текущем процессе."}
::option[`getent passwd`]{#group-current-passwd explanation="Эта команда запрашивает записи учётных записей и не сообщает специально список дополнительных групп текущего процесса."}
:::

## Безопасное изменение локальных групп

Используйте `groupadd`, `groupmod`, `groupdel`, `gpasswd` и `usermod`, а не редактируйте записи универсальным редактором. Особенно внимательно различайте:

- `usermod -aG GROUP USER`, добавляющую дополнительное членство.
- `usermod -G ...`, заменяющую список дополнительных групп, если `-a` опущен.

Если ручной ремонт локальной базы неизбежен, используйте `vigr` для блокировки и `grpck` для проверки. Перед удалёнными изменениями идентичностей сохраняйте путь восстановления.

## Итоги

Теперь вы можете интерпретировать локальные записи групп и точнее определять полное членство.

1. Запрашивайте настроенные источники через `getent group`.
2. Читайте четыре поля группы, разделённые двоеточиями.
3. Находите числовой GID и список явных участников.
4. Учитывайте первичное членство из записей passwd.
5. Проверяйте активные учётные данные, прежде чем полагаться на изменённое членство.
