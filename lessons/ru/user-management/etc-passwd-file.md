`/etc/passwd` хранит локальные записи учётных записей в текстовом формате с двоеточиями. Он сопоставляет имена входа числовым UID и хранит первичный GID, описание, домашний путь и программу входа.

## Локальные записи и разрешённые учётные записи

Покажите локальный файл командой только для чтения:

```bash
$ cat /etc/passwd
```

Это не обязательно все известные системе учётные записи. Name Service Switch (NSS) может разрешать их из файлов, служб каталогов, системных баз и других настроенных источников. Для запроса разрешённой базы passwd используйте `getent`:

```bash
$ getent passwd
$ getent passwd root
```

Первая команда может раскрывать имена и метаданные учётных записей, поэтому проверяйте вывод перед публичной передачей.

:::single-choice{#passwd-query-resolved-database} Какая команда запрашивает разрешённую через NSS базу passwd, а не читает только локальный файл?

::option[`cat /etc/passwd`]{#passwd-cat-local explanation="Эта команда показывает только локальный файл и не включает учётные записи, предоставленные исключительно другими источниками NSS."}
::option[`cat /etc/shadow`]{#passwd-cat-shadow explanation="Файл shadow содержит защищённые локальные данные паролей и их сроков и не должен отображаться для этой задачи."}
::option[`getent passwd`]{#passwd-getent-all .correct explanation="`getent` обращается через NSS к настроенным источникам базы passwd."}
:::

## Чтение семи полей

Локальная запись обычно выглядит так:

```text
root:x:0:0:root:/root:/bin/bash
```

Семь полей, разделённых двоеточиями:

1. **Имя входа**: понятное человеку имя учётной записи, например `root`.
2. **Поле пароля**: обычно `x` в системе теневых паролей, указывающий, что защищённые данные хранятся отдельно.
3. **UID**: числовая идентичность пользователя. UID 0 традиционно обрабатывается как суперпользователь.
4. **Первичный GID**: числовой идентификатор первичной группы учётной записи.
5. **GECOS/комментарий**: описательные сведения, часто внутренне разделённые запятыми.
6. **Домашний каталог**: путь, используемый как домашняя настройка учётной записи; он может отсутствовать на диске.
7. **Оболочка/программа входа**: программа для применимых сеансов входа, например `/bin/bash` или программа, запрещающая вход.

Ядро не требует уникальности UID в повреждённых или намеренно дублированных записях, но учётные записи с одинаковым UID неразличимы для многих решений о владении и правах. Обычно администраторы должны сохранять UID уникальными.

:::single-choice{#passwd-uid-field} Какое поле в `root:x:0:0:root:/root:/bin/bash` содержит UID?

::option[Второе поле, `x`]{#passwd-second-password explanation="Второе поле — заполнитель пароля, а не числовая идентичность пользователя."}
::option[Четвёртое поле, второй `0`]{#passwd-fourth-gid explanation="Поле 4 — первичный GID, а не UID."}
::option[Третье поле, первый `0`]{#passwd-third-uid .correct explanation="Поле 3 — UID, поэтому первый ноль обозначает UID 0 этой записи."}
:::

:::single-choice{#passwd-primary-gid-field} Какое поле записи passwd хранит первичный GID учётной записи?

::option[Поле 5]{#passwd-gecos-five explanation="Пятое поле — GECOS или комментарий."}
::option[Поле 4]{#passwd-gid-four .correct explanation="Четвёртое поле, разделённое двоеточиями, численно обозначает первичную группу."}
::option[Поле 7]{#passwd-shell-seven explanation="Седьмое поле задаёт оболочку или программу входа."}
:::

## Интерпретация заполнителя пароля

В типичных системах теневых паролей `x` в поле 2 направляет инструменты работы с паролями к защищённым данным в `/etc/shadow`. Значения вроде `*` и `!` не являются допустимыми хешами и обычно запрещают аутентификацию паролем Unix через эту запись.

Это не доказывает невозможность входа любым способом. Ключи SSH, сертификаты, токены и механизмы конкретных служб могут быть независимы. Поведение пустого поля пароля также зависит от стека аутентификации и имеет значение для безопасности; не создавайте и не «исправляйте» его вручную.

:::single-choice{#passwd-x-placeholder} Что обычно означает `x` в поле 2 локальной записи `/etc/passwd`?

::option[Учётная запись гарантированно не имеет никакого способа аутентификации.]{#passwd-no-auth-guarantee explanation="Заполнитель не описывает все возможные методы и сам по себе не означает неработоспособность учётной записи."}
::option[Домашний каталог учётной записи удалён.]{#passwd-home-deleted explanation="Домашний каталог хранится в поле 6 и не связан с заполнителем `x`."}
::option[Защищённые данные пароля хранятся в теневой базе.]{#passwd-shadow-placeholder .correct explanation="Публичная запись passwd содержит заполнитель, а хеш пароля и поля срока находятся в защищённых данных shadow."}
:::

## Служебные учётные записи

Многие записи представляют службы, а не людей. Отдельные служебные идентичности помогают ограничить файлы и процессы полномочиями одного демона. Их домашние пути могут быть нестандартными или отсутствовать, а программа входа — `/usr/sbin/nologin`, `/bin/false` или другая ограничительная программа.

Не определяйте назначение учётной записи только по диапазону UID без проверки политики дистрибутива. Диапазоны выделения различаются, а централизованно управляемые записи могут следовать другим соглашениям.

:::single-choice{#passwd-nologin-shell} Каково распространённое назначение программы входа `/usr/sbin/nologin` в поле 7?

::option[Удалять файлы учётной записи при остановке службы.]{#passwd-nologin-delete explanation="Программа входа не удаляет принадлежащие данные и не управляет файлами остановки службы автоматически."}
::option[Запрещать обычную интерактивную оболочку через пути входа, учитывающие это поле.]{#passwd-nologin-purpose .correct explanation="Программа без входа часто применяется для служебных учётных записей, которым не нужна интерактивная оболочка через обычный вход."}
::option[Предоставлять учётной записи те же привилегии, что UID 0.]{#passwd-nologin-root explanation="Ограничение интерактивного входа не повышает права и не меняет числовой UID."}
:::

## Безопасное изменение записей

Предпочитайте инструменты `useradd`, `usermod` и `userdel`: они согласуют связанные записи и применяют системные значения по умолчанию. Точное поведение настраивается дистрибутивом, поэтому изучайте параметры до изменения учётной записи.

Если локальной базе passwd действительно нужен ручной ремонт, используйте `vipw`, а не обычный редактор. Он применяет блокировку для предотвращения одновременных правок. Проверяйте базы инструментами вроде `pwck` и сохраняйте сеанс восстановления перед удалённым изменением файлов аутентификации.

Чтобы попрактиковаться с записями пользователей и групп в контролируемой среде, выполните лабораторные работы:

1. **[Управление учётными записями Linux с useradd, usermod и userdel](https://labex.io/ru/labs/comptia-manage-linux-user-accounts-with-useradd-usermod-and-userdel-590837)** — отработайте полный жизненный цикл создания, защиты, изменения и удаления учётных записей.
2. **[Управление группами Linux с groupadd, usermod и groupdel](https://labex.io/ru/labs/comptia-manage-linux-groups-with-groupadd-usermod-and-groupdel-590836)** — попрактикуйтесь создавать группы и изменять членство пользователей.

## Итоги

Теперь вы можете интерпретировать локальные записи passwd, не принимая их за полную базу идентичностей.

1. Запрашивайте разрешённые NSS учётные записи через `getent passwd`.
2. Читайте семь полей passwd, разделённых двоеточиями.
3. Находите поля UID и первичного GID.
4. Интерпретируйте заполнители пароля без чрезмерных выводов о входе.
5. Используйте инструменты учётных записей или `vipw`, а не обычный редактор.
