Перемещение файлов по сети охватывает как разовые копирования, так и постоянно подключённые общие ресурсы и синхронизируемые деревья каталогов. Выбирайте способ с учётом направления, объёма данных, частоты обновлений, модели идентификации, доверия к сети, требований к метаданным и необходимости постоянного совместного доступа клиентов.

## Выбор способа передачи

- `scp` или SFTP обеспечивает копирование с аутентификацией SSH либо интерактивную передачу.
- `rsync` эффективно согласует деревья каталогов локально или через транспорт, например SSH.
- NFS представляет экспортированные сервером ресурсы как подключённые файловые системы, обычно между Unix-подобными хостами.
- SMB, реализованный в Linux посредством Samba, поддерживает совместный доступ из многих операционных систем.
- HTTP подходит для простой загрузки файлов, но не является универсальной подключаемой файловой системой.

Копия не становится резервной автоматически. Для резервного копирования также нужны независимое хранение версий, проверка восстановления, контроль целостности и защита от того же удаления или взлома.

## Пути в scp

Общая форма команды — `scp SOURCE DESTINATION`. Удалённый операнд обычно записывается как `user@host:path`:

```bash
$ scp -- report.txt alice@example.net:/srv/incoming/
$ scp -- alice@example.net:/srv/outgoing/result.txt ./result.txt
```

Первая команда отправляет локальный файл, а вторая получает удалённый. Двоеточие отделяет удалённый хост от пути на нём. Заключайте в кавычки пути с символами, значимыми для оболочки, и избегайте неоднозначных недоверенных имён файлов.

:::single-choice{#file-sharing-scp-pull-source}
Где находится удалённая спецификация при получении файла через `scp`?

::option[В операнде источника перед локальным назначением.]{#file-sharing-pull-source .correct explanation="Направление копирования определяется порядком операндов от источника к назначению."}
::option[В локальном назначении после всех параметров.]{#file-sharing-pull-destination explanation="Получаемый удалённый объект является операндом источника."}
::option[Только в файле конфигурации SSH пользователя.]{#file-sharing-pull-config explanation="Конфигурация SSH может задавать значения по умолчанию, но копируемый удалённый путь всё равно остаётся операндом."}
:::

## Копирование каталога

Для дерева каталогов используйте рекурсивный режим:

```bash
$ scp -r -- project/ alice@example.net:/srv/incoming/
```

До копирования проверьте объём данных, символические ссылки, права, требования к владельцам, свободное место и имя назначения. SCP не задаёт политику синхронизации: повторное копирование каталогов может оставить в назначении файлы, которых уже нет в источнике.

## Проверка подлинности и результатов

Проверка ключа хоста SSH защищает от подключения к неверному серверу. Считайте изменение ключа событием, которое следует проверить через доверенный канал, а не поводом обойти предупреждение. Используйте учётные записи с минимальными привилегиями и подходящие для среды правила работы с ключами.

После передачи проверьте код завершения, ожидаемые файлы, размеры, метаданные, а при наличии требований к целостности — независимо рассчитанные хеши на обеих сторонах. Убедитесь, что приложение назначения действительно может прочитать данные.

:::single-choice{#file-sharing-host-key-change}
Что делать, если SSH сообщает о неожиданном изменении ключа хоста?

::option[Отключить проверку ключей хостов для всех будущих передач.]{#file-sharing-disable-checking explanation="Так будет удалён важный механизм проверки подлинности сервера."}
::option[До продолжения проверить новый ключ через доверенный источник.]{#file-sharing-verify-key .correct explanation="Предупреждение может означать переустановку хоста, неверное назначение или перехват, поэтому его нужно исследовать."}

Теперь вы умеете выбирать и проверять безопасное разовое копирование файла по сети.

1. Сопоставляйте способ общего доступа с потребностями в доступе и хранении.
2. Читайте локальные и удалённые операнды `scp` как источник и назначение.
3. Осознанно используйте рекурсивный режим для деревьев каталогов.
4. Проверяйте подлинность сервера, результат передачи и пригодность данных в назначении.
