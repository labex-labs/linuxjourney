Network File System позволяет клиенту обращаться к экспортированному сервером ресурсу через локальное пространство имён файловой системы. Сервер управляет экспортами и значительной частью политики доступа, а клиент — местом и временем подключения разрешённого экспорта.

## Подготовка клиента

Установите клиентские утилиты NFS для своего дистрибутива: обычно это пакет `nfs-common` в системах семейства Debian или `nfs-utils` в системах семейства Red Hat. Вместе с администратором сервера проверьте DNS или доступность адреса, разрешённые версии NFS, политику межсетевого экрана и точный путь экспорта.

`showmount -e SERVER` может перечислить экспорты, предоставляемые через старый протокол подключения, но этот список не является исчерпывающим для каждого сервера только с NFSv4. Неудача команды не доказывает отсутствие разрешённого экспорта NFSv4.

:::single-choice{#nfs-showmount-limit} Почему вывод `showmount -e` может быть неполным для сервера NFSv4?

::option[Команда запрашивает старый протокол перечисления экспортов, который может быть недоступен.]{#nfs-showmount-protocol .correct explanation="NFSv4 способен работать без предоставления отдельной службы перечисления."}
::option[Команда показывает только температуру локального процессора.]{#nfs-showmount-temperature explanation="Команда предназначена для сведений об экспортах сервера NFS."}
::option[Команда навсегда отключает каждый перечисленный экспорт.]{#nfs-showmount-disables explanation="Перечисление — запрос только для чтения."}
:::

## Подключение экспорта

Создайте пустую отдельную точку подключения и подключите разрешённый экспорт:

```bash
$ sudo mkdir -p /mnt/team
$ sudo mount -t nfs server.example.net:/srv/team /mnt/team
```

Указывайте версию только тогда, когда этого требуют политика или совместимость, например `-o vers=4.2`. Не угадывайте параметры производительности или безопасности. Проверьте итоговые источник, тип и параметры:

```bash
$ findmnt --target /mnt/team
```

:::single-choice{#nfs-mount-operands} Что в команде подключения означает `server.example.net:/srv/team`?

::option[Локальный каталог, который скрывает удалённый экспорт.]{#nfs-local-mountpoint explanation="Локальная точка подключения в примере — `/mnt/team`."}
::option[Имя клиентского пакета для установки.]{#nfs-package-name explanation="Имена пакетов зависят от дистрибутива и не являются операндами источника mount."}
::option[Сервер и экспортированный удалённый путь.]{#nfs-remote-export .correct explanation="Хост и путь после двоеточия определяют источник NFS."}
:::

## Идентификация и права

Доступ NFS сочетает правила серверного экспорта, безопасность протокола, числовые идентификаторы или службы каталогов и права файловой системы. Одинаковые отображаемые имена пользователей на двух хостах не гарантируют совпадения числовых идентификаторов. Традиционный `AUTH_SYS` передаёт предоставленные клиентом числовые идентификаторы и сильно зависит от доверия к клиенту и средствам контроля сети; в средах с более строгими требованиями можно использовать режимы безопасности Kerberos, если они настроены сквозным образом.

Обычно сервер сопоставляет удалённого пользователя root с непривилегированной учётной записью посредством root squashing. Не отключайте эту защиту лишь ради устранения ошибки прав: проверьте идентификаторы, владельцев каталогов, политику экспорта и требуемую модель безопасности.

:::single-choice{#nfs-name-versus-id} Почему два пользователя с одинаковым отображаемым именем могут получить разные права NFS?

::option[Права NFS могут зависеть от сопоставления числовых идентификаторов.]{#nfs-numeric-mapping .correct explanation="Совпадение имён само по себе не подтверждает, что клиент и сервер определяют одинаковые UID и группы."}
::option[NFS игнорирует все права файловой системы.]{#nfs-ignores-permissions explanation="Права файловой системы и экспорта остаются частью авторизации."}
::option[Каждое подключение автоматически изменяет базу учётных записей сервера.]{#nfs-changes-accounts explanation="Клиентское подключение не переписывает идентификаторы сервера."}
:::

## Автоматизация сетевых подключений

Обычная запись подключения при загрузке в `/etc/fstab` может задержать запуск, если сеть или сервер недоступны. В зависимости от хоста используйте `autofs` с картами по требованию либо параметры подключения systemd, например `_netdev,nofail,x-systemd.automount`, предварительно проверив их точную семантику:

```fstab
server.example.net:/srv/team /mnt/team nfs4 rw,_netdev,nofail,x-systemd.automount 0 0
```

Перед редактированием fstab обеспечьте доступ для восстановления и проверьте запись неразрушающим синтаксическим анализатором или контролируемым тестовым подключением. Автоматическое подключение улучшает поведение при недоступности, но не исправляет авторизацию, DNS или сбои сервера.

:::single-choice{#nfs-automount-benefit} Каково основное преимущество подключения ресурса NFS по требованию?

::option[Оно предоставляет каждому клиенту доступ root к экспорту.]{#nfs-automount-root explanation="Время подключения не отменяет авторизацию сервера."}
::option[Оно позволяет не требовать доступности сервера во время начальной загрузки.]{#nfs-automount-boot .correct explanation="Соединение создаётся при обращении, а не обязательно блокирует ранний запуск системы."}
::option[Оно копирует всю файловую систему сервера на локальный диск.]{#nfs-automount-copy explanation="Подключение предоставляет удалённый доступ, а не полную локальную копию."}
:::

## Отключение и проверка

Перед отключением остановите или скоординируйте процессы, использующие ресурс, и завершите запись приложений. Затем отключите точку подключения и убедитесь, что она исчезла:

```bash
$ sudo umount /mnt/team
$ findmnt --target /mnt/team
```

Принудительное или отложенное отключение может скрыть активные ссылки и вызвать ошибки приложений; применяйте такие параметры только при диагностированном сбое и с явным планом восстановления.

:::single-choice{#nfs-safe-unmount} Что следует сделать перед обычным отключением NFS?

::option[Скоординировать использующие ресурс процессы и завершить важные операции записи.]{#nfs-coordinate-writers .correct explanation="Удаление работающей файловой системы из-под приложений может прервать ввод-вывод или оставить работу незавершённой."}
::option[Удалить каталог экспорта на сервере.]{#nfs-delete-export explanation="Для клиентского отключения не требуется уничтожать данные сервера."}
::option[Отключить все сетевые интерфейсы клиента.]{#nfs-disable-network explanation="Это может усложнить нормальное завершение и не является обычной последовательностью."}
:::

## Итоги

Теперь вы можете работать с клиентским подключением NFS, явно учитывая идентификацию и доступность.

1. Проверяйте клиентские инструменты, путь экспорта, протокол и сетевую политику.
2. Подключайте ресурс к отдельному пути и проверяйте фактический источник и параметры.
3. Диагностируйте права через идентификацию и политику экспорта.
4. Если важна загрузочная доступность, используйте проверенное подключение по требованию.
5. Координируйте пользователей, отключайте ресурс обычным способом и проверяйте результат.
