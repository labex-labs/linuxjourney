Конфигурация Linux, сценарии, исходный код и журналы обычно хранятся как обычный текст. Терминальный редактор позволяет работать с такими файлами в локальном терминале, удалённом сеансе SSH или среде без графического рабочего стола.

## Выбор редактора с учётом среды

Не существует единственного редактора, лучшего для каждого человека и каждой задачи. Подходящими могут оказаться графический или терминальный редактор, а также интегрированная среда разработки. Для работы в командной строке выбирайте установленный редактор, из которого умеете безопасно выйти и базовую модель редактирования которого понимаете.

Не считайте, что Vim или Emacs обязательно установлен. Проверьте разрешение команды в текущей оболочке:

```bash
$ command -v vim
/usr/bin/vim
$ command -v emacs
/usr/bin/emacs
```

Пустой результат с ненулевым кодом завершения означает, что имя не найдено по текущим правилам поиска команд. В минимальной системе может быть доступен `vi`, в других — Nano или вообще ни одного интерактивного редактора.

:::single-choice{#editors-check-availability} Какая команда проверяет, может ли текущая оболочка найти исполняемый файл с именем `vim`?

::option[`vim --install`]{#editors-vim-install explanation="У Vim нет такой переносимой проверки установки, а способ установки пакетов зависит от дистрибутива."}
::option[`file ~/.vimrc`]{#editors-file-vimrc explanation="Команда определяет тип файла конфигурации, если он существует, но не показывает, доступна ли команда `vim`."}
::option[`command -v vim`]{#editors-command-v-vim .correct explanation="Встроенная команда оболочки проверяет разрешение имени и при наличии выводит найденную форму команды."}
:::

## Модель работы Vim

Vim — модальный редактор. Одна и та же клавиша может иметь разное значение в зависимости от активного режима:

- Нормальный режим воспринимает клавиши как команды навигации и редактирования.
- Режим вставки добавляет вводимый текст.
- Режим командной строки принимает команды, например для сохранения или выхода.

После практики такая модель ускоряет повторяющиеся операции с клавиатуры, но начинающему важно следить за активным режимом. В следующих уроках действия Vim будут вводиться по одному.

:::single-choice{#editors-vim-modal-meaning} Что означает модальность Vim?

::option[Каждый файл открывается в отдельном графическом окне.]{#editors-vim-windows explanation="Окна и буферы — отдельные понятия. Модальность описывает изменение поведения клавиш в зависимости от состояния редактора."}
::option[Vim может одновременно редактировать только один вид текстовых файлов.]{#editors-vim-file-type explanation="Vim поддерживает множество типов файлов. Модальность относится к модели взаимодействия, а не к ограничению форматов."}
::option[Клавиши выполняют разные действия в зависимости от активного режима.]{#editors-vim-modes .correct explanation="Например, в нормальном режиме клавиша запускает команду, а в режиме вставки вводит символ."}
:::

## Модель работы Emacs

Emacs обычно использует сочетания клавиш и именованные команды в расширяемой среде. Файлы открываются в буферах, а основные и дополнительные режимы настраивают поведение для разного содержимого и задач. Emacs может работать как в терминале, так и в графическом окне.

И Vim, и Emacs благодаря настройкам и расширениям умеют гораздо больше базового редактирования. Сначала научитесь открывать, изменять, сохранять и закрывать обычный текстовый файл, а затем переходите к персонализации.

:::single-choice{#editors-emacs-buffer} Где, согласно терминологии Emacs, обычно хранится редактируемый текст открытого файла?

::option[В буфере.]{#editors-emacs-buffer-answer .correct explanation="Emacs открывает файл в буфере, где находится просматриваемый или редактируемый текст."}
::option[В таблице псевдонимов оболочки.]{#editors-emacs-alias-table explanation="Псевдонимы участвуют в разрешении команд оболочки и не хранят текст редактора."}
::option[Только в истории вывода терминала.]{#editors-emacs-scrollback explanation="История терминала сохраняет показанный вывод, тогда как Emacs управляет редактируемым текстом в буферах."}
:::

## Выбор предпочитаемого редактора

Многие программы командной строки обращаются к `VISUAL` или `EDITOR`, когда им нужно запустить редактор. Например, так можно выбрать Vim для команд, запускаемых из текущего сеанса Bash и его дочерних процессов:

```bash
$ export VISUAL=vim
$ export EDITOR="$VISUAL"
```

Эти переменные задают предпочтение, но не устанавливают программу. Указывайте реально существующую команду, а добавляйте экспорт в подходящий файл запуска оболочки лишь после проверки.

:::single-choice{#editors-editor-variable} Что делает `export EDITOR=vim`?

::option[Сообщает будущим дочерним процессам, что предпочитаемый редактор — `vim`.]{#editors-export-preference .correct explanation="Экспорт помещает это предпочтение в окружение, наследуемое командами из текущей оболочки."}
::option[Устанавливает Vim для всех пользователей системы.]{#editors-install-vim explanation="Присваивание переменной окружения не устанавливает пакеты и не меняет системы других пользователей."}
::option[Заставляет все программы использовать клавиши Vim.]{#editors-global-bindings explanation="Программа может прочитать переменную, чтобы запустить редактор, но собственная модель взаимодействия программы от этого не меняется."}
:::

## Безопасная практика

Осваивайте редактор на одноразовом файле в принадлежащем вам каталоге:

```bash
$ printf 'first line\nsecond line\n' > editor-practice.txt
$ vim editor-practice.txt
```

Не начинайте с системной конфигурации или чужих данных. Перед изменением важного файла сделайте резервную копию, разберитесь с сохранением и выходом, а затем проверьте результат командой только для чтения, например `cat` или `diff`.

:::single-choice{#editors-first-practice-file} Какой файл безопаснее всего выбрать для первого знакомства с новым редактором?

::option[Критически важный файл загрузки, открытый от имени root.]{#editors-boot-file explanation="Случайное изменение может нарушить загрузку, а повышенные права увеличивают последствия ошибки."}
::option[Одноразовый текстовый файл в принадлежащем вам каталоге.]{#editors-disposable-file .correct explanation="Учебный файл ограничивает последствия случайных правок, пока вы осваиваете навигацию, сохранение и выход."}
::option[Общий рабочий файл без резервной копии.]{#editors-production-file explanation="Неосторожная практика на общих данных может помешать другим и не оставляет простого пути восстановления."}
:::
