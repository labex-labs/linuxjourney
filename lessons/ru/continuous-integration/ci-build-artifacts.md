**Артефакт сборки** — это файл или набор файлов, сохранённый после запуска для дальнейшего использования. Например, это может быть отчёт о тестах или архив сайта. Если указать рядом с артефактом запуск и ревизию, проверяющий сможет понять, из каких исходных файлов он получен.

## Упаковываем выходной каталог

Используйте учебный каталог, где в `dist` лежит собранная страница. Пример создаёт сжатый архив — один файл с содержимым всего каталога. Существующий архив с тем же именем в текущем каталоге будет заменён.

```bash
$ tar -czf site.tar.gz -C dist .
$ tar -tzf site.tar.gz
```

В первой команде `-c` создаёт архив, `-z` сжимает его, а `-f` задаёт имя выходного файла. Аргумент `-C dist .` указывает tar начать работу в `dist`. Вторая команда с параметром `-t` перечисляет содержимое архива. Прежде чем передавать архив, найдите в списке `./index.html`.

:::single-choice{#ci-build-artifacts-inspect-archive} Как убедиться, что страница вошла в архив?

::option[Вывести содержимое командой tar -tzf site.tar.gz.]{#ci-build-artifacts-inspect-archive-b .correct explanation="Список покажет, есть ли внутри index.html."}
::option[Создать архив ещё раз.]{#ci-build-artifacts-inspect-archive-a explanation="Повторная упаковка не показывает список файлов для проверки."}
::option[Посмотреть только имя файла.]{#ci-build-artifacts-inspect-archive-c explanation="По имени архива нельзя узнать, что внутри."}
:::

## Связываем артефакт с запуском

Рабочий процесс может загрузить готовый архив. На странице запуска видно, какая ревизия использовалась при сборке. Два артефакта с именем `site.tar.gz` могут различаться, если собраны из разных ревизий. При выборе файла для скачивания проверяйте и запуск, и ревизию.

:::single-choice{#ci-build-artifacts-choose-run} В запусках 41 и 42 есть site.tar.gz. Как найти пакет для ревизии, которую вы проверили?

::option[Взять первый доступный файл с именем site.tar.gz.]{#ci-build-artifacts-choose-run-b explanation="Имя не указывает, какие исходные файлы использованы при сборке."}
::option[Взять последний успешный запуск независимо от его ревизии.]{#ci-build-artifacts-choose-run-c explanation="Более поздний запуск может пройти успешно с другими файлами. Найдите нужную вам ревизию."}
::option[Взять запуск, в котором указана проверенная вами ревизия.]{#ci-build-artifacts-choose-run-a .correct explanation="Одно и то же имя файла может использоваться в нескольких запусках."}
:::

## Различаем архив и образ контейнера

Архив сайта содержит файлы, которые можно распаковать. Образ контейнера содержит файловую систему и настройки, с которыми Docker запускает контейнер. Рабочий процесс может опубликовать образ в реестре. Если планируете запустить контейнер из этого образа, сохраните его ссылку вместе с исходной ревизией.

:::single-choice{#ci-build-artifacts-deployable-type} На следующем этапе нужно запустить контейнер из образа в реестре. На какой результат нужно сослаться?

::option[На отчёт о тестах, скачанный со страницы запуска.]{#ci-build-artifacts-deployable-type-a explanation="Отчёт описывает результаты и не содержит файловой системы контейнера."}
::option[На ссылку на опубликованный образ контейнера.]{#ci-build-artifacts-deployable-type-c .correct explanation="По ней Docker может получить подготовленный образ."}
::option[На имя файла архива сайта.]{#ci-build-artifacts-deployable-type-b explanation="В архиве лежат файлы страниц, а его имя не указывает на образ в реестре."}
:::

## Итоги

Теперь вы можете распознать артефакт сборки и выяснить его происхождение.

1. Упаковывайте собранные файлы и проверяйте содержимое архива.
2. Сверяйте запуск и исходную ревизию.
3. Выбирайте файловый артефакт или образ контейнера с учётом того, что требуется на следующем этапе.
