Задание CI может запускать команды и получать учётные данные. **Разрешение** определяет, что с этими данными можно прочитать или изменить. Если задание только проверяет страницу, обычно ему достаточно читать исходные файлы.

## Даём проверке доступ на чтение

Этот фрагмент GitHub Actions ограничивает встроенный токен рабочего процесса чтением содержимого репозитория.

```yaml
permissions:
  contents: read
```

Действие checkout и локальный тест могут читать файлы репозитория. Заданию, которое публикует пакет, нужно разрешение на другое действие с другим ресурсом. Дайте право на публикацию конкретному заданию, которому оно нужно.

:::single-choice{#ci-workflow-permissions-choose-permission} Задание читает страницу и запускает grep. Какое право доступа к содержимому репозитория ему нужно?

::option[Запись, потому что результат теста выводится в терминал.]{#ci-workflow-permissions-choose-permission-a explanation="Для вывода в терминал не нужно разрешение менять содержимое репозитория."}
::option[Чтение.]{#ci-workflow-permissions-choose-permission-c .correct explanation="Заданию нужно получить файлы. Менять что-либо в репозитории ему не требуется."}
::option[Запись, потому что исходные файлы находятся в репозитории Git.]{#ci-workflow-permissions-choose-permission-b explanation="Для описанной проверки достаточно чтения исходных файлов."}
:::

## Работаем с конфиденциальными значениями

**Секрет** — это конфиденциальное значение, например закрытый токен. Если одобренному заданию нужен секрет, используйте хранилище секретов платформы. Обычные настройки страницы храните отдельно. Регулярные проверки локального примера должны работать без учётных данных для публикации.

:::single-choice{#ci-workflow-permissions-secret-needed} Какое значение следует поместить в хранилище секретов с ограниченным доступом?

::option[Закрытые учётные данные для загрузки пакета.]{#ci-workflow-permissions-secret-needed-a .correct explanation="Учётные данные могут предоставить доступ к другой системе."}
::option[Текст Welcome, используемый в тесте.]{#ci-workflow-permissions-secret-needed-b explanation="Это общедоступный текст примера."}
::option[Имя выходного каталога dist.]{#ci-workflow-permissions-secret-needed-c explanation="Имя каталога — обычная настройка."}
:::

## Оставляем в журналах полезные сведения

Журналы рабочих процессов могут быть доступны другим людям. Указывайте действие и его результат, не выводя значения секретов. В сообщении об ошибке можно написать, что обязательные учётные данные были недоступны или что доступ был запрещён. Укажите ответственному за процесс название задания и ревизию, чтобы он мог разобраться. Само значение оставьте за пределами сообщения.

:::single-choice{#ci-workflow-permissions-safe-diagnostic} Задание публикации не может пройти аутентификацию. Какое сообщение поможет разобраться и не раскроет учётные данные?

::option[Напечатать учётные данные целиком, чтобы их можно было скопировать.]{#ci-workflow-permissions-safe-diagnostic-a explanation="Любой, у кого есть доступ к журналу, увидит эти данные."}
::option[Вывести все переменные окружения, чтобы показать состояние задания.]{#ci-workflow-permissions-safe-diagnostic-c explanation="Полный вывод окружения может содержать конфиденциальные значения."}
::option[Указать шаг публикации, на котором случился сбой, и результат попытки доступа.]{#ci-workflow-permissions-safe-diagnostic-b .correct explanation="Так проверяющий сможет найти место сбоя и отдельно проверить настройки доступа."}
:::

## Проверяем новое задание

Предложенный рабочий процесс проверяет страницы в пул-реквестах и добавляет задание для публикации пакета. Заданиям нужны разные права. Ограничьте проверку необходимым доступом на чтение, а одобренные права на публикацию выдайте только заданию, которое действительно публикует пакет.

:::single-choice{#ci-workflow-permissions-final-application} Какое изменение предложения учитывает потребности обоих заданий?

::option[Дать обоим заданиям право записи в репозиторий.]{#ci-workflow-permissions-final-application-b explanation="Проверка только читает исходные файлы. Для публикации пакета может потребоваться другое разрешение."}
::option[Использовать общие данные для загрузки на всех шагах, чтобы повторные запуски вели себя одинаково.]{#ci-workflow-permissions-final-application-c explanation="Данные для загрузки нужны только заданию публикации."}
::option[Оставить проверкам доступ на чтение, а заданию публикации дать только необходимый доступ к пакету.]{#ci-workflow-permissions-final-application-a .correct explanation="Каждое задание получает достаточный доступ, а лишние полномочия ограничиваются."}
:::

## Итоги

Теперь вы можете определить, какие права нужны небольшому конвейеру CI.

1. Сопоставляйте разрешения на доступ к репозиторию с задачами задания.
2. Храните закрытые учётные данные в месте с ограниченным доступом.
3. Записывайте полезные сообщения об ошибках, не раскрывая учётные данные.
