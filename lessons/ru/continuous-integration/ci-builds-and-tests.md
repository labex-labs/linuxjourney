Причину сбоя проще понять, если у каждого этапа своя задача. На этапе **подготовки** становятся доступны входные файлы и инструменты. **Сборка** создаёт результат. **Тест** проверяет, выполняется ли заданное условие в исходных файлах или в результате сборки.

## Готовим входной файл

Создайте страницу-пример в пустом учебном каталоге. Перенаправление заменит существующий `index.html`, поэтому используйте новый каталог для упражнения.

```bash
$ printf '%s\n' '<h1>Welcome</h1>' > index.html
```

В задании CI файл страницы был бы получен из репозитория на шаге checkout. В некоторых проектах также устанавливают зависимости — библиотеки или инструменты, необходимые для сборки и тестирования.

## Собираем результат

Скопируйте страницу в каталог, где будет лежать готовый сайт.

```bash
$ mkdir -p dist
$ cp index.html dist/index.html
```

Параметр `-p` позволяет команде `mkdir` завершиться успешно, даже если каталог уже существует. После копирования в выходном каталоге появится отдельный файл. Его можно будет проверить на следующих этапах.

## Проверяем страницу

Запустите проверку сразу после сборки. Параметр `-F` ищет заданную строку как обычный текст, а `-q` отключает вывод совпавших строк. Оболочка хранит код завершения последней команды в `$?`. Ноль означает, что текст найден. Единица означает, что подходящей строки нет.

```bash
$ grep -Fq '<h1>Welcome</h1>' dist/index.html
$ echo "$?"
```

Ожидаемый результат — `0`. Проверка искала точный текст в полученном файле. Цвета, отображение в браузере и время ответа она не проверяла.
