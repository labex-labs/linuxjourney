Результат рабочего процесса показывает его общее состояние. Чтобы понять причину сбоя, откройте задание с ошибкой и прочитайте шаги по порядку. Более поздний шаг мог быть пропущен из-за ошибки на предыдущем.

## Находим первый сбой

Этот смоделированный запуск показывает состояние каждого шага задания проверки страницы.

```text
Prepare: passed
Build page: failed
Check heading: skipped
Package site: skipped
```

Начните с `Build page`. Пропущенные проверки не дают результатов по странице. После устранения ошибки проверьте следующие шаги в новом запуске.

:::single-choice{#ci-workflow-logs-first-failure} Вывод какого шага нужно прочитать сначала?

::option[Package site, потому что он указан последним.]{#ci-workflow-logs-first-failure-a explanation="Команда упаковки в этом запуске была пропущена."}
::option[Check heading, потому что рабочий процесс проверяет страницу.]{#ci-workflow-logs-first-failure-c explanation="По состоянию шага видно, что проверка заголовка не запускалась."}
::option[Build page, потому что этот шаг завершился ошибкой до запуска других шагов.]{#ci-workflow-logs-first-failure-b .correct explanation="Его журнал показывает, почему последующие шаги пропущены."}
:::

## Читаем сообщение об ошибке

Шаг со сбоем вывел следующие строки.

```text
Run cp index.html dist/index.html
cp: cannot create regular file 'dist/index.html': No such file or directory
Process completed with exit code 1.
```

В сообщении указан путь назначения. Если родительского каталога `dist` нет, команда копирования не может создать внутри него файл. Проверьте, создала ли одна из предыдущих команд этот каталог до копирования. Код завершения 1 сообщает о сбое. Из сообщения понятно, где искать причину.

:::single-choice{#ci-workflow-logs-actionable-log} Каталога dist нет. Какое изменение устраняет указанную проблему?

::option[Изменить заголовок, который проверяет grep.]{#ci-workflow-logs-actionable-log-b explanation="Проверка заголовка не запускалась. Пока нет оснований считать текст неверным."}
::option[Создать dist до копирования файла.]{#ci-workflow-logs-actionable-log-a .correct explanation="Чтобы создать файл назначения, нужен родительский каталог."}
::option[Скачать артефакт из пропущенного шага.]{#ci-workflow-logs-actionable-log-c explanation="Шаг упаковки в этом запуске не создал артефакт."}
:::

## Проверяем новый запуск

Исправив сборку, сравните ревизию и состояние шагов в новом запуске. Успешное копирование подтверждает, что выходной файл появился. Прежде чем считать весь процесс успешным, прочитайте результаты тестирования и упаковки. Сообщая о проблеме, укажите первую полезную ошибку вместе с именем шага.

:::single-choice{#ci-workflow-logs-rerun-evidence} В новом запуске Build page прошёл, а Check heading завершился ошибкой. Что изменилось?

::option[Сборка удалась, а теперь есть результат проверки заголовка, который можно исследовать.]{#ci-workflow-logs-rerun-evidence-c .correct explanation="Первый оставшийся сбой находится на шаге тестирования."}
::option[Новый запуск не важен, потому что предыдущая сборка завершилась ошибкой.]{#ci-workflow-logs-rerun-evidence-a explanation="Каждый запуск даёт сведения о своей ревизии."}
::option[Упаковка тоже должна была пройти, раз прошла сборка.]{#ci-workflow-logs-rerun-evidence-b explanation="Более поздний шаг всё ещё может завершиться ошибкой или быть пропущен."}
:::

## Итоги

Теперь вы можете читать сообщения об ошибке в контексте рабочего процесса.

1. Находите первый выполненный шаг, который завершился неудачно.
2. По сообщению в журнале определяйте, что нужно проверить.
3. После исправления проверяйте новую ревизию и следующие шаги.
