Рабочий процесс — это весь автоматизированный процесс. **Задание** объединяет работу, порученную **исполнителю** (runner) — машине или среде, которая её выполняет. **Шаг** — одна операция внутри задания.

## Читаем небольшой рабочий процесс

В этом примере одно задание выполняется на исполнителе Ubuntu, предоставляемом GitHub. Такой файл находится в каталоге `.github/workflows/` репозитория GitHub.

```yaml
name: Page check
on: push
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: Get the repository
        uses: actions/checkout@v6
      - name: Find the heading
        run: grep -q '<h1>Welcome</h1>' index.html
```

Идентификатор задания — `check`. Поле `runs-on` выбирает среду выполнения. Поле `uses` вызывает готовое действие, которое в этом примере предоставляет файлы репозитория. Поле `run` выполняет команду на исполнителе.

## Читаем шаги по порядку

По умолчанию шаги одного задания выполняются в порядке, указанном в файле. Проверка читает файл из репозитория, поэтому действие checkout для получения файлов стоит первым. Внутри одного задания более поздний шаг может использовать файлы, записанные на предыдущем шаге.

## Учитываем раздельное выполнение заданий

Отдельные задания могут выполняться одновременно. Каждое задание, выполняемое на инфраструктуре GitHub, получает собственного исполнителя. Файл, записанный в одном задании, будет доступен в другом, только если рабочий процесс его передаст. Если для запуска одного задания необходимо успешное завершение другого, укажите зависимость через `needs`. Для передачи файлов при необходимости используйте артефакт.

:::single-choice{#ci-jobs-steps-runners-separate-jobs} Задание сборки записывает site.tar.gz. Следующее задание запустится на другом исполнителе GitHub. Как передать ему файл?

::option[Предположить, что файл остался в том же рабочем каталоге.]{#ci-jobs-steps-runners-separate-jobs-a explanation="У отдельного исполнителя своя файловая система."}
::option[Передать файл как артефакт.]{#ci-jobs-steps-runners-separate-jobs-c .correct explanation="Рабочий процесс может загрузить артефакт в одном задании и скачать в другом."}
::option[Задать needs, чтобы второе задание дождалось сборки.]{#ci-jobs-steps-runners-separate-jobs-b explanation="Needs задаёт порядок выполнения. Файл сборки всё равно нужно передать между исполнителями."}
:::

## Итоги

Теперь вы можете читать основные части рабочего процесса CI.

1. Находите задание и его исполнителя.
2. Различайте готовое действие и шаг с командой оболочки.
3. Определяйте, когда заданиям нужны зависимость или передача файлов.
