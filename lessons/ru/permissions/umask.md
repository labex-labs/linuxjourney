Маска создания файлов процесса, или umask, не позволяет устанавливать выбранные биты прав при создании объектом файловой системы этим процессом. Это маска, а не полный режим по умолчанию: сначала приложение запрашивает режим, а затем ядро удаляет биты, запрещённые umask.

Упрощённо:

```text
resulting mode = requested mode AND NOT umask
```

Списки управления доступом и поведение приложения могут вносить дополнительные особенности, поэтому проверяйте результат, когда важны точные права.

## Просмотр и установка umask

Запустите `umask` без операнда, чтобы вывести маску текущей оболочки, обычно в восьмеричной форме:

```bash
$ umask
0022
```

Задайте её для текущей оболочки и процессов, которые она запустит впоследствии:

```bash
$ umask 027
```

Каждая восьмеричная позиция соответствует владельцу, группе и остальным. Бит маски удаляет соответствующее запрошенное право: `2` маскирует запись, `4` — чтение, а `1` — выполнение.

:::single-choice{#umask-command-purpose}
Что изменяет `umask 027` в текущей оболочке?

::option[Права каждого уже существующего файла.]{#umask-existing-files explanation="Umask влияет на запросы создания и не запускает `chmod` задним числом для существующих объектов."}
::option[Маску, наследуемую командами, которые впоследствии запускает эта оболочка.]{#umask-current-shell-mask .correct explanation="Оболочка задаёт umask своего процесса, и дочерние процессы обычно наследуют это значение."}
::option[Имена владельца и группы, сохраняемые у новых файлов.]{#umask-owner-group explanation="Маска фильтрует биты прав и не выбирает идентификаторы владения."}
:::

## Расчёт режимов новых файлов и каталогов

Многие обычные программы запрашивают для новых обычных файлов `0666`, поскольку создание исполняемых файлов по умолчанию было бы небезопасно. Для новых каталогов они обычно запрашивают `0777`, где право выполнения необходимо для прохода.

При umask `0022`:

```text
regular file: 0666 masked by 0022 -> 0644 (rw-r--r--)
directory:    0777 masked by 0022 -> 0755 (rwxr-xr-x)
```

Umask только удаляет запрошенные биты. Она не может добавить право выполнения, если приложение его не запросило. Приложение также может запросить более ограничительный исходный режим и получить более ограничительный результат.

:::single-choice{#umask-file-mode-022}
Какой режим получится, если программа запрашивает `0666` для обычного файла, а umask равна `0022`?

::option[`0666`]{#umask-file-0666 explanation="Запрошенные в 0666 биты записи группы и остальных удаляются маской 0022."}
::option[`0755`]{#umask-file-0755 explanation="Биты выполнения не запрашивались для обычного файла, поэтому umask не может их добавить."}
::option[`0644`]{#umask-file-0644 .correct explanation="Удаление записи группы и остальных из 0666 оставляет владельцу чтение и запись, а группе и остальным — только чтение."}
:::

:::single-choice{#umask-directory-mode-027}
Какой режим получится, если программа запрашивает `0777` для каталога, а umask равна `0027`?

::option[`0777`]{#umask-directory-0777 explanation="Ненулевая маска отфильтровывает запрошенные право записи группы и все права остальных."}
::option[`0640`]{#umask-directory-0640 explanation="Такой результат также удаляет биты выполнения, которые маска 0027 не удаляет у владельца или группы."}
::option[`0750`]{#umask-directory-0750 .correct explanation="Маска удаляет запись группы и все права остальных, оставляя `rwxr-x---`."}
:::

## Область действия и постоянство

Изменение umask в одной оболочке не влияет на её родительский процесс или другие сеансы. Значение применяется к будущим объектам, создаваемым этой оболочкой и её потомками; существующие файлы сохраняют свои режимы.

Чтобы сделать предпочтительное значение постоянным, задайте его в подходящей конфигурации входа, оболочки, PAM, диспетчера служб или приложения вашей среды. Правильное место различается, а службы могут устанавливать собственную umask. Не предполагайте, что изменение одного файла интерактивной оболочки управляет всеми процессами системы.

:::single-choice{#umask-existing-file-effect}
Что происходит с существующим файлом после установки новой umask?

::option[Его текущий режим остаётся прежним.]{#umask-existing-unchanged .correct explanation="Новая umask фильтрует последующие запросы создания и не изменяет режимы, уже сохранённые у объектов файловой системы."}
::option[Его режим заново вычисляется из `0666`.]{#umask-existing-recalculated explanation="Существующие объекты не создаются повторно и не пропускаются автоматически через новую маску."}
::option[Его владелец немедленно теряет замаскированные права.]{#umask-existing-owner-loss explanation="Изменение umask процесса не является операцией над метаданными существующего файла."}
:::

Для практики создавайте файлы и каталоги с разными масками в изолированной среде, затем сравнивайте их режимы через `ls -ld`. Лаборатория [Пользователи, группы и права файлов Linux](https://labex.io/ru/labs/linux-linux-user-group-and-file-permissions-18002) предоставляет подходящую рабочую среду.

1. Просматривайте или задавайте маску текущей оболочки командой `umask`.
2. Удаляйте замаскированные биты из режима, запрошенного приложением.
3. Отличайте распространённый запрос `0666` для файлов от `0777` для каталогов.
4. Учитывайте зависимость области действия и постоянства umask от процесса и среды.
