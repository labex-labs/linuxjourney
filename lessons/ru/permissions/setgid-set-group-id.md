У бита set-group-ID, обычно называемого setgid или SGID, два важных применения. Для исполняемого обычного файла он может изменить эффективный идентификатор группы нового процесса. Для каталога он заставляет новые записи наследовать группу каталога, что особенно полезно в деревьях для совместной работы.

## Setgid у исполняемых файлов

Подробный список может показывать setgid в позиции выполнения группы:

```bash
$ ls -l /path/to/program
-rwxr-sr-x 1 root operators 24576 Jan 10 09:30 /path/to/program
```

Строчная `s` означает, что установлены и setgid, и выполнение группы. Прописная `S` означает, что setgid установлен, а выполнение группы отсутствует.

Когда ядро учитывает этот бит при выполнении, процесс получает эффективный идентификатор группы на основе группы-владельца исполняемого файла. Это поведение может подавляться такими средствами, как подключение с `nosuid`, и его нельзя считать универсальной гарантией для любого типа файлов или среды.

:::single-choice{#setgid-executable-effect} Какие учётные данные берутся у группы-владельца исполняемого файла, когда setgid учитывается?

::option[Эффективный идентификатор группы процесса.]{#setgid-effective-group .correct explanation="Выполнение set-group-ID устанавливает группу-владельца исполняемого файла в качестве эффективной группы процесса."}
::option[Действительный идентификатор пользователя процесса.]{#setgid-real-user explanation="Бит относится к групповым учётным данным, а не к действительному идентификатору вызывающего пользователя."}
::option[Владелец каждого файла, открываемого процессом.]{#setgid-opened-owner explanation="Учётные данные выполнения не переписывают метаданные владения открытых файлов."}
:::

## Setgid у каталогов

Setgid у каталога имеет другое назначение. Новые файлы и подкаталоги обычно наследуют группу каталога вместо основной группы создателя. В Linux новые подкаталоги также наследуют бит setgid, помогая сохранять единую группу в общем дереве проекта.

Сам по себе setgid не предоставляет группе право записи. Доступ по-прежнему определяется режимом каталога, umask процесса, запрошенным режимом создания, ACL по умолчанию и другими механизмами.

```bash
$ sudo chgrp developers /srv/project
$ sudo chmod g+s /srv/project
$ ls -ld /srv/project
drwxr-sr-x 2 root developers 4096 Jan 10 09:30 /srv/project
```

:::single-choice{#setgid-directory-inheritance} Что обычно наследует новый файл благодаря setgid у `/srv/project`?

::option[Пользователя-владельца каталога.]{#setgid-inherit-user explanation="Setgid каталога влияет на наследование группы, а не пользователя-владельца новой записи."}
::option[Полный режим прав каталога.]{#setgid-inherit-mode explanation="Права создания по-прежнему вычисляются из запрошенного режима, umask и возможных ACL."}
::option[Группу-владельца каталога.]{#setgid-inherit-group .correct explanation="Новая запись обычно получает группу setgid-каталога, поддерживая единое групповое владение."}
:::

## Установка и удаление setgid

Установите бит символически:

```bash
$ sudo chmod g+s myfile
```

Установите его вместе с обычными битами режима через начальную восьмеричную `2`:

```bash
$ sudo chmod 2755 myfile
```

Удалите только специальный бит командой `chmod g-s myfile`.

:::single-choice{#setgid-octal-value} Какое значение setgid добавляет к начальной восьмеричной цифре специальных битов?

::option[`4`]{#setgid-value-four explanation="Значение 4 в цифре специальных битов обозначает setuid."}
::option[`1`]{#setgid-value-one explanation="Значение 1 обозначает sticky-бит."}
::option[`2`]{#setgid-value-two .correct explanation="Setgid добавляет `2`, как в режиме `2755`."}
:::

## Безопасное использование общих каталогов

Для совместного каталога сочетайте требуемую группу-владельца, setgid и узко выбранные биты доступа. Проверьте создание от имени типичных пользователей и изучите результат через `ls -ld`. Не делайте дерево доступным для записи всем лишь ради решения проблемы общего доступа группы; выделенная группа, подходящая umask или ACL по умолчанию и setgid-каталог обычно обеспечивают более понятное управление.

:::single-choice{#setgid-directory-write-access} Предоставляет ли одна установка setgid членам группы право создавать файлы в каталоге?

::option[Да; setgid всегда добавляет группе чтение, запись и выполнение.]{#setgid-adds-rwx explanation="Специальный бит не изменяет автоматически три обычных бита прав группы."}
::option[Да; setgid отключает все проверки для членов группы.]{#setgid-disables-checks explanation="Обычные дискреционные и дополнительные проверки безопасности продолжают действовать."}
::option[Нет; применимые права записи и поиска также должны разрешать создание.]{#setgid-no-automatic-write .correct explanation="Setgid управляет наследованием группы, а обычные права и другие механизмы доступа — записью в каталог."}
:::

## Итоги

Теперь вы можете различать значения setgid для исполняемых файлов и каталогов.

1. Распознавайте setgid в позиции выполнения группы.
2. Связывайте setgid исполняемого файла с эффективным идентификатором группы.
3. Используйте setgid каталога для сохранения группового владения в общих деревьях.
4. Устанавливайте или удаляйте бит, не смешивая его с обычным правом записи.
