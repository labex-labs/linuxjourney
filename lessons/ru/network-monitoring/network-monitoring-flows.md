**Поток** объединяет трафик с общими признаками, например сетевыми адресами, портами и протоколом. Системы мониторинга могут считать байты или пакеты потока, без сохранения полного содержимого пакетов.

## Как читать адреса обеих сторон

В этой учебной сводке сборщик фиксирует направление от источника к назначению. У транспортных протоколов, таких как TCP, есть номера портов. По порту можно определить слушающий сокет принимающей стороны.

```text
start=09:21:00Z protocol=TCP src=192.0.2.10:51600 dst=192.0.2.20:443 bytes=1800
start=09:21:00Z protocol=TCP src=192.0.2.20:443 dst=192.0.2.10:51600 bytes=8200
```

Первая строка описывает поток к порту 443. Вторая показывает обратное направление. Некоторые сборщики объединяют оба направления, так что сначала уточните формат записи.

:::single-choice{#network-monitoring-flows-endpoint-direction} Какой адрес и порт получают трафик из первой строки?

::option[192.0.2.10:51600.]{#network-monitoring-flows-endpoint-direction-a explanation="Это отправитель в первом направлении."}
::option[Оба указанных адреса с портами являются назначениями.]{#network-monitoring-flows-endpoint-direction-c explanation="В каждой строке примера указано одно направление."}
::option[192.0.2.20:443.]{#network-monitoring-flows-endpoint-direction-b .correct explanation="Поле назначения показывает, куда отправлен трафик."}
:::

## Как сравнивать счётчики

В примере в направлении от порта 443 передано больше байтов. Для веб-страницы более объёмный ответ может быть обычным. По одному счётчику нельзя определить содержимое страницы, учётную запись или причину такого объёма.

:::single-choice{#network-monitoring-flows-byte-count} Что описывают 8 200 байт во второй строке?

::option[Точный текст ответного сообщения.]{#network-monitoring-flows-byte-count-b explanation="Сводка потока указывает объём без текста сообщения."}
::option[Зарегистрированный объём в этом направлении.]{#network-monitoring-flows-byte-count-a .correct explanation="Счётчик показывает объём трафика, а источник и назначение — его направление."}
::option[Гарантию, что страница успешно загрузилась.]{#network-monitoring-flows-byte-count-c explanation="Объём трафика не показывает результат HTTP."}
:::

## Как дополнить данные о потоке

Учитывайте известные сведения о сервисе и время, чтобы выбрать подходящие потоки. Если нужно узнать, что вернул веб-сервер, проверьте его журнал доступа за то же время и для того же соединения, если такие записи доступны.

:::single-choice{#network-monitoring-flows-next-source} Вам нужен статус HTTP для веб-запроса. Какой источник поможет?

::option[Соответствующая запись журнала веб-доступа.]{#network-monitoring-flows-next-source-c .correct explanation="Журнал доступа сервера может содержать результат HTTP."}
::option[Число байтов потока, округлённое до сотен.]{#network-monitoring-flows-next-source-a explanation="Округление меняет точность счётчика и не добавляет статуса ответа."}
::option[Вторая сводка потока между теми же адресами и портами.]{#network-monitoring-flows-next-source-b explanation="Сводка может дополнить наблюдения о трафике. Статус ответа HTTP обычно в неё не входит."}
:::

## Итоги

Теперь вы можете читать основные поля сводки сетевого потока.

1. Находить адреса и порты обеих сторон.
2. Читать счётчик байтов для указанного направления.
3. Выбирать другой источник, когда важен результат работы приложения.
