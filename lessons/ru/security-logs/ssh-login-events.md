**SSH** расшифровывается как Secure Shell и позволяет входить на другую машину по сети. Принимающая сторона может записывать каждую попытку. Из записи видно, какая учётная запись была указана и принял ли сервер предоставленное подтверждение подлинности.

## Как читать результат

Перед вами две учебные записи SSH. Поле `login` содержит результат. Отклонённая попытка не прошла проверку входа. Принятая попытка её прошла.

```text
t=09:13:48Z source=ssh host=web-01 account=alex login=rejected
t=09:14:02Z source=ssh host=web-01 account=alex login=accepted
```

Первая запись описывает отказ для `alex`. Вторая показывает принятую попытку для той же учётной записи. Каждый результат относится к своей попытке.

:::single-choice{#ssh-login-events-outcome-order} Какой вывод следует из этих двух записей?

::option[Более поздняя попытка прошла проверку входа.]{#ssh-login-events-outcome-later .correct explanation="Во второй записи в 09:14:02 указано login=accepted."}
::option[Обе попытки прошли проверку входа.]{#ssh-login-events-outcome-both explanation="В первой строке зафиксирована отклонённая попытка."}
::option[Более поздняя попытка не прошла проверку входа.]{#ssh-login-events-outcome-failed explanation="Отклонена была первая попытка. Вторая была принята."}
:::

## Как читать адрес и метод аутентификации

Удалённый адрес указывает, откуда пришло соединение с точки зрения принимающей машины. В примере он записан в поле `peer`. Сетевым адресом могут пользоваться разные люди, поэтому по одному полю нельзя установить, кто именно им воспользовался.

```text
t=09:14:02Z source=ssh host=web-01 account=alex login=accepted
peer=192.0.2.10 method=publickey connection=17
```

Вторая строка продолжает ту же запись. Поле `method` показывает, какое подтверждение проверял SSH. `password` означает, что SSH проверял пароль. При `publickey` подключившаяся машина доказала, что может использовать ключ, который сервер принимает для этой учётной записи.

:::single-choice{#ssh-login-events-method-evidence} Что можно утверждать о принятой попытке?

::option[Сервер принял вход с паролем.]{#ssh-login-events-method-password explanation="Пароль указывался бы как отдельный метод. В записи указан метод с открытым ключом."}
::option[Сервер установил личность человека, использовавшего этот адрес.]{#ssh-login-events-method-person explanation="Адрес описывает соединение с точки зрения хоста. Он не показывает, кто был за клавиатурой."}
::option[Сервер принял вход с помощью ключа.]{#ssh-login-events-method-key .correct explanation="В записи указаны и login=accepted, и method=publickey."}
:::

## Группировка попыток по соединению

**Соединение** — это сетевой канал, по которому SSH обменивается сообщениями. В примерах хост назначает каждому соединению идентификатор. Через одно соединение можно сделать несколько попыток входа, а с того же адреса можно установить другое соединение.

```text
t=09:13:48Z host=web-01 account=alex peer=192.0.2.10 connection=17 login=rejected
t=09:13:55Z host=web-01 account=alex peer=192.0.2.10 connection=18 login=rejected
t=09:14:02Z host=web-01 account=alex peer=192.0.2.10 connection=17 login=accepted
```

На `web-01` первая и последняя записи относятся к соединению 17. Смотрите на идентификатор вместе с именем хоста.

![Терминал LabEx показывает учебные попытки SSH с одного адреса и идентификаторами соединений 17 и 18](https://cdn.jsdelivr.net/gh/labex-labs/linuxjourney@master/images/lessons/security-logs/ssh-login-events/ssh-connections.png)

Терминал выводит все три попытки рядом, чтобы можно было сравнить номера соединений.

:::single-choice{#ssh-login-events-group-connection} Какие записи относятся к соединению 18 на web-01?

::option[Попытки в 09:13:48 и 09:14:02.]{#ssh-login-events-group-seventeen explanation="В обеих строках указан номер соединения 17."}
::option[Только попытка в 09:13:55.]{#ssh-login-events-group-eighteen .correct explanation="Только эта строка показывает соединение 18 на web-01."}
::option[Все три попытки с адреса 192.0.2.10.]{#ssh-login-events-group-address explanation="Для одного адреса указаны два номера соединения."}
:::

## Что происходит после успешного входа

Успешный вход показывает, что SSH принял подтверждение для этой учётной записи. Чтобы узнать, что было дальше, ищите запись об открытии **сеанса**. Сеанс охватывает активность после входа. Сама запись об успешном входе сообщает лишь результат проверки.

:::single-choice{#ssh-login-events-after-accepted} Какая запись поможет выяснить, привёл ли успешный вход к открытию сеанса?

::option[Ещё одна запись о том, что тот же вход был принят.]{#ssh-login-events-after-accepted-again explanation="Она лишь повторит результат проверки входа."}
::option[Более ранний отказ для той же учётной записи на другом хосте.]{#ssh-login-events-after-other-host explanation="Эта запись описывает отдельную попытку на другой машине."}
::option[Запись об открытии сеанса после этого входа.]{#ssh-login-events-after-session .correct explanation="Она описывает следующий этап и позволяет связать его с успешным входом."}
:::

## Итоги

Теперь вы можете прочитать результат попытки входа по SSH и определить, какие записи связаны одним соединением.

1. Отличить принятую попытку от отклонённой.
2. Описать попытку по удалённому адресу и методу аутентификации.
3. Группировать записи по хосту и соединению, когда доступен идентификатор.
4. Найти запись о сеансе, чтобы выяснить, что произошло после успешного входа.
