`sysfs` — виртуальная файловая система, обычно смонтированная в `/sys`. Она представляет объекты ядра и связи между ними каталогами, символическими ссылками и небольшими файлами атрибутов. Средства обнаружения и менеджеры устройств используют её для понимания текущей модели ядра.

## Навигация по модели устройств

Важные представления верхнего уровня:

- `/sys/devices/`: физическая и логическая иерархия;
- `/sys/class/`: устройства по функциональным классам, например block или network;
- `/sys/bus/`: шины, их устройства и драйверы;
- `/sys/block/`: удобное представление блочных устройств;
- `/sys/dev/`: ссылки по major- и minor-номерам символьных и блочных устройств.

Многие записи вне `/sys/devices` являются ссылками на каноническую иерархию. Получите фактический родительский путь через `readlink -f`:

```bash
$ readlink -f /sys/class/block/sda
```

На системе с другим интерфейсом хранения такого имени может не быть.

## Чтение атрибутов

Файлы атрибутов предоставляют отдельные значения и элементы управления. Для блочного устройства встречаются:

```bash
$ cat /sys/class/block/sda/dev
8:0
$ cat /sys/class/block/sda/ro
0
$ cat /sys/class/block/sda/size
1953525168
```

`dev` сообщает major и minor, `ro` — флаг только для чтения. Для блочных устройств Linux `size` по соглашению выражен в 512-байтовых секторах независимо от физического сектора. Единицы и смысл конкретного атрибута сверяйте с ABI ядра.

:::single-choice{#sysfs-dev-attribute} Что обычно содержит атрибут `dev` блочного устройства?

::option[Все файлы, хранящиеся на устройстве.]{#sysfs-file-list explanation="Дерево файловой системы не встроено в этот небольшой атрибут."}
::option[Имя пакета, установившего оборудование.]{#sysfs-package-name explanation="Оборудование не устанавливается как пакет, названный атрибутом `dev`."}
::option[Его major- и minor-номера.]{#sysfs-major-minor .correct explanation="Атрибут связывает объект sysfs с соответствующей личностью блочного устройства."}
:::

## Связь `/sys` и `/dev`

`/dev` содержит узлы, которые приложения открывают для ввода-вывода. `/sys` показывает связи объектов, свойства, состояние и некоторые элементы управления. Блочный `/dev/sda` можно сопоставить с `/sys/dev/block/8:0`, который разрешается в объект sysfs.

Интерфейсы дополняют друг друга. Ни один не является полностью автономной инвентаризацией, а устройство может исчезнуть во время исследования.

:::single-choice{#sysfs-versus-dev} Какое утверждение правильно различает `/sys` и `/dev`?

::option[`/sys` хранит документы, а `/dev` — архивы пакетов.]{#sysfs-dev-user-files explanation="Ни один каталог не выполняет эти обычные роли хранения."}
::option[`/sys` показывает атрибуты объектов ядра, а `/dev` предоставляет узлы для ввода-вывода.]{#sysfs-dev-distinction .correct explanation="Sysfs моделирует объекты и управление, а узлы направляют операции символьным или блочным драйверам."}
::option[Оба — статические списки, созданные при установке.]{#sysfs-dev-static explanation="Их видимое состояние меняется с появлением и исчезновением объектов ядра."}
:::

## Безопасная запись атрибутов

Некоторые атрибуты доступны для записи и меняют питание, привязку драйвера, очереди, авторизацию, светодиоды и другие живые элементы. Успешная текстовая запись может немедленно повлиять на оборудование или службу и не равна правке постоянной конфигурации.

Читайте документированный ABI и текущее значение, определяйте способ постоянной настройки и тестируйте только на разрешённой системе. Не меняйте рекурсивно разрешения и не записывайте угаданные значения по `/sys`.

:::single-choice{#sysfs-write-risk} Почему запись в атрибут sysfs может быть операционно значимой?

::option[Каждая запись создаёт обычную резервную копию на диске.]{#sysfs-backup-copy explanation="Sysfs виртуальна и не создаёт автоматических копий управляющих изменений."}
::option[Sysfs игнорирует любые записи даже в доступный атрибут.]{#sysfs-ignore-writes explanation="Записываемые атрибуты существуют именно для поддерживаемых управляющих значений."}
::option[Запись может вызвать живое управление ядра или драйвера.]{#sysfs-live-control .correct explanation="Записываемые атрибуты активны и способны немедленно изменить поведение устройства."}
:::
