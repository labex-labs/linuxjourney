Поток — это планируемая внутри процесса последовательность выполнения. У каждого работающего процесса есть хотя бы один поток, а у многопоточного процесса — несколько последовательностей, способных продвигаться параллельно.

## Процессы и потоки

Потоки одного процесса совместно используют такие ресурсы, как виртуальное адресное пространство и открытые файловые дескрипторы. При этом у каждого потока есть собственное состояние выполнения, включая регистры и стек. Совместное использование делает обмен эффективным, но также означает, что несинхронизированное изменение одного потока может повлиять на остальные.

У отдельных процессов обычно разные адресные пространства, и они обмениваются через явные межпроцессные механизмы. Ни один подход не является автоматически быстрее или безопаснее; компромисс определяется нагрузкой и реализацией.

## Идентификаторы потоков

Linux представляет каждый поток как планируемую задачу с собственным идентификатором потока. Идентификатор лидера группы потоков обычно показывается как идентификатор процесса, а все участники имеют общий идентификатор группы потоков. Инструменты используют метки `PID`, `TID`, `LWP` и `SPID`; проверяйте определения полей конкретного инструмента, а не считайте все метки равнозначными.

## Перечисление потоков через ps

Используйте явные поля вывода, чтобы избежать неоднозначных стандартных представлений:

```bash
$ ps -eLo pid,tid,psr,stat,comm
```

В `ps` из procps параметр `-L` показывает потоки, а `-e` выбирает все процессы. `pid` обозначает группу потоков, `tid` — отдельный поток, `psr` показывает CPU, на котором поток выполнялся последним, а `stat` сообщает состояние. Чтобы проверить один процесс:

```bash
$ ps -L -p 1234 -o pid,tid,stat,pcpu,comm
```

Списки потоков являются снимками. Сразу после вывода поток может завершиться или изменить состояние.

:::single-choice{#threads-ps-one-process} Какая команда перечисляет потоки PID 1234 с явными полями?

::option[`ps -p 1234 -o pid,ppid,stat,pcpu,comm`]{#threads-process-only explanation="Этот вывод не запрашивает отдельные строки потоков."}
::option[`ps -L -p 1234 -o pid,tid,stat,pcpu,comm`]{#threads-ps-l .correct explanation="Параметр -L запрашивает строки потоков выбранного процесса."}
::option[`ps -e -o pid,user,stat,pcpu,comm`]{#threads-all-processes explanation="Команда выбирает процессы всей системы без идентификаторов потоков."}
:::

## Интерпретация активности потоков

Высокое использование CPU одним потоком может скрываться за средним значением всего процесса. Сопоставляйте образцы CPU потоков с журналами приложения, трассировками стеков и профилировщиками. Не подключайте отладчики и не отправляйте сигналы производственным задачам, не разобравшись с остановками, правами и влиянием на службу.

:::single-choice{#threads-snapshot-limit} Почему список потоков `ps` нельзя считать постоянным состоянием?

::option[`ps` создаёт заменяющий поток для каждой строки.]{#threads-ps-creates explanation="Команда наблюдает задачи и не клонирует каждую перечисленную."}
::option[Идентификаторы потоков одинаковы на каждом хосте Linux.]{#threads-identical-ids explanation="Идентификаторы назначаются внутри работающей системы и не являются универсальными."}
::option[После снимка потоки могут изменить состояние или завершиться.]{#threads-change-after-snapshot .correct explanation="Проверка процессов наблюдает один момент непрерывно меняющейся системы."}
:::
