Файловая система может оставаться занятой, потому что процесс открыл файл, отобразил файл в память или использует каталог как текущий рабочий. `lsof` и `fuser` помогают определить такие связи. Сначала исследуйте ситуацию; остановка процессов — отдельное решение с эксплуатационными последствиями.

## Перечисление открытых файлов через lsof

`lsof` означает «list open files» — перечислить открытые файлы. Запросите путь, чтобы увидеть соответствующие записи:

```bash
$ sudo lsof -- /mnt/usb
```

Для целого дерева каталогов в одной файловой системе реализации обычно поддерживают `+D`, но рекурсивное сканирование может быть затратным:

```bash
$ sudo lsof +D /mnt/usb
```

К полезным столбцам относятся `COMMAND`, `PID`, `USER`, файловый дескриптор (`FD`), тип, устройство и `NAME`. Метка `cwd` в столбце `FD` означает, что процесс использует каталог как текущий рабочий. Непривилегированный вывод может быть неполным для процессов других пользователей.

:::single-choice{#lsof-cwd-record} Что означает `cwd` в столбце `FD`?

::option[Процесс использует этот каталог как текущий рабочий.]{#lsof-current-directory .correct explanation="Текущий каталог процесса может удерживать подключённую файловую систему занятой."}
::option[Файл был закрыт во время записи.]{#lsof-closed-write explanation="Метка описывает связь с каталогом, а не событие закрытия."}
::option[Процесс владеет устройством файловой системы.]{#lsof-device-owner explanation="Владение файловой системой не представляется меткой дескриптора cwd."}
:::

## Определение пользователей через fuser

`fuser` сообщает идентификаторы процессов, использующих указанный файл или файловую систему. Подробный вывод добавляет пользователей, виды доступа и имена команд:

```bash
$ sudo fuser -v /mnt/usb
```

Чтобы рассматривать аргумент как подключённую файловую систему и найти процессы, обращающиеся к файлам внутри неё, используйте параметр подключения, поддерживаемый `fuser` из procps:

```bash
$ sudo fuser -vm /mnt/usb
```

Убедитесь, что путь является требуемой точкой подключения, например через `findmnt --target /mnt/usb`. Bind-подключения, пространства имён, права и состояния гонки могут влиять на сведения одного запроса.

:::single-choice{#fuser-verbose-purpose} Зачем использовать `fuser -v` вместо простого `fuser` при исследовании?

::option[Команда автоматически отключает выбранную файловую систему.]{#fuser-verbose-unmount explanation="Подробный режим выводит сведения и не запрашивает отключение."}
::option[Команда добавляет контекст: пользователя, вид доступа и команду.]{#fuser-verbose-details .correct explanation="Дополнительные столбцы помогают оценить, какие процессы можно безопасно скоординировать или остановить."}
::option[Команда навсегда запрещает процессам повторно открывать файлы.]{#fuser-verbose-prevent explanation="Вывод сведений не создаёт правило управления доступом."}
:::

## Работа с занятой файловой системой

Используйте осознанную последовательность вместо немедленного завершения каждого совпавшего PID:

1. Подтвердите хост, путь, источник подключения и запланированное обслуживание.
2. По возможности найдите процессы обоими инструментами.
3. Определите, можно ли остановить каждый процесс, вывести его из каталога или дать ему завершиться.
4. При наличии используйте диспетчер служб или интерфейс приложения для остановки.
5. Повторите запрос, затем отключите файловую систему и проверьте результат.

`fuser -k` отправляет сигнал совпавшим процессам. В распространённых реализациях procps по умолчанию это `SIGKILL`, поэтому нормальное завершение не выполняется. Если явно одобренное завершение необходимо, выберите подходящий сигнал, проверьте PID и владельца и учтите, что набор процессов может измениться между проверкой и действием.

:::single-choice{#fuser-k-risk} Почему `fuser -k /mnt/usb` — плохой первый шаг диагностики?

::option[Команда лишь выводит свободное место файловой системы.]{#fuser-k-space explanation="Параметр воздействует на процессы, а не сообщает ёмкость."}
::option[Команда может завершить несколько совпавших процессов без нормальной очистки.]{#fuser-k-kills .correct explanation="Широкая отправка сигнала может прервать запись или службы, поэтому сначала нужны исследование и координация."}
::option[Команда меняет рабочий каталог каждого совпавшего процесса.]{#fuser-k-chdir explanation="Она отправляет сигнал и не перемещает каталоги процессов."}
:::

## Выбор инструмента

Используйте `lsof`, когда нужен подробный список открытых файлов, дескрипторов или сокетов. Используйте `fuser` для ориентированного на путь представления совпавших PID и видов доступа. Ни один результат сам по себе не говорит, безопасно ли завершать процесс.

Для сетевых сокетов укажите явное пространство протокола в `fuser` или примените специализированный инструмент вроде `ss`:

```bash
$ sudo fuser -v 22/tcp
$ sudo ss -lntp
```

:::single-choice{#lsof-fuser-tool-choice} Какой инструмент подходит для подробного списка открытых файловых дескрипторов и процессов-владельцев?

::option[`lsof`]{#lsof-detailed-records .correct explanation="Его вывод организован вокруг записей открытых файлов и метаданных их процессов."}
::option[`uptime`]{#lsof-uptime explanation="Uptime сообщает время работы и среднюю нагрузку, а не открытые дескрипторы."}
::option[`free`]{#lsof-free explanation="Free суммирует память, а не использование файлов."}
:::

## Итоги

Теперь вы можете исследовать использование файлов и файловых систем, не считая завершение процесса действием по умолчанию.

1. Используйте `lsof` для подробных записей открытых файлов.
2. Используйте `fuser` для сведений о PID и доступе, ориентированных на путь.
3. Подтверждайте подключение и учитывайте права и состояния гонки.
4. Координируйте нормальную остановку до рассмотрения сигнала.
5. Повторяйте запрос и проверяйте результат отключения или работы службы.
