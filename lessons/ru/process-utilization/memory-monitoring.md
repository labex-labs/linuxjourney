Linux намеренно использует простаивающую память для кэшей, поэтому одно малое значение `free` не доказывает нехватку памяти. `vmstat` помогает связать память с выполняемыми задачами, подкачкой, вводом-выводом и активностью CPU.

## Сбор образцов через vmstat

Собирайте один образец в секунду:

```bash
$ vmstat 1
```

Первая строка данных обычно сообщает средние значения с момента загрузки, а последующие строки охватывают каждый интервал. После сбора представительного периода остановите команду сочетанием `Ctrl-C`. Единицы и доступные поля различаются, поэтому проверьте `vmstat --unit` и локальное руководство.

:::single-choice{#vmstat-interval-rows}
Какие строки лучше всего подходят для наблюдения посекундных изменений через `vmstat 1`?

::option[Последующие строки после начального отчёта.]{#vmstat-later-rows .correct explanation="Последующие строки описывают каждый запрошенный интервал, а не накопительный период."}
::option[Только заголовки над первой строкой данных.]{#vmstat-headings explanation="Заголовки определяют поля, но не содержат образцов активности."}
::option[Только строка, скопированная с другого хоста.]{#vmstat-other-host explanation="Другая система не представляет текущую рабочую нагрузку."}
:::

## Процессы и память

Распространённые поля процессов — `r`, выполняемые задачи, и `b`, задачи, заблокированные в непрерываемом сне. Поля памяти включают используемый swap (`swpd`), простаивающую память (`free`), буферы (`buff`) и кэш (`cache`). Это общесистемные значения, а не потребление отдельных процессов.

Для более понятного представления доступной сейчас памяти сравните с:

```bash
$ free -h
```

Оценка `available` обычно полезнее одного `free`, поскольку освобождаемый кэш способен удовлетворить новые выделения.

:::single-choice{#vmstat-free-memory}
Почему низкое значение `free` может быть нормальным в Linux?

::option[Значение всегда исключает всю физическую RAM.]{#vmstat-excludes-ram explanation="Это поле памяти, хотя его точную единицу следует проверить."}
::option[Ядро может использовать простаивающую память для освобождаемых кэшей.]{#vmstat-reclaimable-cache .correct explanation="Кэшированную память часто можно освободить, когда она нужна приложениям."}
::option[Малый объём свободной памяти доказывает, что CPU выключен.]{#vmstat-cpu-off explanation="Выделение памяти и состояние питания CPU — несвязанные выводы."}
:::

## Подкачка и ввод-вывод

`si` и `so` показывают интенсивность чтения из swap и записи в него. Устойчивая подкачка вместе с задержкой и активностью освобождения памяти может указывать на давление, но ненулевое использование swap (`swpd`) само по себе не доказывает текущую проблему. `bi` и `bo` сообщают интенсивность блочного ввода и вывода и не ограничиваются трафиком swap.

:::single-choice{#vmstat-swap-pressure}
Какие свидетельства лучше подтверждают текущую нехватку памяти?

::option[Ненулевое значение `swpd` без других наблюдений.]{#vmstat-swpd-alone explanation="После прежней нехватки страницы могут оставаться в swap, поэтому одного объёма недостаточно."}
::option[Устойчивая подкачка, сопоставленная с освобождением памяти и задержкой нагрузки.]{#vmstat-correlated-pressure .correct explanation="Повторные согласованные свидетельства связывают поведение памяти с текущим влиянием."}
::option[Имя хоста, показанное при входе.]{#vmstat-hostname explanation="Имя хоста не измеряет освобождение памяти или подкачку."}
:::

## Активность CPU и системы

Столбцы CPU обычно включают проценты пользователя (`us`), системы (`sy`), простоя (`id`), ожидания ввода-вывода (`wa`) и забранного времени (`st`). Системные столбцы включают число прерываний (`in`) и переключений контекста (`cs`) в секунду. Интерпретируйте всплески относительно базового уровня: высокая частота переключений контекста может быть нормальной для некоторых нагрузок.

:::single-choice{#vmstat-r-column}
Что представляет поле процесса `r`?

::option[Файловые системы, подключённые только для чтения.]{#vmstat-readonly explanation="Флаги подключения файловых систем не представлены этим полем процессов."}
::option[Удалённых пользователей с активными оболочками.]{#vmstat-remote-users explanation="Сеансы входа сообщают другие инструменты."}
::option[Задачи, готовые к выполнению или ожидающие CPU.]{#vmstat-runnable .correct explanation="Сравнение этого числа с ёмкостью CPU помогает определить спрос на процессор."}
:::

## Итоги

Теперь вы можете интерпретировать `vmstat` как согласованное по времени представление системы.

1. Отличайте начальный накопительный отчёт от интервальных образцов.
2. Рассматривайте кэш как потенциально освобождаемую память.
3. Сопоставляйте подкачку с освобождением и влиянием на приложение.
4. Читайте поля процессов, ввода-вывода, системы и CPU вместе.
