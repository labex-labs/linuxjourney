Канальный уровень переносит пакеты сетевого уровня через одну локальную среду или виртуальный канал. Ethernet и Wi-Fi различаются деталями кадров, но обе технологии обеспечивают локальную доставку под уровнем IP.

## Кадры Ethernet

Кадр Ethernet содержит MAC-адреса назначения и источника, поле EtherType или длины, полезную нагрузку и концевую контрольную последовательность кадра. При физической передаче также используются преамбула и начальный разделитель. Контрольная последовательность обнаруживает повреждение в канале, но не исправляет повреждённый кадр и не защищает его криптографически.

:::single-choice{#link-layer-fcs-purpose}
Для чего используется контрольная последовательность кадра Ethernet?

::option[Для обнаружения повреждения кадра в канале.]{#link-layer-detect-corruption .correct explanation="Получатель может отбросить кадр, который не прошёл проверку целостности."}
::option[Для шифрования полезной нагрузки на всех маршрутизируемых переходах.]{#link-layer-fcs-encryption explanation="FCS — код обнаружения ошибок, а не средство шифрования или аутентификации."}
::option[Для выбора приложения по TCP-порту.]{#link-layer-fcs-port explanation="Транспортные порты передаются внутри полезной нагрузки IP."}
:::

## Коммутаторы и локальная доставка

Коммутатор Ethernet запоминает, с каких портов поступают исходные MAC-адреса, и направляет известные индивидуальные кадры к запомненному порту назначения. Широковещательный трафик и часть трафика с неизвестным назначением рассылаются по широковещательному домену. VLAN позволяют разделить одну систему коммутации на отдельные логические канальные домены.

## Разрешение адреса следующего перехода

Для IPv4 поверх Ethernet протокол разрешения адресов ARP сопоставляет локальный IPv4-адрес следующего перехода с MAC-адресом. Сначала хост проверяет кэш соседей. При необходимости он отправляет широковещательный запрос ARP, а владелец адреса или уполномоченный прокси отвечает.

Если адрес назначения IP находится вне локального канала, хост разрешает MAC-адрес шлюза по умолчанию или другого выбранного шлюза, а не удалённого узла. IPv6 вместо ARP использует обнаружение соседей через ICMPv6.

:::single-choice{#link-layer-remote-destination-mac}
Какой MAC-адрес хост использует для назначения IPv4 вне локального канала?

::option[MAC-адрес выбранного маршрутизатора следующего перехода.]{#link-layer-gateway-mac .correct explanation="IP-пакет по-прежнему адресован удалённому хосту, а локальный кадр направляется маршрутизатору."}
::option[MAC-адрес удалённого сервера на всём пути через маршрутизаторы.]{#link-layer-remote-mac explanation="MAC-адреса являются идентификаторами локального канала и не передаются сквозным образом."}
::option[MAC-адрес, вычисленный из TCP-порта назначения.]{#link-layer-port-mac explanation="Транспортные порты не определяют канальные адреса."}

## Проверка состояния соседей

Просмотрите записи ARP для IPv4 и записи обнаружения соседей для IPv6 командой:

```bash
$ ip neighbor show
```

Состояния `REACHABLE`, `STALE`, `DELAY`, `PROBE` и `FAILED` описывают процесс определения недоступности соседа. `STALE` не означает неисправность: это лишь указывает, что кэшированное подтверждение доступности уже не является свежим и при использовании его можно проверить.

:::single-choice{#link-layer-stale-neighbor}
Что означает запись соседа в состоянии `STALE`?

::option[Сосед навсегда заблокирован межсетевым экраном.]{#link-layer-stale-blocked explanation="Это состояние не описывает политику межсетевого экрана."}
::option[MAC-адрес записан на диск в качестве резервной копии.]{#link-layer-stale-backup explanation="Состояние соседа — это оперативная информация кэша."}
::option[Для кэшированного сопоставления нет недавнего подтверждения доступности.]{#link-layer-stale-confirmation .correct explanation="Сетевой стек всё ещё может использовать его и при необходимости проверить доступность."}
:::

## Инкапсуляция при прохождении маршрутизатора

Отправитель помещает IP-пакет в кадр, адресованный следующему переходу. Маршрутизатор проверяет и удаляет входящий кадр, обрабатывает IP-заголовок, выбирает исходящий маршрут и создаёт новый кадр для соответствующего канала. Получатель выполняет обратную декапсуляцию и передаёт транспортную полезную нагрузку подходящему сокету.

:::single-choice{#link-layer-router-reframing}
Что при обычной пересылке остаётся прежним, когда маршрутизатор меняет кадр Ethernet?

::option[IP-адрес назначения, если его не изменяет промежуточное устройство, например NAT.]{#link-layer-ip-destination .correct explanation="Обычные маршрутизаторы пересылают пакет к конечному IP-адресу, заменяя локальные для каждого перехода кадры."}
::option[Контрольная последовательность входящего кадра.]{#link-layer-same-fcs explanation="Новый исходящий кадр получает собственное значение контроля целостности канала."}
::option[MAC-адрес назначения во всех каналах.]{#link-layer-same-mac explanation="В каждом канале используется соответствующий канальный адрес следующего перехода."}
:::

## Итоги

Теперь вы можете проследить один шаг доставки IP-пакета по локальному каналу.

1. Определяйте основные поля кадра Ethernet и концевое значение контроля целостности.
2. Объясняйте, как коммутатор запоминает локальные направления пересылки.
3. Разрешайте следующий переход IPv4 с помощью ARP, а соседей IPv6 — с помощью NDP.
4. Интерпретируйте состояние кэша соседей, не делая преждевременных выводов о сбое.
5. Помните, что маршрутизаторы создают кадры заново для каждого исходящего канала.
