Internet Control Message Protocol передаёт управляющую, диагностическую информацию и сведения об ошибках наряду с IP. ICMP для IPv4 и ICMPv6 связаны, но являются разными протоколами с различными номерами типов сообщений и обязанностями.

## Типы, коды и контрольные суммы

Сообщение ICMP содержит тип, уточняющий код там, где он применим, и контрольную сумму. В сообщения об ошибках обычно включается часть вызвавшего их пакета, чтобы отправитель мог связать ошибку с потоком.

:::single-choice{#icmp-code-purpose} Что предоставляет код ICMP?

::option[Постоянное DNS-имя сообщившего маршрутизатора.]{#icmp-code-dns explanation="Разрешение имён не является назначением этого поля."}
::option[Более конкретное значение внутри типа сообщения ICMP.]{#icmp-code-specific .correct explanation="Например, коды недостижимости назначения различают несколько причин сбоя."}
::option[Полную полезную нагрузку каждого предыдущего пакета.]{#icmp-code-all-payload explanation="Согласно правилам протокола, ошибка цитирует лишь достаточную для идентификации часть вызвавшего пакета."}
:::

## Эхо- и ошибочные сообщения

В ICMPv4 Echo Request имеет тип 8, а Echo Reply — тип 0. Destination Unreachable соответствует типу 3, а Time Exceeded — типу 11. В ICMPv6 используются другие номера типов, поэтому перед интерпретацией захвата всегда определяйте семейство адресов.

:::single-choice{#icmpv4-echo-request-type} Какой тип имеет ICMPv4 Echo Request?

::option[0]{#icmp-type-zero explanation="Тип 0 — это ICMPv4 Echo Reply."}
::option[11]{#icmp-type-eleven explanation="Тип 11 — ICMPv4 Time Exceeded."}
::option[8]{#icmp-type-eight .correct explanation="Обычно ping отправляет это сообщение ICMPv4, чтобы запросить эхо-ответ."}
:::

## Path MTU и необходимый ICMP

ICMP — не просто необязательный трафик ping. Ошибки IPv4 о необходимости фрагментации и сообщения ICMPv6 Packet Too Big обеспечивают Path MTU Discovery. ICMPv6 также передаёт Neighbor Discovery и Router Advertisements. Поэтому блокировка всего ICMP может создавать чёрные дыры и нарушать работу IPv6.

Фильтруйте по необходимым типам, направлению, частоте и области действия вместо безусловного запрета. Некоторые сообщения ICMP могут быть подделаны атакующим, поэтому проверяйте контекст процитированного пакета и сопоставляйте его с локальными маршрутами и захватами.

:::single-choice{#icmp-block-all-risk} Почему блокировка всего ICMP может нарушить допустимый трафик?

::option[Каждый ответ HTTP передаётся внутри ICMP Echo Reply.]{#icmp-http-echo explanation="HTTP обычно использует TCP или QUIC, а не эхо-сообщения ICMP."}
::option[ICMP хранит все пароли приложений.]{#icmp-passwords explanation="ICMP не является базой учётных данных."}
::option[ICMP передаёт необходимую информацию Path MTU и управления IPv6.]{#icmp-essential-control .correct explanation="Подавление этих сообщений может помешать правильному выбору размера пакета или обнаружению соседей и маршрутизаторов."}
:::

## Интерпретация молчания

Отсутствие ответа ICMP может означать фильтрацию, ограничение частоты, асимметричную маршрутизацию, отсутствие обратного маршрута, неработающий узел или устройство, которое просто не отвечает на такое сообщение. И наоборот, ошибку ICMP может создать промежуточное устройство, а не конечное назначение.

:::single-choice{#icmp-silence-meaning} Что само по себе доказывает отсутствие Echo Reply?

::option[Целевое приложение определённо остановлено.]{#icmp-silence-app-down explanation="Служба может работать, пока эхо-трафик фильтруется или игнорируется."}
::option[Имя узла назначения удалено из DNS.]{#icmp-silence-dns-deleted explanation="Запрос по числовому адресу может остаться без ответа независимо от DNS."}
::option[Только то, что в этом эхо-обмене не наблюдалось ответа.]{#icmp-silence-limited .correct explanation="Для определения причины нужны дополнительные данные о маршруте, транспорте, приложении и захвате."}
:::

## Итоги

Теперь вы можете интерпретировать ICMP как управляющие свидетельства, а не как двоичный вердикт о связности.

1. Читайте тип и код в правильном семействе IP.
2. Различайте роли эхо-сообщений, недостижимости и превышения времени.
3. Сохраняйте ICMP, необходимый для Path MTU и работы IPv6.
4. Сопоставляйте ошибки и молчание с другими данными о пути.
