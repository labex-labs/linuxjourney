**Коммит** сохраняет состояние файлов, подготовленных в индексе. В нём также хранятся сообщение, сведения об авторе и связь с предыдущими коммитами. По присвоенному Git идентификатору можно найти этот коммит в истории.

## Настраиваем данные автора для учебного репозитория

Git записывает в коммит имя и адрес электронной почты. Задайте учебные значения только для этого репозитория. Эти данные показываются в истории и не дают доступа к удалённым сервисам.

```bash
$ git config --local user.name "Journey Learner"
$ git config --local user.email "learner@example.com"
```

Возьмите учебный репозиторий, в котором `index.html` уже добавлен в индекс. Чтобы проверить, какие файлы попадут в коммит, выполните `git status`.

:::single-choice{#git-commits-identity-scope} Что здесь делает параметр --local?

::option[Выполняет вход на общий сервис размещения репозиториев.]{#git-commits-identity-scope-b explanation="Имя и почта записываются в коммит. Для удалённого сервиса нужна отдельная аутентификация."}
::option[Задаёт данные об авторе для этого репозитория.]{#git-commits-identity-scope-a .correct explanation="Локальная настройка относится к текущему репозиторию."}
::option[Меняет автора во всех существующих коммитах.]{#git-commits-identity-scope-c explanation="Настройки будут использованы в будущих коммитах."}
:::

## Сохраняем снимок

Добавьте нужную версию в индекс, а затем выполните `git commit`. Параметр `-m` позволяет указать сообщение прямо в командной строке.

```bash
$ git commit -m "Set the homepage heading"
```

В коммите сохраняется версия файла из индекса. Если затем снова отредактировать файл в рабочем дереве, более поздняя правка не войдёт в коммит, пока вы не добавите её в индекс.

:::single-choice{#git-commits-staged-snapshot} Вы добавили в индекс версию с заголовком Welcome, затем заменили его в файле на Hi и больше не обновляли индекс. Какой заголовок попадёт в коммит?

::option[Welcome, потому что именно эта версия была добавлена в индекс.]{#git-commits-staged-snapshot-c .correct explanation="Коммит фиксирует содержимое индекса."}
::option[Hi, потому что это самый свежий текст на диске.]{#git-commits-staged-snapshot-a explanation="Текущая рабочая копия может отличаться от версии в индексе."}
::option[Оба, потому что Git автоматически сохраняет каждую правку.]{#git-commits-staged-snapshot-b explanation="В индекс попадает одна выбранная версия файла."}
:::

## Читаем краткую историю

Чтобы увидеть компактный вывод истории, выполните `git log --oneline`. В начале каждой строки стоит сокращённый идентификатор коммита, за ним — сообщение. Ваш идентификатор будет отличаться от показанного в примере.

```text
$ git log --oneline
a12c345 Set the homepage heading
```

Когда нужен конкретный коммит, указывайте его идентификатор: одинаковое сообщение может быть у разных коммитов. Как правило, первой в текущей истории показывается самая новая запись.

:::single-choice{#git-commits-identify-snapshot} У двух коммитов одинаковое сообщение Set the homepage heading. Как различить сохранённые в них снимки?

::option[По общему для них сообщению.]{#git-commits-identify-snapshot-a explanation="Один текст может встречаться у нескольких коммитов."}
::option[По имени файла, который они оба меняют.]{#git-commits-identify-snapshot-c explanation="Один файл может входить во множество коммитов."}
::option[По идентификатору коммита.]{#git-commits-identify-snapshot-b .correct explanation="Идентификатор позволяет указать конкретную запись."}
:::

Теперь вы можете сохранить подготовленные изменения и найти их в истории.

2. Сохраните снимок из индекса с понятным сообщением.
3. Определите нужный коммит по краткой истории.
