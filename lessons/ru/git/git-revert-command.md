Изменение можно отменить, даже если вы уже поделились им. Команда `git revert` создаёт новый коммит с обратным изменением. В истории остаётся видно, что изменилось изначально и что сделали для отмены.

## Находим изменение, которое нужно отменить

В ветке `main` учебного репозитория есть коммиты главной страницы и страницы состояния. Посмотрите краткую историю, чтобы определить самую свежую запись. Идентификаторы ниже приведены для примера.

```text
$ git log --oneline
3ab4501 Add a health page
a12c345 Set the homepage heading
```

`HEAD` указывает на коммит, который сейчас открыт в рабочем дереве. Убедитесь, что это изменение, которое вы хотите отменить. Перед продолжением выполните `git status`, чтобы проверить, что в рабочем дереве нет несохранённых правок.

:::single-choice{#git-revert-command-newest-commit} Какое изменение отменится, если в этом примере отменить HEAD?

::option[Более раннее изменение заголовка главной страницы.]{#git-revert-command-newest-commit-b explanation="Заголовок меняется в предыдущем коммите."}
::option[Оба изменения за одну операцию.]{#git-revert-command-newest-commit-c explanation="Здесь HEAD указывает на один коммит, и отмена относится именно к нему."}
::option[Добавление страницы состояния.]{#git-revert-command-newest-commit-a .correct explanation="HEAD указывает на самую свежую запись в этой ветке."}
:::

## Записываем отмену

В учебном репозитории с чистым рабочим деревом отмените коммит страницы состояния. Команда изменит файлы рабочего дерева и создаст коммит. Параметр `--no-edit` оставляет сообщение об отмене, которое предложил Git.

```bash
$ git revert --no-edit HEAD
```

В этом примере файл страницы состояния удаляется, поскольку исходный коммит его добавил. Если в более поздних коммитах изменились те же строки, Git может остановиться и попросить разрешить конфликты. Прежде чем продолжать, проверьте состояние репозитория.

:::single-choice{#git-revert-command-undo-effect} Как должны измениться файлы проекта, если отмена прошла успешно?

::option[Файл главной страницы удалится вместе со страницей состояния.]{#git-revert-command-undo-effect-a explanation="Более ранний коммит главной страницы продолжает действовать."}
::option[Файл страницы состояния будет удалён.]{#git-revert-command-undo-effect-b .correct explanation="Отмена убирает файл, который добавил выбранный коммит."}
::option[Страница состояния добавится ещё раз.]{#git-revert-command-undo-effect-c explanation="При отмене применяется обратное изменение."}
:::

## Проверяем историю после отмены

Снова выполните `git log --oneline`. Над исходным коммитом страницы состояния должна появиться новая запись об отмене. Командой `git status --short` проверьте, остались ли локальные изменения. Новый коммит можно проверить и отправить как любое другое изменение.

:::single-choice{#git-revert-command-history-after-revert} Что должно остаться под записью об отмене?

::option[Исходный коммит страницы состояния.]{#git-revert-command-history-after-revert-c .correct explanation="Две записи показывают исходное изменение и его отмену."}
::option[Только исходный коммит с изменением заголовка.]{#git-revert-command-history-after-revert-a explanation="Исходный коммит страницы состояния по-прежнему есть в истории."}
::option[Ни одного коммита.]{#git-revert-command-history-after-revert-b explanation="Отмена добавляет коммит к существующей истории ветки."}
:::

## Сохраняем другие изменения

Представьте историю с тремя отдельными изменениями. Сначала добавили файл состояния, затем исправили опечатку на главной странице. Обоими изменениями уже поделились. Если отменить коммит, который добавил файл состояния, файл можно убрать, сохранив исправленную опечатку. Прежде чем выбрать коммит, проверьте историю и затронутые файлы.

:::single-choice{#git-revert-command-final-application} Какая проверка показывает, что отмена сохранила нужную работу?

::option[Коммит с добавлением файла состояния исчез из истории.]{#git-revert-command-final-application-b explanation="При отмене исходная запись остаётся в истории."}
::option[Исправление опечатки тоже исчезло с главной страницы.]{#git-revert-command-final-application-c explanation="Опечатку исправили отдельным изменением, которое должно сохраниться."}
::option[Файла состояния больше нет, исправление на главной странице осталось, а в истории видна отмена.]{#git-revert-command-final-application-a .correct explanation="Так можно убедиться, что выбранное изменение отменено, исправление сохранилось, а в истории появилась новая запись."}
:::

## Итоги

Теперь вы можете отменить сохранённое изменение и оставить в истории след обеих операций.

1. Определите, какой именно коммит нужно отменить.
2. Отмените его в чистом рабочем дереве.
3. Убедитесь, что в истории видны оба коммита.
