Из вывода команды status понятно, какие файлы изменились. Чтобы увидеть изменённые строки, используйте `git diff`. В этом примере файл `index.html` с заголовком Hello уже добавлен в индекс в предыдущем уроке.

## Сравниваем рабочий файл с версией в индексе

Замените заголовок в учебном файле и сравните рабочую версию с версией в индексе.

```bash
$ printf '%s\n' '<h1>Welcome</h1>' > index.html
$ git diff -- index.html
```

Символы `--` отделяют параметры команды от пути к нужному файлу. В выводе строка, начинающаяся с `-`, взята из предыдущей версии. Строка, начинающаяся с `+`, пришла ей на смену. Ниже показан фрагмент вывода с этими двумя строками.

```diff
-<h1>Hello</h1>
+<h1>Welcome</h1>
```

:::single-choice{#git-diff-command-changed-heading} Какой заголовок сейчас находится в рабочей копии?

::option[Welcome.]{#git-diff-command-changed-heading-b .correct explanation="В этом сравнении строка со знаком «плюс» показывает новый текст в рабочем дереве."}
::option[Hello.]{#git-diff-command-changed-heading-a explanation="Строка со знаком «минус» показывает исходный текст, который сейчас в индексе."}
::option[Оба заголовка.]{#git-diff-command-changed-heading-c explanation="Две строки показывают один и тот же заголовок до и после правки."}
:::

## Сравниваем индекс с историей

Команда `git diff --staged -- index.html` сравнивает версию из индекса с последним коммитом. До первого коммита Git берёт за основу пустое состояние. Поэтому в выводе видно, что заголовок Hello добавлен. При этом `git diff` без параметров показывает более позднюю правку — замену на Welcome.

```bash
$ git diff --staged -- index.html
```

:::single-choice{#git-diff-command-preview-commit} Какая команда покажет, что попадёт в коммит, если создать его прямо сейчас?

::option[git diff -- index.html]{#git-diff-command-preview-commit-b explanation="Эта команда сравнивает текущий рабочий файл с версией в индексе."}
::option[git status --short]{#git-diff-command-preview-commit-c explanation="Вывод показывает, где есть изменения, без подробностей о конкретных строках."}
::option[git diff --staged -- index.html]{#git-diff-command-preview-commit-a .correct explanation="Команда сравнивает версию из индекса с предыдущим снимком."}
:::

## Почему вывод бывает пустым

Снова добавьте текущую версию файла в индекс, чтобы обновить его.

```bash
$ git add index.html
$ git diff -- index.html
```

Теперь `git diff` без параметров может ничего не показать: рабочий файл и версия в индексе совпадают. Чтобы увидеть ещё не сохранённые в коммите изменения, сравните индекс с историей. В обычное сравнение также не попадают неотслеживаемые файлы. Если сомневаетесь, где сейчас изменение, проверьте состояние репозитория.

:::single-choice{#git-diff-command-empty-diff} Сразу после добавления правки в индекс git diff без параметров ничего не выводит. Где всё ещё можно увидеть изменение относительно истории?

::option[Повторно выполнить git diff без параметров.]{#git-diff-command-empty-diff-a explanation="Повторная команда сравнит те же совпадающие версии."}
::option[В выводе git diff --staged.]{#git-diff-command-empty-diff-c .correct explanation="Команда сравнит индекс с опорным состоянием в истории."}
::option[Только после создания коммита.]{#git-diff-command-empty-diff-b explanation="Посмотреть содержимое будущего коммита можно ещё до его создания."}
:::
