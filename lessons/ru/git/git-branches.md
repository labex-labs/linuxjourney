**Ветка** — это имя, которое указывает на коммит. Когда вы создаёте коммит в текущей ветке, её имя начинает указывать на новый коммит. Другая ветка остаётся на своей позиции, пока вы её не обновите.

## Начинаем работу в отдельной ветке

Находясь в ветке `main` учебного репозитория, создайте ветку `health-page` и переключитесь на неё. Параметр `-c` у команды `git switch` означает «создать ветку».

```bash
$ git switch -c health-page
```

Сначала оба имени указывают на один и тот же коммит. Команда `git branch --show-current` покажет, в какой ветке появится ваш следующий коммит.

:::single-choice{#git-branches-start-pointer} На какой коммит указывает новое имя сразу после git switch -c health-page?

::option[На пустой коммит, созданный этой командой.]{#git-branches-start-pointer-a explanation="Команда создаёт имя, которое указывает на уже существующий коммит."}
::option[На коммит в чужом репозитории.]{#git-branches-start-pointer-c explanation="Команда создаёт локальную ветку в текущем репозитории."}
::option[На коммит, с которого вы начали.]{#git-branches-start-pointer-b .correct explanation="Изначально оба имени указывают на один снимок."}
:::

## Сохраняем изменение в ветке

Находясь в `health-page`, добавьте файл состояния с одной строкой и сохраните его в коммите.

```bash
$ printf '%s\n' ready > health.txt
$ git add health.txt
$ git commit -m "Add a health page"
```

Допустим, коммит главной страницы обозначен A, а коммит страницы состояния — B.

```text
A (main) --- B (health-page)
```

Только `health-page` переместилась на B. Если в рабочем дереве нет несохранённых изменений, после переключения обратно на `main` файлы вернутся к состоянию A.

:::single-choice{#git-branches-branch-snapshot} В какой ветке находится коммит страницы состояния до слияния?

::option[В обеих, потому что они в одном репозитории.]{#git-branches-branch-snapshot-a explanation="Ветки одного репозитория могут указывать на разные снимки."}
::option[Только в health-page.]{#git-branches-branch-snapshot-c .correct explanation="Именно эта ветка была текущей, когда вы создали коммит B."}
::option[Только в main, потому что работа началась с неё.]{#git-branches-branch-snapshot-b explanation="При создании коммита в health-page ветка main осталась на прежнем месте."}
:::

## Выполняем слияние с main

Переключитесь на ветку, которая должна получить изменение, а затем укажите ветку, из которой оно должно прийти.

```bash
$ git switch main
$ git merge health-page
```

В этом примере после A в ветке `main` нет своих изменений. Git может сразу переместить её на B. Такая операция называется **перемоткой вперёд** (fast-forward). Если новые коммиты появились в обеих ветках, Git может потребоваться объединить их изменения. Прочитайте результат, чтобы убедиться, что слияние завершилось.

:::single-choice{#git-branches-merge-direction} Вы хотите перенести изменение из health-page в main. В какой ветке выполняется слияние?

::option[В main, с указанием health-page как источника.]{#git-branches-merge-direction-a .correct explanation="Результат слияния попадает в текущую ветку."}
::option[В health-page, с указанием main как источника.]{#git-branches-merge-direction-b explanation="В таком случае обновится health-page."}
::option[В новой ветке, которой нет ни на одной стороне.]{#git-branches-merge-direction-c explanation="Main останется на прежнем коммите, пока не получит изменение."}
:::

## Итоги

Теперь вы можете проследить, как изменение из локальной ветки попадает в main.

1. Создайте ветку на текущем коммите.
2. Сохраните изменение в нужной ветке.
3. Выполните слияние в ветку, которая должна получить изменение.
