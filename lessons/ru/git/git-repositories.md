Сайт начинается с нескольких файлов. Git позволяет зафиксировать, как эти файлы выглядели в разные моменты. Файлы проекта и история изменений образуют локальное рабочее пространство Git.

## Создаём репозиторий

Начните в учебном каталоге, где можно создать новую папку. Выполните следующие команды один раз. Знак доллара обозначает приглашение оболочки.

```bash
$ mkdir journey-git
$ cd journey-git
$ git init --initial-branch=main
```

Новая папка — ваше **рабочее дерево**, в котором вы редактируете файлы проекта. Git создаёт в нём скрытый каталог `.git` для истории и настроек. В новом репозитории ещё нет сохранённых изменений. Первая ветка называется `main`.

:::single-choice{#git-repositories-empty-history} Вы инициализировали репозиторий в каталоге, где уже есть index.html. Что будет с историей этого файла?

::option[Git сразу запишет файл в первый коммит.]{#git-repositories-empty-history-b explanation="При инициализации файлы проекта ещё не сохраняются в истории."}
::option[Git сможет записать файл в одном из следующих коммитов.]{#git-repositories-empty-history-a .correct explanation="Инициализация подготавливает репозиторий. Чтобы сохранить состояние файла, нужен отдельный шаг."}
::option[Git перенесёт файл в свой скрытый каталог.]{#git-repositories-empty-history-c explanation="Файлы проекта остаются в рабочем дереве, где их можно редактировать."}
:::

## Находим корень рабочего дерева

Команда `git rev-parse --show-toplevel` показывает корень текущего репозитория. Если выполнить её в учебной папке, путь должен заканчиваться на `journey-git`. Вложенный каталог принадлежит тому же репозиторию, если внутри этого каталога нет собственного репозитория.

```bash
$ git rev-parse --show-toplevel
```

:::single-choice{#git-repositories-find-root} Вы перешли в подкаталог images внутри journey-git. Какой каталог Git покажет как корень?

::option[Каталог journey-git.]{#git-repositories-find-root-b .correct explanation="Git находит корень репозитория выше текущего каталога."}
::option[Подкаталог images.]{#git-repositories-find-root-a explanation="Команда показывает верхний уровень репозитория, даже если оболочка открыта в подкаталоге."}
::option[Скрытый каталог .git.]{#git-repositories-find-root-c explanation="Команда показывает корень рабочего дерева, где находятся файлы проекта."}
:::

## Начинаем с готовой историей

Если нужный репозиторий уже существует, скопируйте его с помощью `git clone`. При обычном клонировании Git создаёт локальное рабочее дерево и загружает существующую историю. Для проекта, историю которого вы начинаете локально, используйте `git init`. В следующих уроках вы продолжите работать с `journey-git`.

:::single-choice{#git-repositories-choose-start} Коллега дал вам адрес репозитория, история которого вам нужна. С чего начать?

::option[Создать пустую папку и инициализировать в ней репозиторий.]{#git-repositories-choose-start-a explanation="В новом репозитории не будет истории коллеги."}
::option[Скопировать только видимые файлы сайта.]{#git-repositories-choose-start-b explanation="Видимые файлы дают вам одну версию сайта без истории репозитория."}
::option[Клонировать репозиторий коллеги.]{#git-repositories-choose-start-c .correct explanation="При клонировании вы получаете общую историю и локальное рабочее дерево."}
:::

## Итоги

Теперь вы можете выбрать подходящий способ создать локальный репозиторий Git.

1. Различайте рабочее дерево и скрытый каталог Git.
2. Находите корень репозитория из подкаталога.
3. Для новой истории инициализируйте репозиторий, а для работы с существующей историей клонируйте его.
