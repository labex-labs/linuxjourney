Когда вы работаете в репозитории, `git status` показывает, какие изменения Git видит в рабочем дереве и какие из них вы выбрали для следующего сохранения. Используйте пустой репозиторий `journey-git` из предыдущего урока.

## Находим новый файл

Создайте небольшую страницу, затем выведите состояние в кратком формате.

```bash
$ printf '%s\n' '<h1>Hello</h1>' > index.html
$ git status --short
```

Здесь `>` записывает данные в указанный файл. Если файл существует, его содержимое перезаписывается. Новый файл в кратком выводе выглядит как `?? index.html`. Git называет его **неотслеживаемым**. Файл существует, но ещё не выбран для следующего снимка состояния проекта.

:::single-choice{#git-status-command-untracked-file} Рядом с новым файлом Git выводит два вопросительных знака. Что они означают?

::option[Файл входит в последний сохранённый снимок.]{#git-status-command-untracked-file-a explanation="Неотслеживаемого файла в последнем снимке нет."}
::option[Файл удалён из рабочего дерева.]{#git-status-command-untracked-file-c explanation="Git видит этот файл в рабочем дереве."}
::option[Файл существует, но пока не входит в следующий снимок.]{#git-status-command-untracked-file-b .correct explanation="Вы можете добавить файл в индекс."}
:::

## Проверяем подготовленные изменения

Выполните `git add`, чтобы выбрать текущее содержимое файла для следующего снимка. Сохранённый снимок называется **коммитом**. Выбранное содержимое помещается в **индекс**. В кратком выводе в первой колонке теперь стоит `A`: добавление файла подготовлено к коммиту.

```bash
$ git add index.html
$ git status --short
```

:::single-choice{#git-status-command-staged-new} Где после git add находится выбранная версия index.html?

::option[Уже в новом коммите.]{#git-status-command-staged-new-a explanation="Git add подготавливает содержимое для следующего коммита. Сам коммит создаётся отдельно."}
::option[В индексе.]{#git-status-command-staged-new-c .correct explanation="Git выбрал содержимое файла на момент выполнения git add."}
::option[В чужом репозитории.]{#git-status-command-staged-new-b explanation="Команда меняет только ваш локальный индекс."}
:::

## Различаем два вида изменений

В кратком выводе перед именем файла есть две колонки. Первая показывает изменения в индексе, вторая — правки рабочего файла после добавления в индекс. Например, `AM index.html` означает, что новый файл подготовлен к коммиту, а его рабочая копия затем изменена. Если удобнее читать подробности по разделам, выполните `git status` без параметров.

:::single-choice{#git-status-command-two-columns} Рядом с index.html стоит AM. Что стоит проверить перед следующим коммитом?

::option[Вошла ли нужная правка в версию, сохранённую в индексе.]{#git-status-command-two-columns-a .correct explanation="Буква M во второй колонке говорит, что в рабочей копии есть более поздняя правка."}
::option[Есть ли в репозитории другой файл с именем AM.]{#git-status-command-two-columns-b explanation="AM — два обозначения состояния файла index.html."}
::option[Не удалён ли файл с диска.]{#git-status-command-two-columns-c explanation="M обозначает изменение в рабочем дереве."}
:::

## Итоги

Теперь вы можете проверить, какие изменения попадут в следующий коммит.

1. Распознавайте новые неотслеживаемые файлы.
2. Добавляйте файл в индекс с помощью git add.
3. Отдельно смотрите изменения в индексе и в рабочем дереве.
