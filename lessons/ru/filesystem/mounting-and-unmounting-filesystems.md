Монтирование присоединяет файловую систему к каталогу в видимом пространстве имён. Источником может быть блочное устройство, сетевой экспорт, виртуальная файловая система, источник bind или иной специфичный для реализации объект. Целевой каталог называется точкой монтирования.

## Подготовка и проверка точки монтирования

Если этого требует локальная политика, создайте каталог с осмысленным именем:

```bash
$ sudo mkdir -p /mnt/mydrive
```

Проверьте его до монтирования:

```bash
$ findmnt --target /mnt/mydrive
$ sudo ls -la /mnt/mydrive
```

Монтирование в непустой каталог скрывает его существующие записи за новой файловой системой до размонтирования, но не удаляет их. Это может запутать приложения и незаметно расходовать место, поэтому используйте пустую выделенную точку монтирования.

:::single-choice{#mount-umount-nonempty-target}
Что происходит с существующими файлами каталога, когда в него монтируют другую файловую систему?

::option[Они автоматически копируются в новую файловую систему.]{#mount-umount-copied-files explanation="Монтирование меняет присоединение пространства имён и не переносит содержимое каталога."}
::option[Ядро навсегда удаляет их.]{#mount-umount-erased-files explanation="Обычно файлы появляются после размонтирования, поскольку были скрыты, а не удалены."}
::option[Они скрыты монтированием до его отсоединения.]{#mount-umount-hidden-files .correct explanation="Нижележащий каталог сохраняется, но поиск пути переходит в смонтированную файловую систему."}
:::

## Монтирование проверенной файловой системы

Подтвердив идентичность источника, обнаруженный тип и ожидаемое содержимое, выполните явное монтирование:

```bash
$ sudo mount -t ext4 /dev/VERIFIED-PARTITION /mnt/mydrive
```

Параметр `-t` задаёт реализацию файловой системы. Mount часто может определить тип, но явный тип и проверенные параметры яснее выражают намерение. Для недоверенного или съёмного содержимого рассмотрите ограничения `ro`, `nosuid`, `nodev` и `noexec`, если они подходят нагрузке; каждое имеет пределы и не является полноценной песочницей.

Проверьте, что фактически смонтировано:

```bash
$ findmnt --target /mnt/mydrive -o TARGET,SOURCE,FSTYPE,OPTIONS
```

Монтирования ограничены пространством имён. Монтирование, созданное в контейнере или приватном пространстве службы, может отсутствовать в представлении другого процесса.

:::single-choice{#mount-umount-mount-role}
Что делает команда `mount` в показанном процессе?

::option[Создаёт новую файловую систему и стирает источник.]{#mount-umount-format-source explanation="Создание файловой системы — отдельная разрушительная операция `mkfs`."}
::option[Присоединяет источник файловой системы к каталогу в пространстве имён монтирования.]{#mount-umount-attach-filesystem .correct explanation="После этого поиск путей под целью переходит в присоединённую файловую систему."}
::option[Изменяет границы разделов диска.]{#mount-umount-change-partitions explanation="Редактирование таблицы разделов выполняется отдельно от монтирования пространства имён."}
:::

## Использование UUID файловой системы

Имена перечисления вроде `/dev/sdb2` могут меняться. Найдите идентификаторы файловых систем:

```bash
$ lsblk -f
$ sudo blkid
```

Затем смонтируйте проверенную файловую систему по UUID:

```bash
$ sudo mount UUID=130b882f-7d79-436d-a096-1e594c92bb76 /mnt/mydrive
```

UUID идентифицирует файловую систему, но не обязательно физический диск. При переформатировании он меняется, а при клонировании может дублироваться. До одновременного подключения оригинала и клона проверьте уникальность.

:::single-choice{#mount-umount-uuid-benefit}
Почему UUID файловой системы часто предпочтительнее `/dev/sdX` для постоянной конфигурации?

::option[Он навсегда предотвращает отказы любых устройств хранения.]{#mount-umount-uuid-no-failure explanation="Идентификатор не обеспечивает избыточность, исправление целостности или резервное копирование."}
::option[Он гарантирует разные идентификаторы клонированных файловых систем.]{#mount-umount-uuid-clone-unique explanation="Поблочный клон может скопировать UUID и создать конфликт."}
::option[Он связан с идентичностью файловой системы, а не текущим порядком перечисления.]{#mount-umount-uuid-identity .correct explanation="Путь блочного устройства может измениться, пока метаданные файловой системы сохраняют UUID."}
:::

## Безопасное размонтирование

Отсоедините файловую систему по точной точке монтирования:

```bash
$ sudo umount /mnt/mydrive
```

Команда пишется `umount`, без первой `n`. Успешное размонтирование отсоединяет файловую систему после завершения требуемой записи ядром и при отсутствии мешающих ссылок. Перед отключением хранилища подтвердите результат через `findmnt`.

Для съёмного носителя успешное размонтирование не всегда является последним шагом безопасного извлечения. Стеки хранения рабочего стола могут предлагать извлечение или отключение питания, которое сбрасывает кеши устройства и отключает USB-устройство. Следуйте процессу платформы и оборудования.

:::single-choice{#mount-umount-command-name}
Какая команда отсоединяет `/mnt/mydrive`?

::option[`umount /mnt/mydrive`]{#mount-umount-umount-correct .correct explanation="`umount` отсоединяет файловую систему, смонтированную в указанной цели."}
::option[`unmount /mnt/mydrive`]{#mount-umount-unmount-spelling explanation="В названии стандартной команды отсутствует первая `n`."}
::option[`mkfs /mnt/mydrive`]{#mount-umount-mkfs-target explanation="Mkfs создаёт структуры файловой системы и не должен использоваться для отсоединения."}
:::

## Диагностика занятой файловой системы

Размонтирование завершается ошибкой, если в пространстве имён остаются активные ссылки: открытые файлы, рабочий каталог процесса, вложенные монтирования, swap или другие уровни хранилища. Исследуйте причину, а не применяйте принуждение сразу:

```bash
$ findmnt --submounts /mnt/mydrive
$ sudo fuser -vm /mnt/mydrive
```

Выведите оболочки из дерева, корректно остановите ответственное приложение и размонтируйте дочерние монтирования до родительского. Ленивое и принудительное размонтирование имеют специализированную семантику, могут оставить активные ссылки или привести к потере данных; применяйте их только при документированном понимании восстановления.

:::single-choice{#mount-umount-busy-cause}
Какое условие может заставить `umount` сообщить, что файловая система занята?

::option[Имя каталога точки монтирования содержит строчные буквы.]{#mount-umount-lowercase explanation="Регистр пути сам по себе не создаёт активную ссылку файловой системы."}
::option[Текущий рабочий каталог процесса находится внутри монтирования.]{#mount-umount-cwd-busy .correct explanation="Процесс сохраняет ссылку внутрь смонтированной файловой системы, препятствуя обычному отсоединению."}
::option[UUID файловой системы длиннее имени устройства.]{#mount-umount-uuid-length explanation="Длина строки идентификатора не связана с проверками занятого состояния."}
:::

Используйте лабораторную работу [Управление разделами и файловыми системами Linux](https://labex.io/ru/labs/comptia-manage-linux-partitions-and-filesystems-590845), чтобы практиковаться на специально выделенном одноразовом хранилище.

## Итоги

Теперь вы можете подключать и отключать файловые системы с проверяемой областью действия.

1. Использовать пустую выделенную точку монтирования.
2. Проверять источник, тип, параметры и результат монтирования.
3. Предпочитать уникальный идентификатор файловой системы для постоянных ссылок.
4. Размонтировать по цели и подтверждать отсоединение до извлечения.
5. Исследовать активные ссылки вместо принудительного размонтирования занятой системы.
