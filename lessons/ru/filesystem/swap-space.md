Linux может перемещать выбранные страницы анонимной памяти между RAM и хранилищем swap. Это позволяет удерживать неактивную память, освобождая RAM для действующих нагрузок и кеша файловой системы, но хранилище намного медленнее RAM. Swap — инструмент ёмкости и управления памятью, а не замена достаточному объёму памяти или ограничению памяти приложения.

## Участие swap в управлении памятью

Ядро может использовать swap до полного исчерпания RAM в зависимости от нагрузки, давления памяти, cgroups и таких параметров, как swappiness. Чистые страницы с файловой поддержкой часто можно отбросить и перечитать из файлов, тогда как анонимным страницам нужен swap или место в RAM.

Интенсивный продолжительный обмен может вызвать огромную задержку или thrashing. Диагностируйте спрос на память, рабочие наборы, давление и ограничения приложений, а не считайте увеличение swap универсальным исправлением производительности.

:::single-choice{#swap-space-anonymous-pages}
Какая память является основным кандидатом для хранения в swap?

::option[Каждый исполняемый файл, установленный в `/usr`.]{#swap-space-installed-files explanation="Установленные файлы остаются в файловых системах; чистые отображённые страницы можно перечитать оттуда."}
::option[Неактивные страницы анонимной памяти.]{#swap-space-anonymous-memory .correct explanation="У анонимных страниц нет обычного файла-источника, из которого их можно просто перечитать."}
::option[Записи таблицы разделов диска.]{#swap-space-partition-table explanation="Метаданные разделов остаются на блочном устройстве и не являются памятью процесса, выгружаемой из RAM."}
:::

## Просмотр активного swap

Сначала используйте команды только для чтения:

```bash
$ swapon --show
$ cat /proc/swaps
$ free -h
```

Они показывают настроенный активный swap и агрегированные показатели памяти. Ненулевое значение «used» само по себе не проблема; сопоставляйте его с частотой ввода и вывода swap, давлением памяти, задержкой и поведением нагрузки.

:::single-choice{#swap-space-show-active}
Какая команда выводит активные области swap в структурированном виде?

::option[`swapon --show`]{#swap-space-swapon-show .correct explanation="Режим show сообщает активные файлы или устройства swap, их размер, использование и, где доступно, приоритет."}
::option[`mkswap --all`]{#swap-space-mkswap-all explanation="Mkswap инициализирует сигнатуры swap, а не выводит активные области только для чтения."}
::option[`mkfs -t swap`]{#swap-space-mkfs-swap explanation="Стандартный инструмент инициализации — `mkswap`, а форматирование не является запросом состояния."}
:::

## Инициализация и активация устройства swap

`mkswap` записывает сигнатуру swap и уничтожает прежние пригодные метаданные цели. Практикуйтесь только на проверенной одноразовой цели:

```bash
$ sudo mkswap /dev/VERIFIED-SWAP-TARGET
$ sudo swapon /dev/VERIFIED-SWAP-TARGET
```

До `mkswap` проверьте модель, серийный номер, размер, постоянную идентичность, существующие сигнатуры, монтирования, RAID, LVM, шифрование и резервные копии, как перед `mkfs`. После активации подтвердите точный источник через `swapon --show`.

Для постоянства используйте UUID swap в `/etc/fstab` с типом и параметрами локальной политики:

```text
UUID=VERIFIED-SWAP-UUID none swap sw 0 0
```

:::single-choice{#swap-space-enable-command}
Какая команда активирует инициализированную область swap?

::option[`swapon`]{#swap-space-command-swapon .correct explanation="Swapon добавляет корректное устройство или файл swap в активный набор ядра."}
::option[`mkswap`]{#swap-space-command-mkswap explanation="Mkswap инициализирует сигнатуру, но сам не активирует область."}
::option[`mount`]{#swap-space-command-mount explanation="Swap активируется подсистемой swap, а не монтируется как каталог файловой системы."}
:::

## Файлы swap и другие варианты хранения

Файл swap позволяет гибко добавить ёмкость без переразметки, но требования к созданию зависят от файловой системы. Файл должен иметь строгие разрешения, подходящее распределение без неподдерживаемых разреженных областей или поведения copy-on-write, сигнатуру swap и активацию. Следуйте документации файловой системы и дистрибутива вместо универсального рецепта с `fallocate`.

Сжатые RAM-устройства вроде zram могут предоставить другой уровень swap с иными компромиссами CPU и ёмкости. Зашифрованный swap защищает страницы в состоянии покоя, а гибернации нужны конфигурация возобновления и достаточно подходящего хранилища. Эти цели влияют на размер и проектирование.

Нет универсального правила, что swap должен вдвое превышать RAM. Определяйте размер по пикам нагрузки, желаемому поведению при отказе, потребностям гибернации, задержке и ресурсу хранилища, проектированию дампов сбоев и эксплуатационному мониторингу.

:::single-choice{#swap-space-sizing-rule}
На чём лучше всего основывать размер swap?

::option[Всегда ровно вдвое больше установленной RAM.]{#swap-space-twice-ram explanation="Эта историческая эвристика подходит не каждой нагрузке и современному объёму памяти."}
::option[На измеренных потребностях нагрузки, целях гибернации и политике отказов.]{#swap-space-sizing-requirements .correct explanation="Назначение системы и наблюдаемое поведение памяти важнее фиксированного множителя RAM."}
::option[Всегда ноль, если в системе есть SSD.]{#swap-space-zero-ssd explanation="Один тип хранилища не определяет требования давления памяти или гибернации."}
:::

## Безопасная деактивация swap

Деактивируйте конкретную проверенную область:

```bash
$ sudo swapoff /dev/VERIFIED-SWAP-TARGET
```

Ядро должно переместить находящиеся в ней страницы. Если RAM и оставшийся swap не вмещают их, операция может завершиться ошибкой или создать опасное давление памяти. Сначала остановите или ограничьте нагрузки, наблюдайте за памятью, удаляйте постоянную запись fstab только после проверки правильной цели и подтвердите деактивацию через `swapon --show` до смены назначения хранилища.

:::single-choice{#swap-space-swapoff-capacity}
Почему `swapoff` может завершиться ошибкой или подвергнуть опасности сильно нагруженную систему?

::option[Swapoff всегда форматирует каждый модуль RAM.]{#swap-space-formats-ram explanation="Он меняет конфигурацию активного swap и не форматирует физическую память."}
::option[Страницам из этой области нужна ёмкость в RAM или другом swap.]{#swap-space-pages-need-capacity .correct explanation="Для деактивации нужно переместить живые выгруженные страницы при продолжающейся работе системы."}
::option[Неактивная область swap должна оставаться смонтированной в `/swap`.]{#swap-space-mounted-path explanation="Области swap не являются файловыми системами, смонтированными в каталог."}
:::

Используйте лабораторную работу [Создание и активация файла swap в Linux](https://labex.io/ru/labs/comptia-create-and-activate-a-swap-file-in-linux-590858), чтобы в контролируемой среде отработать разрешения файла, активацию и постоянство.

## Итоги

Теперь вы можете считать swap явно управляемым ресурсом памяти.

1. Связывать swap прежде всего с анонимной памятью под давлением.
2. Проверять активный swap и поведение нагрузки до изменения ёмкости.
3. Инициализировать только проверенную одноразовую цель, затем активировать её через `swapon`.
4. Выбирать размер и защиту swap по требованиям нагрузки и гибернации.
5. Обеспечивать ёмкость для перемещения до применения `swapoff`.
