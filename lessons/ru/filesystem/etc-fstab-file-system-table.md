`/etc/fstab`, таблица файловых систем, объявляет файловые системы, области swap, bind-монтирования, сетевые источники и другие подключения, которые могут монтировать или активировать системные инструменты. Записи могут участвовать в загрузке, однако такие параметры, как `noauto`, интеграция автомонтирования и политика менеджера служб, влияют на время и сам факт подключения.

## Шесть полей

Обычная запись содержит шесть полей, разделённых пробелами:

```text
UUID=130b882f-7d79-436d-a096-1e594c92bb76 /data ext4 defaults,nosuid,nodev 0 2
```

1. **Источник**: путь устройства, `UUID=`, `LABEL=`, сетевой источник или другая поддерживаемая спецификация.
2. **Цель**: точка монтирования либо `none` для таких назначений, как swap.
3. **Тип**: тип файловой системы, `swap`, `none` или допустимый автоматический тип.
4. **Параметры**: разделённый запятыми список, интерпретируемый помощниками mount и уровнями интеграции.
5. **Поле dump**: исторически управляет программой резервирования `dump`; `0` обычно отключает участие.
6. **Поле pass**: управляет порядком `fsck` при загрузке, где это применимо; `0` отключает автоматическую проверку через этот механизм.

Пробел внутри поля нужно экранировать синтаксисом fstab, например `\040`. Символ `#` вне поля начинает комментарий.

## Стабильные идентификаторы источника

Для локальных файловых систем UUID часто стабильнее имени перечисления `/dev/sdX`:

```bash
$ lsblk -f
$ sudo blkid
```

Используйте `UUID=...` только после подтверждения, что идентификатор принадлежит нужной файловой системе. Переформатирование создаёт новый UUID, а поблочные клоны могут дублировать его. `PARTUUID=` вместо этого идентифицирует запись таблицы разделов и имеет другую семантику.

::option[Учётную запись пользователя — владельца точки монтирования.]{#fstab-user-uuid explanation="Идентичность учётной записи не выбирается синтаксисом UUID файловой системы."}
::option[Метаданные файловой системы с этим UUID.]{#fstab-filesystem-uuid .correct explanation="Mount находит по идентификатору доступное блочное устройство вместо зависимости от имени перечисления."}

## Параметры монтирования и поля проверки

`defaults` раскрывается в определяемый реализацией обычный набор параметров; это не обязательно самая безопасная политика для каждого монтирования. Добавляйте параметры по уровню доверия и нагрузке: например, доступ только для чтения или ограничения узлов устройств и поведения setuid. Для сетевых и съёмных систем может требоваться политика тайм-аутов, зависимостей или устойчивости к отказу, чтобы загрузка неожиданно не зависла.

Для файловых систем с поддержкой `fsck` корневая традиционно использует pass `1`, а остальные проверяемые локальные системы — pass `2`. Практика отдельных форматов различается: некоторые типы не используют общий fsck при загрузке. Следуйте документации установленной системы и дистрибутива, а не назначайте `2` механически.

:::single-choice{#fstab-pass-zero}
Что запрашивает значение `0` в шестом поле?

::option[Пропустить для этой записи автоматическое упорядочивание fsck через fstab.]{#fstab-pass-zero-skip .correct explanation="Нулевой pass исключает запись из управляемой этим полем последовательности проверки при загрузке."}
::option[Всегда монтировать файловую систему только для чтения.]{#fstab-pass-zero-readonly explanation="Режим только для чтения задаётся в поле параметров монтирования."}
::option[Стирать файловую систему перед каждой загрузкой.]{#fstab-pass-zero-erase explanation="Поле pass не форматирует и не стирает файловую систему."}
:::

## Редактирование с путём восстановления

Неверная запись корня, загрузочного или обязательного сетевого ресурса может прервать запуск. Перед редактированием:

1. Подтвердите актуальную резервную копию и доступ к консоли или среде восстановления.
2. Скопируйте существующий файл с сохранением разрешений.
3. Проверьте идентичность источника и создайте нужную точку монтирования.
4. Внесите одно ограниченное изменение.
5. Проверьте и протестируйте его до перезагрузки.

Не размещайте учётные данные прямо в общедоступной записи fstab. Используйте защищённый механизм учётных данных соответствующего помощника монтирования.

:::single-choice{#fstab-editing-recovery}
Почему до изменения критичной записи fstab нужно подтвердить аварийный доступ?

::option[Изменения fstab всегда немедленно стирают таблицу разделов.]{#fstab-no-partition-erase explanation="Само редактирование текста не переписывает разделы диска, хотя последующие монтирования могут иметь последствия."}
::option[Файл можно редактировать только из другой операционной системы.]{#fstab-other-os-only explanation="Его можно редактировать в Linux с нужными правами и мерами защиты."}
::option[Ошибочная запись может не позволить обычной загрузке достичь пригодной к работе системы.]{#fstab-boot-failure .correct explanation="Сбои критичных монтирований могут перевести систему в аварийный режим или заблокировать зависимые службы."}
:::

## Проверка без предположения об успехе

Начните со статической проверки, если она поддерживается:

```bash
$ sudo findmnt --verify --verbose
```

Затем в контролируемых условиях протестируйте конкретную новую запись, подтвердите её через `findmnt` и размонтируйте, если тест был временным. `mount -a` пытается подключить множество подходящих записей и может обратиться к сетям или присоединить непредусмотренные источники; он также пропускает уже смонтированные записи и `noauto`, поэтому не является ни безвредной проверкой синтаксиса, ни полным доказательством.

В системах на базе systemd после редактирования fstab перечитайте конфигурацию менеджера, чтобы обновились сгенерированные mount units, затем проверьте зависимости и поведение загрузки по локальной документации.

:::single-choice{#fstab-mount-a-limit}
Почему одного `mount -a` недостаточно для полной проверки fstab?

::option[Он всегда переформатирует каждое указанное устройство до монтирования.]{#fstab-mount-a-formats explanation="Mount обычно не создаёт файловые системы."}
::option[Он может пропустить записи и выполняет широкие реальные монтирования, а не только проверяет синтаксис.]{#fstab-mount-a-incomplete .correct explanation="Уже смонтированные записи и `noauto` могут не проверяться, а подходящие источники получают реальные эффекты."}
::option[Он читает только историю оболочки и игнорирует fstab.]{#fstab-mount-a-history explanation="Команда обращается к fstab за подходящими записями."}
:::
