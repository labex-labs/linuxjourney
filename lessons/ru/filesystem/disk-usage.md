У ёмкости файловой системы есть как минимум два ограничения: блоки данных и объекты метаданных, например inode. `df` сообщает распределение с точки зрения файловой системы, а `du` обходит достижимые пути и суммирует приписанное им использование. Значения отвечают на разные вопросы и не обязаны совпадать.

## Ёмкость файловой системы через `df`

Покажите тип смонтированной файловой системы и удобные для чтения показатели блоков:

```bash
$ df -hT
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/sda1      ext4  6.2G  2.3G  3.6G  40% /
```

`Size`, `Used` и `Avail` берутся из учёта файловой системы. Доступное место может быть меньше разности общего и использованного из-за зарезервированных блоков, метаданных, политики распределения, квот или округления. Запустите `df` с путём, чтобы получить файловую систему, содержащую его:

```bash
$ df -hT /var/log
```

## Ёмкость inode

Файловые системы, выделяющие inode-подобные объекты, могут исчерпать их при наличии свободных блоков:

```bash
$ df -i /var
```

Множество мелких файлов может занять все inode. Удаление одного большого файла освобождает много блоков, но обычно только один inode; удаление множества ненужных мелких файлов снижает давление inode. Некоторые файловые системы выделяют метаданные динамически и иначе отображают эти понятия.

:::single-choice{#disk-usage-inode-exhaustion}
Что может произойти, если в файловой системе есть свободные блоки, но нет свободных inode?

::option[Каждый существующий файл автоматически удвоится в размере.]{#disk-usage-inode-double explanation="Исчерпание inode препятствует выделению новых метаданных, но не увеличивает существующее содержимое."}
::option[Создать ещё один файл не удастся.]{#disk-usage-inode-create-fail .correct explanation="Новому объекту файловой системы нужны метаданные, даже если место для данных ещё есть."}

## Использование путей через `du`

Суммируйте выделенное пространство, достижимое под одним каталогом:

```bash
$ du -sh /var/log
```

Сравните непосредственных потомков, оставаясь в одной файловой системе:

```bash
$ sudo du -xhd1 /var | sort -h
```

Показанные параметры GNU означают удобный формат, максимальную глубину один и одну файловую систему. Разрешения могут скрыть поддеревья и дать неполную сумму. По умолчанию `du` также может учитывать файлы с жёсткими ссылками только один раз, различать видимый размер и выделенные блоки и по-разному обрабатывать разреженные файлы в зависимости от параметров.

:::single-choice{#disk-usage-du-purpose}
Какая команда суммирует выделенное использование под `/var/log`?

::option[`df -i /var/log`]{#disk-usage-df-inodes explanation="Она сообщает статистику inode содержащей файловой системы."}
::option[`du -sh /var/log`]{#disk-usage-du-summary .correct explanation="Du обходит указанное дерево, а `-s` выдаёт одну сумму в удобных единицах."}

## Почему `df` и `du` различаются

Распространённые причины:

- процесс удерживает удалённый файл открытым, поэтому его блоки остаются выделенными, но пути для `du` уже нет;
- метаданные файловой системы, зарезервированное место, журналы, reflink, снимки или сжатие влияют на учёт;
- внутри обходимого дерева смонтирована другая файловая система;
- разрешения не дают `du` прочитать некоторые каталоги;
- видимый и выделенный размеры разреженных файлов различаются.

Для удалённых, но открытых файлов проверьте авторизованные процессы инструментом вроде `lsof +L1`; перезапустите ответственную службу или отправьте ей сигнал обычным способом, не обрезая неизвестные дескрипторы.

:::single-choice{#disk-usage-deleted-open-file}
Почему `df` может показывать занятое место, которое основанный на путях `du` не находит?

::option[`df` всегда удваивает размер каждого файла.]{#disk-usage-df-doubles explanation="Универсального правила удвоения нет."}
::option[Удалённый файл может оставаться открытым и занимать блоки работающего процесса.]{#disk-usage-open-deleted .correct explanation="Записи каталога уже нет, но файловая система сохраняет блоки до закрытия последней открытой ссылки."}

## Исследование без усугубления инцидента

Начните с заполненной файловой системы из отчёта `df`, найдите её цель монтирования через `findmnt`, затем сужайте поиск `du` в пределах той же файловой системы. Учитывайте снимки, слои контейнеров, журналы, кеши пакетов и политику хранения приложений. Не удаляйте файлы лишь из-за большого размера; сначала определите владельца, резервирование, нормативные требования и поведение службы.

:::single-choice{#disk-usage-safe-investigation}
Как безопаснее всего поступить, найдя большой файл?

::option[Немедленно удалить его, пока служба продолжает запись.]{#disk-usage-delete-immediately explanation="Это может уничтожить нужные данные и не освободить место, если файл останется открытым."}
::option[Запустить `mkfs` на содержащем устройстве.]{#disk-usage-mkfs-device explanation="Форматирование уничтожит файловую систему вместо устранения роста одного файла."}
::option[Определить его владельца и роль в политике хранения до изменений.]{#disk-usage-review-large-file .correct explanation="Один размер не доказывает, что файл не нужен или его безопасно обрезать."}
:::

## Итоги

Теперь вы можете согласовывать отчёты о месте на уровне файловой системы и путей.

1. Использовать `df` для ёмкости блоков смонтированной файловой системы.
2. Использовать `df -i` для давления inode, где это поддерживается.
3. Выполнять ограниченные обходы `du`, чтобы приписывать использование достижимым путям.
4. Исследовать удалённые открытые файлы и особенности учёта конкретной файловой системы.
5. Применять правила владения и хранения до удаления данных.
