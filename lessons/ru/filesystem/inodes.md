В основанных на inode файловых системах Unix каталог сопоставляет имя каждой записи с номером inode. Inode представляет объект файловой системы и хранит метаданные, необходимые для поиска и интерпретации его данных. Поэтому путь не хранится как собственная основная идентичность объекта.

## Метаданные inode

Распространённые метаданные, связанные с inode:

- тип объекта и режим разрешений;
- владелец-пользователь и группа;
- логический размер и учёт выделенных блоков;
- количество жёстких ссылок;
- время доступа, изменения содержимого и изменения состояния;
- ссылки на данные файла или специфичные для файловой системы структуры экстентов.

Inode обычно не хранит имя записи каталога. Файловая система также может хранить расширенные атрибуты, списки контроля доступа, время рождения, встроенные данные и другую информацию через структуры конкретного формата.

`ctime` — время изменения состояния inode, а не обязательно время создания файла. Отдельная временная метка рождения или создания необязательна и может отсутствовать.

## Номера inode и область файловой системы

Покажите номера inode:

```bash
$ ls -li
```

Номер inode находится в первом поле. Подробно изучите один объект:

```bash
$ stat path
```

Номер inode уникален лишь внутри одной файловой системы в конкретный момент. Такой же номер может существовать в другой файловой системе, а после освобождения inode номер может использоваться повторно. Для надёжной идентификации объекта учитывайте и идентичность файловой системы, и номер inode.

:::single-choice{#inodes-number-scope} В какой области номер inode служит идентификатором объекта?

::option[Во всех системах Linux в мире навсегда.]{#inodes-global-forever explanation="Выделение inode локально для файловой системы, а идентификаторы могут переиспользоваться."}
::option[В одной файловой системе в конкретный момент.]{#inodes-one-filesystem .correct explanation="Другие файловые системы могут использовать тот же номер, а освобождённые номера позднее выделяются снова."}
::option[Только в процессе оболочки, создавшем файл.]{#inodes-shell-scope explanation="Идентичность inode поддерживает файловая система, а не одна оболочка."}
:::

## Жёсткие ссылки и открытые ссылки

Несколько записей каталогов могут ссылаться на один inode — это жёсткие ссылки. Создание ещё одной жёсткой ссылки увеличивает счётчик ссылок объекта. Удаление одного имени уменьшает счётчик, но не удаляет данные, пока остаётся другая ссылка.

Даже после удаления последней записи каталога открытый файл остаётся выделенным до закрытия последней ссылки процесса. Его счётчик ссылок может быть равен нулю, пока файловый дескриптор всё ещё обращается к нему. Поэтому удаление большого открытого журнала может не сразу уменьшить использование в `df`.

:::single-choice{#inodes-unlinked-open-file} Когда обычно освобождаются ресурсы файла, утратившего имена?

::option[Сразу после удаления любого одного имени жёсткой ссылки.]{#inodes-one-link-removed explanation="Другие жёсткие ссылки или открытые ссылки могут сохранять объект."}
::option[Только после полного переформатирования файловой системы.]{#inodes-reformat-only explanation="Обычные unlink и close освобождают неиспользуемые inode и блоки."}
::option[После обнуления счётчика ссылок и закрытия последней открытой ссылки.]{#inodes-zero-links-no-opens .correct explanation="Имена каталогов и файловые дескрипторы процессов являются независимыми ссылками на inode."}
:::

## Ёмкость inode

В файловых системах с конечным или отображаемым пулом inode миллионы мелких файлов могут исчерпать ёмкость метаданных раньше блоков данных. Проверьте учёт inode смонтированных систем:

```bash
$ df -i
```

Если свободных inode нет, создание файла может завершиться ошибкой, даже когда `df -h` показывает свободные блоки. Стратегии распределения различаются: одни файловые системы заранее создают структуры inode, другие динамически управляют метаданными и могут иначе сообщать ёмкость inode.

:::single-choice{#inodes-df-i-purpose} Что сообщает `df -i`, если файловая система предоставляет учёт inode?

::option[Содержимое каждого файла в порядке inode.]{#inodes-df-i-content explanation="Df сообщает агрегированную статистику файловой системы и не читает содержимое файлов."}
::option[Использованную и доступную ёмкость inode.]{#inodes-df-i-capacity .correct explanation="Представление inode помогает диагностировать исчерпание объектов метаданных отдельно от блоков данных."}
::option[Версию прошивки диска.]{#inodes-df-i-firmware explanation="Инвентаризация прошивки не связана с использованием inode."}
:::

## Зависимое от файловой системы отображение данных

Не считайте, что у каждого inode ровно 12 прямых указателей и три косвенных. Это полезное описание некоторых классических компоновок, но современная ext4 может использовать экстенты, а XFS, Btrfs и другие системы — иные структуры. Встроенные данные, сжатые экстенты и copy-on-write дополнительно меняют взаимосвязь.

Когда внутреннее отображение действительно важно, используйте специфичные для файловой системы диагностические средства только в режиме чтения или документированном режиме. Для обычного администрирования `stat`, `find -inum`, `df -i` и учитывающие ссылки инструменты предоставляют более безопасные абстракции.

:::single-choice{#inodes-layout-portability} Почему нельзя предполагать одну фиксированную компоновку указателей для каждого inode?

::option[Inode вообще никак не ссылаются на данные файлов.]{#inodes-no-data-reference explanation="Файловая система должна связывать объект с содержимым, хотя механизм различается."}
::option[Реализации файловых систем используют разные структуры экстентов, деревьев и встроенных данных.]{#inodes-format-specific-layout .correct explanation="Дисковое отображение inode на содержимое является частью формата каждой файловой системы."}
::option[Компоновку каждого inode отдельно выбирает владелец файла.]{#inodes-owner-layout explanation="Структуру метаданных определяют реализация и формат файловой системы."}
:::

Используйте лабораторную работу [Управление файлами и каталогами в Linux](https://labex.io/ru/labs/comptia-manage-files-and-directories-in-linux-590835), чтобы сравнить номера inode и счётчики ссылок на одноразовых файлах.
