Пользователь видит ошибку. Журнал сервиса может показать, на каком этапе возникла проблема с запросом. Начните со времени, затем поищите **идентификатор запроса** — метку, которую передают дальше и сохраняют в записях об одном запросе.

## Как читать записи об одном запросе

В примере ниже показаны два сервиса. **Зависимость** — это сервис, который нужен другой программе для завершения работы. Здесь веб-сервис запрашивает у сервиса каталога список товаров.

```text
09:14:02 service=web     request=r17 path=/items status=502
09:14:02 service=catalog request=r17 action=read result=timeout
09:14:03 service=catalog request=r18 action=read result=ok
```

Строка веб-сервиса показывает ошибку по запросу `r17`. Строка каталога с тем же идентификатором сообщает об истечении времени ожидания. Соседняя успешная запись каталога относится к `r18`.

:::single-choice{#service-logs-matching-request} Какой результат каталога соответствует ошибке веб-сервиса по запросу r17?

::option[Успешный результат по r18.]{#service-logs-matching-request-a explanation="Эта строка относится к другому запросу."}
::option[Оба результата каталога.]{#service-logs-matching-request-c explanation="Близкие метки времени могут относиться к разным запросам."}
::option[Истечение времени ожидания по r17.]{#service-logs-matching-request-b .correct explanation="Общий идентификатор связывает две записи об этом запросе."}
:::

## Как отфильтровать пример

Сохраните три строки выше как `requests.log` в каталоге для упражнений. Используйте `grep -F` для поиска буквального текста. Включите пробел после идентификатора, чтобы в этом примере поиск учитывал границу поля.

```bash
$ grep -F 'request=r17 ' requests.log
```

Должны появиться строки веб-сервиса и каталога по запросу `r17`. В реальных журналах формат может меняться, а идентификатор запроса иногда отсутствует. Убедитесь, что поля поиска обозначают одно и то же во всех сервисах.

:::single-choice{#service-logs-choose-filter} Зачем искать по всему полю запроса, если можно поискать слово timeout?

::option[Так мы гарантированно узнаем, что у всего трафика была одна ошибка.]{#service-logs-choose-filter-b explanation="Фильтр находит записи по одному запросу."}
::option[Так найдутся соответствующие записи веб-сервиса и каталога, хотя timeout есть только в одной.]{#service-logs-choose-filter-a .correct explanation="По общему идентификатору можно проследить запрос в обоих сервисах."}
::option[Это изменит журнал, чтобы следующие поиски выдавали правильный результат.]{#service-logs-choose-filter-c explanation="Grep читает файл и выводит подходящие строки."}
:::

## Что можно сообщить о сбое

Истечение времени ожидания указывает, на каком этапе этого запроса возникла ошибка. Из записи нельзя узнать, какой компонент каталога замедлился. Дальше проверьте метрики или свежие записи самой зависимости. Передавая коллеге фрагмент журнала, сохраните идентификатор запроса и удалите секреты и личные данные, которые ему не нужны.

:::single-choice{#service-logs-evidence-limit} Что указать в первом сообщении?

::option[По запросу r17 истекло время ожидания ответа каталога. Каталог нужно проверить подробнее.]{#service-logs-evidence-limit-c .correct explanation="Это передаёт смысл связанных записей без предположений о причине."}
::option[Все запросы к каталогу завершились по истечении времени ожидания.]{#service-logs-evidence-limit-a explanation="В выборке есть отдельный успешный запрос к каталогу."}
::option[Отказал конкретный диск сервера базы данных.]{#service-logs-evidence-limit-b explanation="В записях нет сведений о дисках."}
:::
