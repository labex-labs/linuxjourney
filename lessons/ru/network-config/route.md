Маршруты, заданные вручную, изменяют выбор исходящего интерфейса и следующего перехода ядром. Ошибка может отключить хост от сети или перенаправить конфиденциальный трафик, поэтому перед изменением состояния проверьте действующий маршрут, владельца конфигурации и путь восстановления.

## Проверка текущего решения

Запишите относящиеся к задаче маршруты и запросите у ядра текущий путь к адресу назначения:

```bash
$ ip -4 route show
$ ip route get 192.168.2.25
```

Если используются политики маршрутизации и дополнительные таблицы, проверьте и их. Поиск маршрута служит локальным свидетельством и не отправляет трафик.

:::single-choice{#route-get-before-change} Зачем выполнять `ip route get DESTINATION` перед изменением маршрута?

::option[Команда фиксирует текущее локальное решение для сравнения и отката.]{#route-get-baseline .correct explanation="Выбранные интерфейс, следующий переход и адрес источника помогают точно определить требуемое изменение."}
::option[Команда навсегда резервирует адрес назначения на каждом маршрутизаторе.]{#route-get-reserves explanation="Она выполняет локальный поиск и не изменяет удалённое состояние."}
::option[Команда отключает все правила политик маршрутизации.]{#route-get-disables-policy explanation="Поиск учитывает политики, а не удаляет их."}
:::

## Добавление или замена маршрута

Добавьте маршрут к каноническому префиксу через доступный следующий переход:

```bash
$ sudo ip route add 192.168.2.0/23 via 10.11.12.3 dev enp1s0
```

Шлюз должен быть доступен через соответствующий канал либо в соответствии с явной корректной схемой on-link. Команда `add` завершается ошибкой, если эквивалентный маршрут уже существует. Команда `replace` создаёт или изменяет маршрут, что удобно для идемпотентной настройки, но может перезаписать рабочее состояние; сначала точно проверьте цель.

:::single-choice{#route-add-existing} Что обычно происходит, если `ip route add` указывает на уже существующий маршрут?

::option[Команда без предупреждения удаляет старый префикс назначения.]{#route-add-deletes explanation="Обычно add сообщает об уже существующем объекте, а не заменяет его."}
::option[Команда завершается ошибкой вместо замены существующего маршрута.]{#route-add-fails .correct explanation="Используйте replace осознанно и только после проверки изменяемой записи."}
::option[Команда перезагружает выбранный шлюз.]{#route-add-reboots explanation="Локальная настройка маршрута не может таким способом запросить перезагрузку удалённого узла."}
:::

## Точное удаление

Если возможны несколько подходящих записей или таблиц, при удалении указывайте точные атрибуты маршрута:

```bash
$ sudo ip route del 192.168.2.0/23 via 10.11.12.3 dev enp1s0
```

Удаление только по адресу назначения может охватить больше записей, чем задумано, или оказаться неоднозначным. До удаления сохраните исходную команду, с помощью которой можно восстановить маршрут.

:::single-choice{#route-delete-precision} Зачем при удалении маршрута указывать следующий переход и устройство?

::option[Чтобы точнее определить нужную запись.]{#route-delete-exact .correct explanation="Явные атрибуты снижают риск удаления другого маршрута с тем же префиксом."}
::option[Чтобы одновременно удалить физический сетевой адаптер.]{#route-delete-adapter explanation="Удаление маршрута не удаляет объект канала из ядра."}
::option[Чтобы стереть DNS-зону адреса назначения.]{#route-delete-dns explanation="Маршрутизация и авторитетные данные DNS — разные системы."}
:::

## Постоянная конфигурация и безопасность удалённой работы

Команда `ip route` изменяет только текущее состояние ядра. NetworkManager, systemd-networkd, netplan, ifupdown, DHCP, демоны маршрутизации или система оркестрации могут позднее заменить его. Сохраняйте маршрут у активного владельца конфигурации лишь после проверки текущего поведения.

При работе с удалённым хостом сохраните независимый доступ к консоли и используйте откат, который не зависит от изменяемого маршрута. Затем проверьте поиск маршрута, состояние соседей, движение трафика в обоих направлениях и настоящую службу.

:::single-choice{#route-runtime-persistence} Что может произойти с маршрутом, добавленным вручную, после перезагрузки диспетчера сети?

::option[Он навсегда станет неизменяемой функцией ядра.]{#route-manual-immutable explanation="Маршруты текущего состояния могут быть удалены или заменены."}
::option[Он автоматически появится на каждом хосте подсети.]{#route-manual-all-hosts explanation="Команда изменяет только текущее сетевое пространство имён."}
::option[Он может исчезнуть, если отсутствует в постоянной политике.]{#route-manual-disappears .correct explanation="Диспетчер приводит состояние ядра в соответствие со своими настроенными профилями."}
:::

## Итоги

Теперь вы можете вносить ограниченные изменения маршрутов Linux с возможностью восстановления.

1. Сохраняйте текущие маршруты, правила и результат фактического поиска.
2. Используйте канонический префикс и доступный следующий переход.
3. Отличайте добавление от намеренной замены.
4. Удаляйте точный маршрут и сохраняйте команду восстановления.
5. Записывайте постоянную настройку через активный диспетчер и проверяйте оба направления.
