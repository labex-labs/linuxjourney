`dhclient` — клиент ISC DHCP, встречающийся в некоторых системах Linux. Во многих современных установках собственный клиент DHCP запускает NetworkManager, systemd-networkd или другая служба. Запуск второго клиента на управляемом интерфейсе может привести к конкуренции адресов, маршрутов, параметров DNS и состояния аренды.

## Определение активного клиента

Перед запуском `dhclient` проверьте владельца конфигурации и процессы:

```bash
$ nmcli device status
$ networkctl status
$ ps -ef | grep '[d]hclient'
```

Используйте те инструменты, которые есть на хосте. Если интерфейсом управляет диспетчер, запрашивайте DHCP через него, а не запускайте отдельный клиент.

:::single-choice{#dhclient-second-client-risk}
Почему не следует запускать `dhclient` на уже управляемом интерфейсе?

::option[DHCP может назначать только адреса обратной петли.]{#dhclient-loopback-only explanation="DHCP обычно назначает сетевую конфигурацию не для обратной петли."}
::option[Два клиента могут конкурировать за адреса, маршруты, DNS и аренды.]{#dhclient-competing-state .correct explanation="Обычно согласовывать состояние интерфейса должен только установленный владелец конфигурации."}
::option[Каждый запрос DHCP форматирует локальный диск.]{#dhclient-reformats explanation="Протокол изменяет состояние сети, а не формат диска."}
:::

## Явный запрос аренды

Если `dhclient` должен управлять неуправляемым тестовым интерфейсом, явно укажите интерфейс и включите подробный вывод:

```bash
$ sudo dhclient -v enp1s0
```

Запуск без интерфейса может затронуть несколько подходящих интерфейсов. Пути к конфигурации и арендам зависят от пакета и способа запуска; часто встречаются имена `dhclient.conf` и `dhclient.leases`, но не полагайтесь на единственное фиксированное расположение.

:::single-choice{#dhclient-interface-operand}
Зачем указывать `enp1s0` в ручном запросе?

::option[Чтобы воздействовать только на нужный сетевой интерфейс.]{#dhclient-scope-interface .correct explanation="Запуск клиента без уточнения может охватить больше интерфейсов, чем задумано."}
::option[Чтобы выбрать TCP-порт 1 для DHCP.]{#dhclient-tcp-port explanation="DHCP использует UDP, а имя интерфейса не является портом."}
::option[Чтобы сделать аренду постоянной.]{#dhclient-permanent explanation="Конфигурация DHCP остаётся ограниченным по времени состоянием аренды."}
:::

## Освобождение аренды

`dhclient -r INTERFACE` запрашивает освобождение аренды и может удалить рабочую конфигурацию. Это нарушающее работу действие, причём доступность сервера для получения запроса освобождения не гарантируется. Не освобождайте аренду только ради её просмотра, особенно на пути удалённого управления.

:::single-choice{#dhclient-release-effect}
В чём эксплуатационный риск команды `dhclient -r enp1s0`?

::option[Она лишь выводит текущую аренду без изменений.]{#dhclient-release-readonly explanation="Освобождение изменяет состояние."}
::option[Она продлевает все аренды на неограниченный срок.]{#dhclient-release-renews explanation="Освобождение и продление — противоположные операции."}
::option[Она может удалить текущее подключение, полученное по DHCP.]{#dhclient-release-connectivity .correct explanation="При освобождении состояние аренды прекращается, поэтому удалённый доступ может оборваться."}
:::

## Проверка применённой аренды

После контролируемого запроса проверьте не только адрес:

```bash
$ ip address show dev enp1s0
$ ip route show
$ resolvectl status
```

Изучите журналы диспетчера или клиента и срок аренды, затем проверьте требуемое разрешение имён и приложение. DHCPACK может содержать неверные параметры, а успешное назначение адреса не доказывает доступность шлюза или DNS.

:::single-choice{#dhclient-verify-state}
Что следует проверить после получения аренды?

::option[Адрес, маршруты, DNS, аренду и поведение приложения.]{#dhclient-complete-verify .correct explanation="Аренда настраивает несколько связанных компонентов, которые должны работать совместно."}
::option[Только появление строки с адресом.]{#dhclient-address-only explanation="Маршруты, DNS, срок действия и сквозная работа всё ещё могут быть неверны."}
::option[Только фон рабочего стола.]{#dhclient-wallpaper explanation="Внешний вид рабочего стола не связан с состоянием DHCP."}
:::

## Итоги

Теперь вы умеете использовать `dhclient` только тогда, когда именно он должен управлять интерфейсом.

1. Определяйте активный диспетчер сети и клиент DHCP.
2. Не допускайте конкуренции клиентов на одном интерфейсе.
3. Ограничивайте ручной запрос именованным тестовым интерфейсом.
4. Считайте освобождение аренды нарушающим работу действием и проверяйте полный результат аренды.
