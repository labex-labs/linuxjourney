Проверка целостности показывает, соответствует ли файл эталону. Проверяйте содержимое и метаданные отдельно. Содержимое — это байты внутри файла. К **метаданным** относятся, например, права доступа.

## Как записать хеш содержимого

Создайте небольшой файл конфигурации в пустой папке для упражнений. Перенаправление перезапишет существующий файл с таким именем, поэтому используйте новую папку.

```bash
$ printf '%s\n' 'mode=preview' > site.conf
$ sha256sum site.conf
```

Первое поле — **хеш**, значение фиксированной длины, вычисленное по байтам файла. Позже примените тот же способ к тому же файлу. Изменение хеша указывает, что на вход поступили другие байты.

:::single-choice{#host-file-integrity-changed-hash} Значение SHA-256 изменилось после редактирования файла. Что показывает сравнение?

::option[Содержимое отличается от байтов, по которым считали хеш раньше.]{#host-file-integrity-changed-hash-a .correct explanation="Хеш меняется вместе с содержимым, по которому его вычисляют."}
::option[Изменение точно было несанкционированным.]{#host-file-integrity-changed-hash-b explanation="Наличие разрешения проверяют отдельно."}
::option[Права учётной записи точно изменились.]{#host-file-integrity-changed-hash-c explanation="В хеше содержимого не записаны права доступа."}
:::

## Как записать права доступа

В Linux команда `stat -c` выводит выбранные метаданные. Поле `%a` выводит права в числовом виде, а `%n` — имя файла.

```bash
$ stat -c '%a %n' site.conf
```

Начальные права могут зависеть от способа создания файла. Запишите их вместе с хешем содержимого, чтобы позже сравнить оба свойства.

:::single-choice{#host-file-integrity-mode-vs-content} Хеш совпал с эталоном, а stat показывает другой режим доступа. Что изменилось по результатам проверок?

::option[Байты файла изменились, а режим доступа остался прежним.]{#host-file-integrity-mode-vs-content-a explanation="Хеш совпал, а режим доступа отличается."}
::option[Файл точно удалили.]{#host-file-integrity-mode-vs-content-c explanation="Обе проверки вернули сведения о файле."}
::option[Права доступа изменились, а наблюдаемый хеш содержимого остался прежним.]{#host-file-integrity-mode-vs-content-b .correct explanation="Эти два инструмента измеряют разные свойства."}
:::

## Как проверить изменение прав

Следующая команда меняет права на этот учебный файл на `640`. Владелец сможет читать и изменять файл, а группа — читать. Снова выполните обе проверки и сравните результаты.

```bash
$ chmod 640 site.conf
$ stat -c '%a %n' site.conf
$ sha256sum site.conf
```

Режим доступа должен быть 640, а хеш содержимого должен совпасть с первым измерением.

:::single-choice{#host-file-integrity-repeat-check} Какая проверка обнаружит последующее изменение строки mode=preview внутри файла?

::option[Только имя файла из вывода stat.]{#host-file-integrity-repeat-check-a explanation="После редактирования имя может остаться тем же."}
::option[Повторный расчёт SHA-256 и сравнение с исходным хешем.]{#host-file-integrity-repeat-check-c .correct explanation="Изменение содержимого приведёт к другому хешу."}
::option[Только число, обозначающее права владельца.]{#host-file-integrity-repeat-check-b explanation="Права доступа обычно не зависят от правок содержимого."}
:::
