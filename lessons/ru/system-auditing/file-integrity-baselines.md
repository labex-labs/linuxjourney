**Эталон** — это доверенная запись об ожидаемых свойствах файлов на известный момент времени. При следующей проверке целостности можно сравнить текущие файлы с эталоном и получить список различий.

## Как читать отчёт о различиях

Этот учебный фрагмент сравнивает хост с его последним утверждённым состоянием.

```text
File                      Property  Previous  Current
/etc/journey/site.conf    content   hash-A    hash-B
/etc/journey/banner.txt   mode      644       640
/etc/journey/site.prev    present   yes       no
```

Первая строка показывает изменение содержимого файла. Вторая — изменение прав доступа. Третья сообщает, что ранее отслеживаемый файл отсутствовал на момент проверки.

:::single-choice{#file-integrity-baselines-report-mode} Какая строка сообщает об изменении прав доступа?

::option[Строка site.conf.]{#file-integrity-baselines-report-mode-a explanation="Она сообщает об изменении хеша содержимого."}
::option[Строка banner.txt.]{#file-integrity-baselines-report-mode-b .correct explanation="Режим доступа изменился с 644 на 640."}
::option[Строка site.prev.]{#file-integrity-baselines-report-mode-c explanation="Она показывает, существовал ли файл по указанному пути."}
:::

## Проверка эталона

Отчёт полезен, если прежнему эталону можно доверять. Сохраните идентификатор эталона и дату его создания. Если копию сделали, когда проблема уже существовала, сравнение может ввести в заблуждение. Уточните, какое утверждённое состояние представляет эталон.

:::single-choice{#file-integrity-baselines-reference-source} Какой эталон лучше всего подходит для проверки сегодняшней конфигурации?

::option[Зарегистрированная и утверждённая копия, сделанная до изменения.]{#file-integrity-baselines-reference-source-a .correct explanation="Она даёт известную точку сравнения, которую можно проверить."}
::option[Эталон из сегодняшних файлов с необъяснёнными изменениями.]{#file-integrity-baselines-reference-source-b explanation="Так различия попадут в эталон прежде, чем их проверят."}
::option[Настройки другого хоста без сведений о сопоставимости.]{#file-integrity-baselines-reference-source-c explanation="Разные роли хостов могут требовать разных файлов и прав."}
:::

## Проверка перед обновлением эталона

Сопоставьте каждое различие с согласованным изменением и проверьте, как работает сервис. Если изменение прав баннера запланировано, а изменение конфигурации не запланировано, изучите их по отдельности. Обновляйте эталон после того, как разрешённые различия объяснены и утверждены. Сохраните сведения о прежнем эталоне.

:::single-choice{#file-integrity-baselines-update-timing} Изменение прав баннера согласовано, а изменение site.conf пока не объяснено. Что сделать перед принятием нового эталона?

::option[Одобрить всё, потому что одна строка соответствует ожиданиям.]{#file-integrity-baselines-update-timing-a explanation="Различия в файлах относятся к разным изменениям."}
::option[Удалить отчёт о различиях.]{#file-integrity-baselines-update-timing-b explanation="В отчёте указано, что ещё предстоит проверить."}
::option[Исследовать необъяснённое изменение site.conf.]{#file-integrity-baselines-update-timing-c .correct explanation="Новый эталон утверждают после проверки текущего состояния."}
:::

Чтобы создать эталон и сравнить с ним файлы в учебной среде, пройдите урок [Мониторинг целостности файлов](https://labex.io/tutorials/linux-file-integrity-monitoring-fim-656122).

## Итоги

Теперь вы можете использовать эталон для конкретной проверки.

1. Различать в отчёте содержимое, права доступа и наличие файла.
2. Проверять, отражает ли эталон доверенное состояние.
3. Разбирать неожиданные различия до утверждения нового эталона.
