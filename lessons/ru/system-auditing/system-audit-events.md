Журнал сервиса может сообщить, что страница загрузилась. **Запись аудита** может описать действие, которое система настроена отслеживать, например запись в файл конфигурации сервиса. Сначала определите, какое действие важно и какие сведения нужны для его проверки.

## Как поставить вопрос для аудита

Предположим, конфигурация веб-сервиса определяет, кому доступен предварительный просмотр. Нужно проверять изменения этого файла. В полезной записи будут указаны объект, операция, время, сведения об учётной записи и результат. Каждое поле помогает восстановить свою часть события.

:::single-choice{#system-audit-events-choose-object} Что должна указывать запись аудита для этой проверки?

::option[Только число веб-запросов за день.]{#system-audit-events-choose-object-b explanation="Объём запросов описывает другую активность."}
::option[Файл конфигурации, к которому обращались.]{#system-audit-events-choose-object-a .correct explanation="По объекту можно отличить это изменение от записей в другие файлы."}
::option[Только тип операции, например запись.]{#system-audit-events-choose-object-c explanation="Операция показывает, что пытались сделать. По целевому файлу можно определить, относится ли действие к проверке."}
:::

## Как читать результат

Запись аудита может описывать успешную запись в файл или неудачную попытку. Учитывайте и операцию, и её результат. Отказ в записи полезен как подтверждение попытки. Из него следует другой вывод, чем из успешной записи.

:::single-choice{#system-audit-events-operation-result} В журнале указана запись в файл конфигурации и результат «отказано». Что это показывает?

::option[Зафиксированная попытка записи была отклонена.]{#system-audit-events-operation-result-b .correct explanation="Операция и результат вместе описывают то, что наблюдалось."}
::option[Файл точно заменили.]{#system-audit-events-operation-result-a explanation="Отказ не подтверждает успешного изменения."}
::option[Ожидаемая страница вернула HTTP 200.]{#system-audit-events-operation-result-c explanation="Здесь не описан запрос страницы."}
:::

## Как проверить охват аудита

Система аудита сохраняет только те события, которые охватывают её механизмы и правила. Прежде чем делать вывод по пустому результату поиска, проверьте, охватывали ли правила нужный путь, операции и время. Запишите, какой источник вы просмотрели.

:::single-choice{#system-audit-events-empty-audit} В выбранном журнале нет записи об операции записи в файл. Что проверить, прежде чем заключить, что таких операций не было?

::option[Посчитать установленные редакторы.]{#system-audit-events-empty-audit-a explanation="Список программ ничего не говорит об охвате аудита."}
::option[Поискать в том же интервале только по имени другой учётной записи.]{#system-audit-events-empty-audit-b explanation="Дополнительный поиск полезен, если уже известно, что сбор данных работал. Сначала выясните, могли ли нужные события вообще попасть в журнал."}
::option[Проверить правила аудита и доступный период.]{#system-audit-events-empty-audit-c .correct explanation="При неполном охвате записи могут отсутствовать даже при наличии активности."}
:::

## Итоги

Теперь вы можете выбирать данные аудита для проверки защищённого ресурса.

1. Определять, какую операцию и какой объект нужно проверить.
2. Читать результат вместе с тем, какое действие пытались выполнить.
3. Проверять охват аудита, прежде чем опираться на пустой результат поиска.
