Псевдоним предписывает интерактивной оболочке заменить одно командное слово другой строкой до выполнения. Так можно сократить частую команду или задать предпочитаемые параметры.

## Создание псевдонима в текущей оболочке

В Bash используется форма `alias NAME='REPLACEMENT'` без пробелов вокруг знака равенства:

```bash
$ alias ll='ls -la'
```

После определения `ll` раскрывается в `ls -la`. Кавычки сохраняют замену с пробелом единым значением при определении.

Псевдонимы подходят для простых замен префикса команды. Для структурированной обработки аргументов лучше функция оболочки.

:::single-choice{#define-ll-alias} Какая команда Bash определяет в текущей оболочке `ll` как псевдоним `ls -la`?

::option[`alias ll = 'ls -la'`]{#alias-spaces explanation="Пробелы вокруг `=` разбивают определение на слова, и Bash не получает допустимое присваивание."}
::option[`alias ll='ls -la'`]{#alias-ll .correct explanation="Здесь использована форма `NAME=REPLACEMENT`, а замена с пробелом заключена в кавычки."}
::option[`unalias ll='ls -la'`]{#unalias-definition explanation="`unalias` удаляет имена псевдонимов и не создаёт замену."}
:::

## Загрузка в будущих сеансах Bash

Псевдоним из приглашения принадлежит текущей оболочке и исчезает после выхода. Интерактивные нелогиновые сеансы Bash обычно читают `~/.bashrc`, поэтому туда помещают личные определения:

```bash
alias ll='ls -la'
```

После правки откройте новый интерактивный Bash или перечитайте файл:

```bash
$ source ~/.bashrc
```

Запуск зависит от оболочки, режима входа и дистрибутива. Например, Zsh обычно использует собственную конфигурацию, а не `.bashrc`.

:::single-choice{#persist-bash-alias} Где обычно определить личный псевдоним для загрузки будущими интерактивными нелогиновыми сеансами Bash?

::option[В пользовательском файле `~/.bashrc`.]{#bashrc-alias .correct explanation="Интерактивный нелогиновый Bash обычно читает `~/.bashrc`, поэтому это традиционное место личных псевдонимов."}
::option[В исполняемом файле программы псевдонима.]{#edit-executable explanation="Изменение установленной программы не связано с раскрытием псевдонима и может повредить управляемые файлы."}
::option[В истории прокрутки текущего терминала.]{#terminal-scrollback explanation="Прокрутка хранит показанный текст и не выполняется Bash как конфигурация запуска."}
:::

## Проверка псевдонимов и разрешения имён

`alias` без аргументов перечисляет псевдонимы текущей оболочки:

```bash
$ alias
alias ll='ls -la'
alias grep='grep --color=auto'
```

`type NAME` показывает разрешение конкретного имени:

```bash
$ type ll
ll is aliased to 'ls -la'
```

:::single-choice{#inspect-command-alias} Какая команда показывает, разрешает ли Bash `ll` как псевдоним, функцию, встроенную команду или файл?

::option[`file ll`]{#file-ll explanation="`file` классифицирует путь, а псевдоним хранится в состоянии оболочки и не обязан иметь файл `ll`."}
::option[`type ll`]{#type-ll .correct explanation="Встроенная `type` сообщает, как текущий Bash разрешает имя `ll`."}
::option[`whatis ll`]{#whatis-ll explanation="`whatis` обращается к описаниям man-страниц, а личные псевдонимы обычно не имеют записей."}
:::

## Обход и удаление псевдонима

Для одного вызова поставьте перед именем обратную косую черту или передайте его встроенной `command`:

```bash
$ \ls
$ command ls
```

Это запускает обычное разрешение нижележащей команды. Делайте псевдонимы короткими и предсказуемыми и не скрывайте разрушительное поведение за знакомыми именами.

:::single-choice{#bypass-ls-alias} В Bash есть псевдоним `ls`. Какая команда обходит его для одного вызова?

::option[`alias ls`]{#show-ls-alias explanation="Она печатает определение псевдонима и не запускает нижележащую команду."}
::option[`command ls`]{#command-ls .correct explanation="Поскольку командным словом является `command`, последующая `ls` не раскрывается как псевдоним и проходит обычное разрешение."}
::option[`source ls`]{#source-ls explanation="`source` читает файл как код текущей оболочки и не является безопасным способом обхода псевдонима."}
:::

Удалите псевдоним из текущей оболочки:

```bash
$ unalias ll
```

Если определение осталось в `~/.bashrc`, будущая оболочка создаст его снова. Для постоянного удаления измените и конфигурационную строку.

:::single-choice{#remove-current-alias} Какая команда удаляет `ll` из текущего сеанса Bash?

::option[`unalias ll`]{#unalias-ll .correct explanation="`unalias` удаляет имя из таблицы псевдонимов текущей оболочки."}
::option[`alias ll=''`]{#empty-ll explanation="Она заменяет псевдоним пустым раскрытием, а не удаляет определение."}
::option[`command ll`]{#command-ll explanation="`command` может обойти раскрытие на строке, но не удаляет псевдоним из состояния оболочки."}
:::
