Команда `rm` удаляет записи файловой системы. Обычно удаление из командной строки не перемещает объекты в корзину, а у `rm` нет встроенной отмены, поэтому проверяйте каждую цель до запуска.

Базовый синтаксис:

```bash
rm [OPTIONS] FILE...
```

## Удаление файлов

Передайте `rm` один или несколько путей:

```bash
$ rm file1
```

```bash
$ rm notes.txt old-report.txt draft.md
```

До Enter проверьте написание и расположение. Резервная копия или система контроля версий надёжнее попыток восстановления после удаления.

:::single-choice{#remove-one-file} Какая команда после проверки цели удаляет `old-report.txt`?

::option[`rm old-report.txt`]{#rm-report .correct explanation="`rm` удаляет указанную запись; обычно она не попадает в корзину."}
::option[`rmdir old-report.txt`]{#rmdir-report explanation="`rmdir` работает с пустыми каталогами, а не обычными файлами."}
::option[`mv old-report.txt`]{#mv-report explanation="`mv` требует назначения и меняет путь вместо удаления; неполная команда не выполнит задачу."}
:::

## Предварительный просмотр шаблона

Оболочка может раскрыть шаблон в несколько аргументов. Например, `*.tmp` выбирает совпавшие нескрытые имена текущего каталога:

```bash
$ rm *.tmp
```

Перед удалением просмотрите тот же шаблон без кавычек через `ls`:

```bash
$ ls *.tmp
cache.tmp  test.tmp
$ rm *.tmp
```

Оболочка раскрывает шаблон до запуска `rm`. При неожиданном совпадении исправьте шаблон и не продолжайте.

:::single-choice{#preview-removal-pattern} Какая команда без удаления показывает нескрытые пути, выбранные шаблоном `*.tmp`?

::option[`rm -v *.tmp`]{#verbose-remove explanation="Подробный режим сообщает об удалениях во время их выполнения и не является просмотром."}
::option[`ls '*.tmp'`]{#quoted-pattern explanation="Кавычки запрещают раскрытие, поэтому ищется буквальное имя со `*`."}
::option[`ls *.tmp`]{#list-temp-matches .correct explanation="Оболочка раскрывает `*.tmp` для `ls`, позволяя проверить тот же набор до удаления."}
:::

## Запрос подтверждения

Параметр `-i` спрашивает перед каждым удалением:

```bash
$ rm -i important.txt
rm: remove regular file 'important.txt'? y
```

GNU `rm -I` запрашивает один раз, если удаляется больше трёх файлов или операция рекурсивна.

:::single-choice{#confirm-each-removal} Какая команда спрашивает подтверждение перед удалением каждого файла?

::option[`rm -i important.txt`]{#interactive-important .correct explanation="Параметр `-i` задаёт вопрос перед каждым удалением, позволяя отказаться."}
::option[`rm -f important.txt`]{#force-important explanation="`-f` подавляет вопросы и игнорирует отсутствующий аргумент, а не добавляет подтверждение."}
::option[`rm -v important.txt`]{#verbose-important explanation="`-v` сообщает о выполненном удалении, но не спрашивает заранее."}
:::

## Игнорирование отсутствующих файлов через -f

Параметр `-f` игнорирует отсутствующие аргументы и подавляет вопросы:

```bash
$ rm -f old-cache.txt
```

Это делает очистку в сценариях идемпотентной, если созданный файл уже может отсутствовать. Но не добавляйте `-f` лишь для подавления непонятной ошибки.

## Удаление каталогов

Обычная `rm` каталог не удаляет:

```bash
$ rm projects
rm: cannot remove 'projects': Is a directory
```

Используйте `-r` или `-R` только для намеренного удаления всего дерева:

```bash
$ rm -r old-project
```

Для пустого каталога есть более узкая команда `rmdir`:

```bash
$ rmdir empty-directory
```

Она завершается ошибкой для непустого каталога, защищая содержимое от рекурсивного удаления.

:::single-choice{#remove-empty-directory-only} Какая команда удаляет `old-cache/` только при его пустоте?

::option[`rm -r old-cache/`]{#recursive-cache explanation="Рекурсивная `rm` удаляет каталог вместе с содержимым и не требует пустоты."}
::option[`rmdir old-cache/`]{#rmdir-cache .correct explanation="`rmdir` успешна только для пустого каталога и не удаляет файлы рекурсивно."}
::option[`rm -f old-cache/`]{#force-cache explanation="`-f` не заставляет обычную `rm` удалить каталог и подавляет защиту вместо проверки пустоты."}
:::

## Проверка рекурсивного удаления

Рекурсия может стереть целое дерево, а сочетание `-r` с `-f` в `rm -rf` убирает вопросы. Перед ней проверьте:

- Текущий ли это каталог? Выполните `pwd`.
- Показывает ли `ls -ld -- TARGET` нужный верхний путь?
- Если есть шаблон, совпал ли просмотр без изменений с ожиданием?
- Абсолютный путь или относительный? `/tmp/cache` и `tmp/cache` различаются.
- Нет ли случайного пробела? `rm -rf old-project` и `rm -rf old project` имеют разные цели.

Перед целью, начинающейся с дефиса, используйте `--`, чтобы она не стала параметром:

```bash
$ rm -- -old-name
```

Не используйте `sudo` просто из-за ошибки разрешений. Сначала проверьте цель и причину запрета изменения содержащего каталога. Рекурсивное удаление с повышенными правами может повредить ОС или чужие данные.

Параметр `-v` сообщает об успешных удалениях:

```bash
$ rm -rv old-project
removed 'old-project/notes.txt'
removed directory 'old-project'
```

:::single-choice{#remove-nonempty-tree} Какая команда после полной проверки удаляет `old-project/` со всем содержимым, сохраняя обычные запросы?

::option[`rm old-project/`]{#plain-rm-project explanation="Обычная `rm` не спускается в каталог и не удаляет непустое дерево."}
::option[`rm -r old-project/`]{#recursive-old-project .correct explanation="`-r` рекурсивно удаляет дерево, но в отличие от `-rf` не добавляет подавляющий вопросы `-f`."}
::option[`rmdir old-project/`]{#rmdir-project explanation="`rmdir` требует пустого каталога и завершится ошибкой при наличии записей."}
:::

## Итоги

Теперь вы умеете удалять записи файловой системы, считая каждую цель необратимой.

1. Проверять пути файлов до удаления.
2. Просматривать раскрытие шаблона командой только для чтения.
3. Запрашивать подтверждение через `-i` или `-I`.
4. Предпочитать `rmdir`, когда каталог обязан быть пустым.
5. Полностью проверять цель перед рекурсивным удалением.
