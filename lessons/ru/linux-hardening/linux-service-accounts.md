Веб-сервер запускается как процесс. Linux связывает каждый процесс с учётной записью, от которой зависит, что программа может читать и изменять. **Служебная учётная запись** выделяется для работы программы.

## Как определить учётную запись процесса

В обычном терминале `$$` подставляет идентификатор процесса командной оболочки. Используйте его, чтобы узнать, от чьего имени работает ваша оболочка. Параметр `-p` выбирает этот процесс, а `-o` задаёт столбцы вывода. Знаки равенства убирают заголовки столбцов.

```bash
$ ps -p "$$" -o user=,comm=
```

В терминале LabEx учётной записью может быть `labex`. В столбце команды показана программа командной оболочки. Те же поля для процесса сервиса покажут, от какой записи он работает, независимо от того, кто его запустил.

:::single-choice{#linux-service-accounts-process-user} Какое поле указывает учётную запись выбранного процесса?

::option[Идентификатор процесса, заданный с помощью -p.]{#linux-service-accounts-process-user-a explanation="Идентификатор позволяет выбрать один запущенный процесс."}
::option[Имя команды в последнем столбце.]{#linux-service-accounts-process-user-c explanation="Оно обозначает запущенную программу."}
::option[Поле пользователя в выводе ps.]{#linux-service-accounts-process-user-b .correct explanation="В нём указано, от чьего имени работает процесс."}
:::

## Как выбрать отдельную учётную запись

Рассмотрим веб-сервис, которому нужно лишь читать страницы и писать собственный журнал. Для этого можно выдать подходящие права отдельной учётной записи `site-web`. Запуск с широкими правами администратора позволил бы программе изменить больше, чем ей нужно для работы.

:::single-choice{#linux-service-accounts-isolate-service} Какой набор прав подходит для этого сервиса?

::option[Разрешить site-web изменять файлы всех пользователей.]{#linux-service-accounts-isolate-service-b explanation="Ни одна задача сервиса не требует такого доступа."}
::option[Разрешить site-web читать страницы и писать в собственный журнал.]{#linux-service-accounts-isolate-service-a .correct explanation="Эти права покрывают две указанные задачи."}
::option[Разрешить site-web выполнять каждый запрос с правами администратора.]{#linux-service-accounts-isolate-service-c explanation="Для большинства запросов достаточно ограниченных прав самого сервиса."}
:::

## Как проверить сервис с несколькими процессами

Некоторые сервисы используют разные процессы для разных задач. Чтобы определить применимые права, проверяйте именно процесс, обрабатывающий запрос. Если вы меняете учётную запись процесса, убедитесь, что сервис по-прежнему может читать входные данные и записывать только то, что ему необходимо.

:::single-choice{#linux-service-accounts-verify-identity} Инструмент обслуживания показал, что управляющий процесс работает от root. Как узнать, от чьего имени обрабатываются веб-запросы?

::option[Проверить учётную запись процесса, который обрабатывает запросы.]{#linux-service-accounts-verify-identity-c .correct explanation="Проверка нужного процесса связывает учётную запись с выполняемой работой."}
::option[Посмотреть только имя файла конфигурации сервиса.]{#linux-service-accounts-verify-identity-a explanation="По имени файла нельзя узнать, от чьего имени работает обработчик."}
::option[Посмотреть имя человека, открывшего терминал.]{#linux-service-accounts-verify-identity-b explanation="Пользователь терминала и учётная запись сервиса могут различаться."}
:::
