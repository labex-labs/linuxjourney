Обновление безопасности может исправить дефект в установленной программе. Сначала выясните, какая версия установлена и какое исправление доступно для вашей операционной системы. Планируйте изменение с учётом сервиса, которым пользуются люди.

## Как посмотреть доступные обновления

На учебном хосте Ubuntu следующая команда выводит пакеты, для которых APT видит обновления. Она ничего не меняет и использует сведения о пакетах, уже имеющиеся на хосте.

```bash
$ apt list --upgradable
```

Для пакета из списка в доступных данных имеется более новая версия. В уведомлении о безопасности вашего дистрибутива проверьте, входит ли нужное исправление в это обновление. Пустой список может означать, что сведения устарели.

:::single-choice{#linux-security-updates-candidate-is-listed} Пакет появился в списке. Что это означает?

::option[Обновление уже установлено.]{#linux-security-updates-candidate-is-listed-a explanation="Список показывает доступную версию для обновления."}
::option[APT видит более новую версию установленного пакета.]{#linux-security-updates-candidate-is-listed-b .correct explanation="Именно это сейчас показывают локальные сведения о пакетах."}
::option[Всякая более новая версия — обновление безопасности.]{#linux-security-updates-candidate-is-listed-c explanation="Причину выпуска обновления можно узнать из уведомления дистрибутива."}
:::

## Как спланировать изменение

В согласованном плане укажите сервис, целевую версию и период обслуживания. Чтобы некоторые обновления вступили в силу, нужно перезапустить сервис или перезагрузить машину. До изменений на хосте спланируйте проверочный запрос и способ восстановления.

:::single-choice{#linux-security-updates-reboot-check} Обновление пакета исправляет код, используемый давно запущенным сервисом. Что проверить после установки?

::option[Нужно ли перезапустить сервис, чтобы он начал использовать обновлённый код.]{#linux-security-updates-reboot-check-a .correct explanation="Работающий процесс может всё ещё использовать загруженный старый код."}
::option[Было ли обновление в списке доступных до установки.]{#linux-security-updates-reboot-check-b explanation="Доступность помогает спланировать обслуживание, но не определяет версию, загруженную процессом."}
::option[Остались ли в списке пакеты для обновления.]{#linux-security-updates-reboot-check-c explanation="Даже если все пакеты обновлены, процесс может ещё не загрузить обновлённый код."}
:::

## Как проверить результат

Убедитесь, что установлена утверждённая версия. Проверьте сервис тем путём, которым обычно пользуются клиенты, и запишите результат. Если исправление касается работающего компонента, убедитесь также, что используется именно обновлённая версия.

:::single-choice{#linux-security-updates-security-verification} Какие два результата лучше всего подтверждают завершение обновления сервиса?

::option[Команда вывода списка выполнилась дважды.]{#linux-security-updates-security-verification-a explanation="Повторный вывод списка ничего не говорит о работе сервиса."}
::option[В заявке на обслуживание изменился заголовок.]{#linux-security-updates-security-verification-b explanation="Заголовок не даёт сведений о запущенном сервисе."}
::option[Утверждённая версия используется, и типичный запрос проходит.]{#linux-security-updates-security-verification-c .correct explanation="Так проверяется и версия программы, и работа сервиса для пользователей."}
:::

## Как сопоставить два источника сведений о версии

Установленный пакет и программа, отвечающая на запросы, могут временно иметь разные версии. Например, в перечне пакетов уже указана исправленная версия, а процесс, запущенный до обновления, продолжает работать. Для завершения проверки нужны сведения о запущенном процессе.

:::single-choice{#linux-security-updates-final-application} Какой вопрос остаётся открытым, если установленная версия уже исправлена, а прежний процесс всё ещё существует?

::option[Нужно ли заменить все остальные процессы на машине.]{#linux-security-updates-final-application-c explanation="Вопрос касается обновлённого сервиса и согласованных требований к его обслуживанию."}
::option[Обслуживает ли запросы обновлённая программа.]{#linux-security-updates-final-application-a .correct explanation="Перечень пакетов подтверждает версию установленных файлов, а проверка процесса — версию работающего сервиса."}
::option[Был ли вообще доступен пакет с обновлением.]{#linux-security-updates-final-application-b explanation="Установленный пакет уже сообщает об исправленной версии."}
:::

## Итоги

Теперь вы можете проверить обновление от выбора версии до подтверждения результата.

1. Различать доступные обновления и установленные изменения.
2. Учитывать перезапуск и восстановление в плане.
3. Проверять запущенную версию и ожидаемое поведение сервиса.
