Браузеру нужно убедиться, что он подключился к сайту из URL. **Сертификат** TLS содержит сведения о том, кому он выдан, и открытый ключ. Прежде чем доверять этой информации, браузер проверяет несколько свойств сертификата.

## Как проверить имена

Откройте страницу с [открытым учебным сертификатом](https://github.com/labex-labs/linuxjourney/blob/master/examples/web-security/site-cert.pem) на GitHub и сохраните файл как `site-cert.pem`. Это самоподписанный сертификат для упражнения. С помощью OpenSSL выведите издателя, срок действия и альтернативные имена субъекта. Параметр `-noout` отключает вывод сертификата в закодированном виде.

```bash
$ openssl x509 -in site-cert.pem -noout -issuer -dates -ext subjectAltName
```

Раздел **альтернативных имён субъекта** перечисляет имена DNS, на которые распространяется учебный сертификат. Найдите `DNS:site.example`. Браузер сверяет имя из URL с именами в сертификате.

:::single-choice{#web-certificates-wrong-name} Указано только имя site.example. Какой URL ему соответствует?

::option[`https://site.example/`.]{#web-certificates-wrong-name-b .correct explanation="Имя DNS в сертификате совпадает с именем хоста в URL."}
::option[`https://other.example/`.]{#web-certificates-wrong-name-a explanation="В учебном сертификате указано другое имя."}
::option[`https://preview.site.example/`.]{#web-certificates-wrong-name-c explanation="Поддомен — отдельное имя. Оно должно входить в область действия сертификата."}
:::

## Как проверить срок действия

Поля `notBefore` и `notAfter` задают период действия сертификата. Сравните их со временем проверки. Неверно настроенные часы тоже могут повлиять на результат. Одних дат для проверки сертификата недостаточно.

:::single-choice{#web-certificates-validity-period} Текущее время позже notAfter. Что выяснить?

::option[Указано ли в сертификате нужное имя DNS.]{#web-certificates-validity-period-b explanation="Совпадение имени важно для проверки подлинности сервера. Даже при совпадении сертификат с истёкшим сроком остаётся просроченным."}
::option[Изменился ли пароль одного пользователя.]{#web-certificates-validity-period-c explanation="Вход в приложение — отдельная проверка, не связанная со сроком действия сертификата."}
::option[Истёк ли срок действия сертификата и нужно ли его обновить.]{#web-certificates-validity-period-a .correct explanation="Сервер предъявляет сертификат за пределами указанного срока действия."}
:::

## Как проверить доверие

**Издатель** — тот, кто подписал сертификат. Браузеры обычно проверяют подписи по цепочке, ведущей к доверенному центру сертификации. В выводе OpenSSL можно прочитать поле с именем издателя. Проверку цепочки выполняют отдельно. Учебный сертификат может быть предназначен только для лаборатории.

:::single-choice{#web-certificates-trust-check} Имя и даты подходят, но браузер не доверяет тому, кто подписал сертификат. Чего не хватает?

::option[Второй копии даты сертификата.]{#web-certificates-trust-check-a explanation="Совпадение дат не подтверждает, кто удостоверил подлинность сервера."}
::option[Действительной цепочки до доверенного центра сертификации для этого соединения.]{#web-certificates-trust-check-c .correct explanation="Браузеру нужно доверять цепочке, а имя и срок действия должны пройти свои проверки."}
::option[Другого имени пользователя на сайте.]{#web-certificates-trust-check-b explanation="Решение о доверии принимается до обычной аутентификации в приложении."}
:::

## Итоги

Теперь вы можете проверить три важных свойства сертификата.

1. Сверить имя хоста из URL с именами в сертификате.
2. Сравнить текущее время со сроком действия сертификата.
3. Отдельно проверить доверие к цепочке.
