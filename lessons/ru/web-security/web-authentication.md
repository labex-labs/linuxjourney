**Аутентификация** проверяет, действительно ли пользователь тот, за кого себя выдаёт. Форма входа может запросить имя учётной записи и пароль. Имя указывает, в какую запись человек пытается войти. Пароль служит подтверждением, которое сервис может проверить.

## Как определить заявленную учётную запись

Представьте, что пользователь вводит имя учётной записи `alex`. Ввести его может любой, кто знает имя. Сервис сверяет предъявленное подтверждение с данными и правилами для этой записи.

:::single-choice{#web-authentication-username-claim} Что указывает, в какую учётную запись пользователь пытается войти?

::option[Результат проверки пароля.]{#web-authentication-username-claim-a explanation="Результат помогает подтвердить или отклонить попытку входа."}
::option[Имя учётной записи.]{#web-authentication-username-claim-b .correct explanation="По нему сервис определяет, чью подлинность проверять."}
::option[Формат ответа главной страницы.]{#web-authentication-username-claim-c explanation="Тип содержимого не связан с учётной записью для входа."}
:::

## Как различать факторы аутентификации

**Фактор** — это категория подтверждения. Пароль относится к тому, что пользователь знает. Зарегистрированный ключ безопасности подтверждает владение предметом. Пароль и отдельный зарегистрированный ключ дают подтверждения двух разных видов.

:::single-choice{#web-authentication-independent-factors} Какой пример сочетает знание и владение?

::option[Пароль и зарегистрированный ключ безопасности.]{#web-authentication-independent-factors-a .correct explanation="В одном случае проверяют знание, в другом — наличие ключа."}
::option[Пароль и второй пароль, который пользователь запомнил.]{#web-authentication-independent-factors-b explanation="Оба относятся к тому, что пользователь знает."}
::option[Имя пользователя и заголовок страницы.]{#web-authentication-independent-factors-c explanation="Такие обозначения почти ничего не подтверждают о подлинности пользователя."}
:::

## Что означает успешный вход

Проверив подтверждение, сервис может открыть сеанс. Успешная аутентификация определяет, какая учётная запись считается вошедшей. Чтобы выяснить, какие действия ей доступны, сервис применяет правила доступа к каждому запрошенному ресурсу.

:::single-choice{#web-authentication-auth-limit} Пользователь успешно вошёл и запрашивает страницу администратора. Что должно произойти дальше?

::option[Страница должна автоматически открыться для любой вошедшей учётной записи.]{#web-authentication-auth-limit-a explanation="Для этой страницы по-прежнему нужно отдельное право."}
::option[Доступ должен определяться исходным заголовком страницы.]{#web-authentication-auth-limit-b explanation="Заголовок страницы не определяет права пользователя."}
::option[Приложение должно проверить право учётной записи на доступ к ресурсу.]{#web-authentication-auth-limit-c .correct explanation="Аутентификация и проверка доступа к ресурсу отвечают на разные вопросы."}
:::

## Итоги

Теперь вы можете объяснить, что подтверждает решение об аутентификации.

1. Различать имя, под которым выполняется вход, и подтверждение подлинности.
2. Распознавать разные виды факторов аутентификации.
3. Проверять доступ к конкретным ресурсам по правилам авторизации сервиса.
