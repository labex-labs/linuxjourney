Веб-сервер может сохранять в **журнале доступа** по записи на каждый запрос. В журнал могут входить время, путь, код ответа и идентификатор запроса. Используйте только те поля, которые нужны для вашего вопроса.

## Как читать результат запроса

В этом учебном фрагменте у полей есть имена. Два запроса отправлены по разным путям.

```text
t=09:18:01Z request=r31 method=GET path=/health status=200
t=09:18:04Z request=r32 method=GET path=/staff status=403
```

Код `403` означает, что сервис отказал в выполнении запроса. Прежде чем сопоставлять ответ с другой записью, проверьте точный путь и идентификатор запроса.

:::single-choice{#web-access-logs-log-result} Какой запрос нужно проследить, чтобы разобраться в отказе?

::option[r31 по пути /health.]{#web-access-logs-log-result-a explanation="Эта строка сообщает об успешной проверке состояния."}
::option[r32 по пути /staff.]{#web-access-logs-log-result-b .correct explanation="У него статус 403. Именно по этому запросу получен отказ."}
::option[Оба запроса как один.]{#web-access-logs-log-result-c explanation="Идентификаторы и пути позволяют различить запросы."}
:::

## Как найти решение о доступе

В журнале доступа указано, что вернул сервер. Причины решения о доступе там может не быть. Если приложение отдельно записывает решения об авторизации, сопоставьте идентификатор запроса и время. Так можно узнать, какое правило применилось в этом примере.

:::single-choice{#web-access-logs-refusal-reason} В журнале доступа указан код 403. Какая дополнительная запись лучше всего объяснит причину?

::option[Решение приложения о правах доступа для r32.]{#web-access-logs-refusal-reason-a .correct explanation="Подходящая запись может назвать применённое правило."}
::option[Успешный ответ с другого сайта.]{#web-access-logs-refusal-reason-b explanation="Этот ответ не связан с отказом."}
::option[Более ранний запрос по пути проверки состояния.]{#web-access-logs-refusal-reason-c explanation="В этой записи другая операция и другой результат."}
:::

## Какие данные оставлять за пределами журнала

Избегайте записи значений, которые позволяют воспользоваться чужим сеансом, например полного значения cookie сеанса или токена авторизации. Для диагностики пригодятся идентификатор запроса и статус ответа. Передавая пример журнала, удалите чувствительные поля и оставьте только сведения, нужные для проверки.

:::single-choice{#web-access-logs-safe-fields} Какие два поля помогут проследить отказ без копирования данных для входа?

::option[Полное значение cookie сеанса и пароль учётной записи.]{#web-access-logs-safe-fields-a explanation="Оба значения конфиденциальны и не должны попадать в общие журналы."}
::option[Токен авторизации и общедоступный путь.]{#web-access-logs-safe-fields-b explanation="Путь может пригодиться, а токен даёт доступ и должен оставаться закрытым."}
::option[Идентификатор запроса и статус ответа.]{#web-access-logs-safe-fields-c .correct explanation="Эти поля позволяют сопоставлять записи без раскрытия значения сеанса."}
:::

## Как передать небольшой фрагмент

Представьте, что коллеге нужны сведения об отклонённом запросе. Сохраните время, идентификатор, метод, путь без конфиденциальных данных и статус, если этих полей достаточно. В строке запроса некоторых путей могут встречаться личные или секретные значения. Проверьте фрагмент перед передачей.

:::single-choice{#web-access-logs-final-application} Какой фрагмент лучше всего подойдёт для проверки?

::option[Весь запрос со всеми заголовками по умолчанию.]{#web-access-logs-final-application-b explanation="Запросы могут содержать данные для входа или лишние личные сведения."}
::option[Только код ответа с удалением всех идентификаторов.]{#web-access-logs-final-application-c explanation="Один код бывает трудно сопоставить с записью о применённом правиле."}
::option[Путь без чувствительных данных, время и идентификатор запроса, статус ответа.]{#web-access-logs-final-application-a .correct explanation="Так сохраняются поля для сопоставления записей и не раскрываются значения сеанса."}
:::

## Итоги

Теперь вы можете читать простой журнал доступа и безопасно сохранять нужные сведения.

1. Сопоставить идентификатор запроса, путь и ответ.
2. Найти связанную запись о проверке прав, когда важна причина.
3. Исключать данные для входа из записываемых и передаваемых журналов.
