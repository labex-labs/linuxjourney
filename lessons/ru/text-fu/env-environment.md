У каждого процесса есть окружение — набор строк вида «имя — значение», унаследованный от родительского процесса. Оболочки используют переменные окружения, чтобы передавать запускаемым программам настройки вроде языка и путей поиска исполняемых файлов.

## Раскрытие значений переменных в Bash

Перед запуском команды Bash заменяет `$NAME` или `${NAME}` значением переменной. Заключайте подстановку в кавычки, чтобы сохранить значение как один аргумент:

```bash
$ printf '%s\n' "$HOME"
/home/pete
```

К распространённым переменным окружения относятся:

- `HOME`: путь к домашнему каталогу текущего пользователя.
- `USER`: имя пользователя, предоставляемое средой входа во многих системах.
- `PWD`: текущий рабочий каталог оболочки.
- `PATH`: каталоги, в которых выполняется поиск команд.

Значения зависят от окружения текущего процесса и не являются универсальными константами. Неустановленная переменная раскрывается в пустую строку, если не включено более строгое поведение оболочки.

## Проверка текущего окружения

Запустите `env` без операндов, чтобы вывести окружение, унаследованное процессом `env`:

```bash
$ env
```

Вывод содержит записи `NAME=value`, например:

```plaintext
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/bin
PWD=/home/user
USER=pete
```

Переменные окружения могут содержать учётные данные, токены, внутренние пути и другую конфиденциальную информацию. Не публикуйте полный вывод `env` в открытых задачах или журналах, не проверив и не скрыв такие данные.

## Поиск команд через PATH

`PATH` — разделённый двоеточиями список каталогов, в которых Bash ищет команду, если её имя не содержит косой черты:

```bash
$ printf '%s\n' "$PATH"
```

Порядок важен: Bash использует первую подходящую команду согласно своим правилам разрешения имён. Чтобы проверить, как текущая оболочка разрешает имя, выполните `type -a NAME`.

Чтобы добавить `/opt/coolapp/bin` для текущей оболочки и её будущих дочерних процессов, сохранив существующий путь поиска:

```bash
$ export PATH="/opt/coolapp/bin:$PATH"
```

Не заменяйте `PATH` случайно единственным новым каталогом и не добавляйте каталоги, доступные для записи ненадёжным пользователям. Первая ошибка может помешать находить обычные команды, а вторая — привести к запуску неожиданного исполняемого файла.

:::single-choice{#env-prepend-path-directory}
Какая команда добавляет `/opt/coolapp/bin` перед существующим `PATH` для текущего процесса Bash и его будущих дочерних процессов?

::option[`export PATH="/opt/coolapp/bin"`]{#env-replace-path explanation="Эта команда удаляет все существующие каталоги поиска, из-за чего обычные команды может стать трудно найти."}
::option[`export PATH="/opt/coolapp/bin:$PATH"`]{#env-export-path .correct explanation="Команда добавляет новый каталог в начало, сохраняет прежнее значение и экспортирует результат для дочерних процессов."}
::option[`PATH='$PATH:/opt/coolapp/bin'`]{#env-literal-path explanation="Одинарные кавычки сохраняют буквальный текст `$PATH`, а присваивание не экспортируется будущим дочерним процессам."}
:::

## Экспорт переменной в дочерние процессы

Переменные Bash не включаются автоматически в окружение дочерних процессов. Пометьте имя для экспорта командой `export`:

```bash
$ export TEST=test
```

Теперь текущий процесс Bash содержит переменную `TEST`, а запускаемые им команды наследуют `TEST=test`. Дочерний процесс не может с помощью этого механизма изменить окружение родителя.

```bash
$ printenv TEST
test
```

Обычно присваивание действует, пока вы не удалите переменную или не завершите оболочку. Оно не изменяет общесистемное окружение.

## Значение для одной команды

Поместите присваивания перед командой, чтобы предоставить значения только окружению этой команды:

```bash
$ LANG=C sort names.txt
```

Значение `LANG` в текущей оболочке не изменяется навсегда. Утилита `env` предоставляет другую явную форму:

```bash
$ env LANG=C sort names.txt
```

Используйте `env -i COMMAND`, чтобы запустить команду с изначально пустым окружением, а затем добавьте необходимые присваивания. Многие программы зависят от значений окружения, поэтому применяйте этот параметр осознанно.

:::single-choice{#env-one-command-value}
Какая команда запускает `sort names.txt` с `LANG=C`, не изменяя `LANG` текущей оболочки навсегда?

::option[`env LANG=C sort names.txt`]{#env-lang-sort .correct explanation="`env` добавляет присваивание в окружение запускаемой команды, а родительская оболочка сохраняет прежнее значение."}
::option[`export LANG=C; sort names.txt`]{#env-export-lang explanation="Эта запись экспортирует `LANG=C` в текущей оболочке и оставляет значение изменённым после завершения `sort`."}
::option[`env -i sort names.txt`]{#env-empty-sort explanation="Команда запускается с пустым окружением, но требуемое значение `LANG=C` не задаётся."}
:::

## Загрузка личных значений в будущих сеансах

Чтобы воссоздавать экспортированную переменную в будущих интерактивных сеансах Bash, добавьте подходящую строку `export` в файл запуска, который действительно читают эти сеансы; для интерактивного Bash без входа это обычно `~/.bashrc`:

```bash
export TEST=test
```

Zsh обычно использует `~/.zshrc`, а Fish — другой синтаксис и конфигурацию. Оболочки входа и неинтерактивные оболочки могут читать другие файлы, поэтому определяйте тип оболочки и сеанса, а не считайте, что один файл настраивает каждый процесс.

## Итоги

Теперь вы можете проверять и управлять окружением, которое Bash передаёт дочерним процессам.

1. Раскрывайте значения переменных с осознанным использованием кавычек.
2. Проверяйте экспортированные значения, не раскрывая секреты.
3. Сохраняйте и правильно упорядочивайте каталоги команд в `PATH`.
4. Экспортируйте переменную оболочки для будущих дочерних процессов.
5. Переопределяйте значение для одной команды, не изменяя родительскую оболочку.
