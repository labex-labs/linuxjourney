Команда `cut` выбирает указанные позиции символов или поля из каждой входной строки. Она лучше всего подходит для текста с устойчивой структурой, известными разделителями и позициями полей.

Создайте небольшой файл с полями, разделёнными табуляцией. `printf` интерпретирует `\t` как символ табуляции, а `\n` — как перевод строки:

```bash
$ printf 'name\trole\nalice\tadmin\nbob\tviewer\n' > team.tsv
```

## Выбор позиций символов

Используйте `-c LIST`, чтобы выбрать позиции в каждой строке. Нумерация начинается с 1:

```bash
$ cut -c 1 team.tsv
n
a
b
```

Список может содержать отдельные позиции и диапазоны:

```bash
$ cut -c 1-4 team.tsv
name
alic
bob
$ cut -c 1,3 team.tsv
nm
ai
bb
```

Пробелы, табуляции и знаки препинания тоже занимают позиции. `cut` обрабатывает каждую строку независимо.

:::single-choice{#cut-first-character} Какая команда выводит первый символ каждой строки `names.txt`?

::option[`cut -c 1 names.txt`]{#cut-character-one .correct explanation="Параметр `-c` выбирает позиции символов, а позиция 1 — первый символ каждой строки."}
::option[`cut -f 1 names.txt`]{#cut-field-one explanation="Параметр `-f` выбирает первое поле, разделённое табуляцией; оно может содержать больше одного символа."}
::option[`cut -d 1 names.txt`]{#cut-delimiter-one explanation="Параметр `-d` задаёт разделитель полей и должен сочетаться с выбором поля. Он не выбирает позицию символа."}
:::

## Выбор полей, разделённых табуляцией

Используйте `-f LIST` для выбора полей. По умолчанию разделителем является табуляция:

```bash
$ cut -f 2 team.tsv
role
admin
viewer
```

Как и при выборе символов, список может содержать значения вроде `1`, `1,3`, `2-4`, `-3` или `2-`.

:::single-choice{#cut-second-tab-field} Какая команда выводит второе поле каждой строки `team.tsv`, разделённое табуляцией?

::option[`cut -c 2 team.tsv`]{#cut-second-character explanation="Эта команда выбирает вторую позицию символа каждой строки, а не второе поле."}
::option[`cut -f 2 team.tsv`]{#cut-second-field .correct explanation="Без `-d` режим полей использует табуляцию, а `-f 2` выбирает второе поле."}
::option[`cut -d 2 team.tsv`]{#cut-delimiter-two explanation="Эта команда пытается использовать `2` как разделитель, но не задаёт список полей. Поле 2 она не выбирает."}
:::

## Выбор собственного разделителя

Используйте `-d CHARACTER` вместе с `-f`, если поля разделены не табуляцией. В следующем примере создаются данные с точкой с запятой:

```bash
$ printf 'alice;admin\nbob;viewer\n' > team.txt
$ cut -d ';' -f 1 team.txt
alice
bob
```

В этой форме разделитель состоит из одного символа. Заключите `;` в кавычки, поскольку без кавычек точка с запятой имеет управляющее значение для оболочки.

:::single-choice{#cut-semicolon-role-field} Какая команда выводит второе поле `team.txt`, разделённое точкой с запятой?

::option[`cut -d ':' -f 2 team.txt`]{#cut-colon-second explanation="Эта команда выбирает поля, разделённые двоеточиями, но в файле используются точки с запятой."}
::option[`cut -d ';' -f 2 team.txt`]{#cut-semicolon-second .correct explanation="Точка с запятой в кавычках задаёт разделитель, а `-f 2` выбирает второе поле каждой строки."}
::option[`cut -c 2 -f ';' team.txt`]{#cut-mixed-options explanation="Здесь выбор символов смешан с недопустимым аргументом поля. Разделитель указывается после `-d`, а номер поля — после `-f`."}
:::

## Обработка строк без разделителя

В режиме полей `cut` обычно выводит строку без изменений, если в ней нет разделителя. Добавьте `-s`, чтобы подавить такие строки:

```bash
$ printf 'alice;admin\nheader\nbob;viewer\n' | cut -s -d ';' -f 2
admin
viewer
```

Это не обеспечивает проверку произвольного CSV-файла. CSV может содержать разделители в кавычках, встроенные переводы строк и правила экранирования, которых простое разбиение по одному символу не понимает; для таких данных используйте инструмент с поддержкой CSV.

:::single-choice{#cut-suppress-undelimited} Что делает `-s` в `cut -d ':' -f 1`?

::option[Сортирует выбранные поля перед выводом.]{#cut-s-sort explanation="`cut` не сортирует ввод, а `-s` не связан с порядком."}
::option[Считает последовательные разделители одним.]{#cut-s-squeeze explanation="`cut` не использует `-s` для свёртывания разделителей. Пустые поля сохраняют значение как позиции."}
::option[Подавляет строки, не содержащие выбранного разделителя.]{#cut-s-suppress .correct explanation="В режиме полей `-s` не позволяет строкам без разделителя проходить без изменений."}
:::

## Чтение из stdin

Если файл не указан либо в качестве входного операнда используется `-`, `cut` читает stdin. Поэтому команда естественно работает как этап конвейера:

```bash
$ printf 'red:1\nblue:2\n' | cut -d ':' -f 1
red
blue
```

:::single-choice{#cut-pipeline-input} Откуда `cut` читает ввод в `generate-data | cut -d ':' -f 1`?

::option[Из stdout команды `generate-data` через конвейер.]{#cut-pipe-stdin .correct explanation="Конвейер подключает stdout производителя к stdin команды `cut`, а отдельный входной файл не указан."}
::option[Из файла с буквальным именем `generate-data`.]{#cut-pipe-file explanation="`generate-data` выполняется как левая команда конвейера и не передаётся `cut` как имя файла."}
::option[Из стандартного потока ошибок команды `cut`.]{#cut-pipe-stderr explanation="Обычный конвейер подаёт в стандартный ввод stdout предыдущей команды, а не stderr команды `cut`."}
:::
