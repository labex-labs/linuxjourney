Команды `join` и `split` решают разные задачи обработки файлов. `join` объединяет связанные записи двух отсортированных текстовых источников, а `split` делит один источник на последовательность меньших файлов.

## Объединение двух файлов по первому полю

По умолчанию `join` сравнивает первые поля, разделённые пробельными символами, ровно в двух входных файлах. Рассмотрим уже отсортированные файлы.

`people.txt`:

```text
1 John
2 Jane
3 Mary
```

`surnames.txt`:

```text
1 Doe
2 Doe
3 Sue
```

Объединим записи с одинаковыми ключевыми полями:

```bash
$ join people.txt surnames.txt
1 John Doe
2 Jane Doe
3 Mary Sue
```

Вывод содержит общий ключ один раз, а затем остальные поля первого и второго файлов. `join` обрабатывает два файла за раз и не принимает три обычных файловых операнда как трёхстороннее реляционное объединение.

Какие записи объединяет `join first.txt second.txt` без параметров полей?

::option[Строки с одинаковыми первыми полями, разделёнными пробелами.]{#join-first-fields .correct explanation="По умолчанию `join` сравнивает поле 1 каждого из двух отсортированных источников."}
::option[Строки с одинаковым физическим номером.]{#join-line-numbers explanation="Сопоставление выполняется по значениям ключевых полей, а не просто по позициям записей."}

:::

## Сортировка ключей объединения

Каждый входной файл должен быть упорядочен по своему полю объединения с совместимыми правилами сравнения. Для стандартного поля 1 подготовьте копии командой `sort -k 1,1`:

```bash
$ LC_ALL=C sort -k 1,1 people-raw.txt > people.txt
$ LC_ALL=C sort -k 1,1 surnames-raw.txt > surnames.txt
$ LC_ALL=C join people.txt surnames.txt
```

Одинаковая локаль сортировки и объединения обеспечивает согласованные правила сопоставления. Не перенаправляйте результат `sort` обратно в тот же входной путь: оболочка сначала усечёт файл.

::option[Имена обоих файлов должны находиться рядом при алфавитной сортировке.]{#join-filename-order explanation="Сортировать нужно ключи содержимого; лексическая связь между именами файлов не имеет значения."}
::option[Оба файла должны быть отсортированы по своим полям объединения в совместимом порядке.]{#join-sorted-keys .correct explanation="`join` последовательно проходит упорядоченные ключи, поэтому каждый источник должен использовать порядок, согласованный с выполняемым сравнением."}
:::

## Выбор других полей объединения

Используйте `-1 FIELD` для ключа первого файла и `-2 FIELD` для ключа второго. Предположим, первый источник содержит:

```text
John 1
Jane 2
Mary 3
```

А второй:

```text
1 Doe
2 Doe
3 Sue
```

После сортировки первого файла по полю 2, а второго по полю 1 выполните:

```bash
$ join -1 2 -2 1 people.txt surnames.txt
1 John Doe
2 Jane Doe
3 Mary Sue
```

Используйте `-t CHARACTER`, если поля разделяет один непробельный символ, например `:`. Параметры `-a 1` и `-a 2` позволяют включить несопоставленные строки соответствующего источника; по умолчанию выводятся только совпавшие ключи.

:::single-choice{#join-different-fields}
Какие параметры объединяют поле 2 первого файла с полем 1 второго?

::option[`-1 1 -2 2`]{#join-fields-reversed explanation="Эта запись выбирает поле 1 первого источника и поле 2 второго — отображение, обратное требуемому."}
::option[`-1 2 -2 1`]{#join-fields-two-one .correct explanation="`-1 2` выбирает поле 2 первого файла, а `-2 1` — поле 1 второго."}
::option[`-f 2 -d 1`]{#join-cut-style-options explanation="Эти параметры напоминают выбор поля и разделителя в других текстовых инструментах, но не являются селекторами полей `join`."}
:::

## Разбиение по количеству строк

`split` записывает последовательные части одного источника в отдельные выходные файлы. Эта команда не является обратной для основанного на ключах `join`.

```bash
$ split large.txt
```

По умолчанию GNU-реализация записывает до 1000 строк в каждый выходной файл и использует префикс `x`, создавая имена вроде `xaa`, `xab` и `xac`.

Задайте число строк параметром `-l NUMBER`, а последним операндом — префикс выходных файлов:

```bash
$ split -l 500 large.txt part-
```

Будут созданы `part-aa`, `part-ab` и последующие части, каждая не более чем по 500 строк.

:::single-choice{#split-lines-with-prefix}
Какая команда разбивает `large.txt` на части не более 500 строк с префиксом `part-`?

::option[`split -b 500 large.txt part-`]{#split-five-hundred-bytes explanation="Параметр `-b` выбирает байты, поэтому в обычном тексте части будут намного меньше 500 строк."}
::option[`split -l 500 large.txt part-`]{#split-five-hundred-lines .correct explanation="`-l 500` задаёт максимальное число строк, а последний операнд — префикс имён выходных файлов."}
::option[`join -l 500 large.txt part-`]{#join-split-lines explanation="`join` объединяет записи двух файлов по ключам и не делит один источник на части."}
:::

## Разбиение по размеру

Используйте `-b SIZE`, чтобы делить ввод по числу байтов. Суффиксы GNU вроде `K`, `M` и `G` в этом контексте обозначают степени 1024:

```bash
$ split -b 10M archive.bin chunk-
```

Команда запрашивает части по 10 мебибайтов, кроме, возможно, меньшей последней. `split` не создаёт манифест архива или метаданные сборки; при необходимости восстановления сохраняйте порядок суффиксов и объединяйте части в нём.

:::single-choice{#split-ten-mebibytes}
Какая команда разбивает `archive.bin` на части по 10 МиБ с префиксом `chunk-`?

::option[`split -l 10M archive.bin chunk-`]{#split-lines-ten-m explanation="Параметр `-l` ожидает число строк, а не размер с байтовым суффиксом."}
::option[`join -b 10M archive.bin chunk-`]{#join-bytes explanation="`join` не разбивает двоичный ввод и не поддерживает такую операцию размера части."}
::option[`split -b 10M archive.bin chunk-`]{#split-ten-mib .correct explanation="Параметр `-b` задаёт размер части, `10M` означает 10×1024×1024 байтов, а `chunk-` — выходной префикс."}
:::
