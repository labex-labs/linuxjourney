Путь пакета — последовательность локальных решений. Хост-источник, каждый маршрутизатор и назначение применяют собственные состояние маршрутизации, соседей, фильтрации и протоколов; обычно ни одна конечная точка не знает заранее каждого внутреннего решения.

## Отправка локальному назначению

Для назначения, охваченного подключённым маршрутом, источник выбирает интерфейс и исходный IP. Затем он разрешает канальный адрес назначения — через ARP для IPv4 поверх Ethernet или обнаружение соседей для IPv6 — и отправляет кадр с IP-пакетом. Коммутатор может переслать кадр, не становясь IP-переходом.

:::single-choice{#packet-path-switch-hop}
Считается ли обычный коммутатор Ethernet переходом IP-маршрутизации?

::option[Нет; он пересылает локальные кадры, не уменьшая поле переходов IP.]{#packet-path-switch-not-hop .correct explanation="Маршрутизируемый переход происходит, когда маршрутизатор обрабатывает и пересылает IP-пакет."}
::option[Да; каждый коммутатор заменяет IP-адрес назначения.]{#packet-path-switch-replaces-ip explanation="Пересылка уровня 2 обычно не переписывает IP-адреса назначения."}
::option[Да; каждый кабельный разъём также является IP-переходом.]{#packet-path-cable-hop explanation="Физические компоненты не выполняют IP-маршрутизацию."}
:::

## Отправка через шлюз

Для назначения вне локального канала выбранный маршрут определяет маршрутизатор следующего перехода. IP-адресом назначения остаётся удалённая конечная точка, а канальным адресом назначения локального кадра является адрес шлюза. В своём локальном канале хост разрешает шлюз, а не удалённый сервер.

:::single-choice{#packet-path-gateway-mac}
Чей MAC-адрес используется в первом кадре Ethernet к серверу вне локального канала?

::option[Адрес удалённого сервера через все промежуточные сети.]{#packet-path-remote-mac explanation="Удалённый канальный адрес не имеет смысла в исходной LAN."}
::option[Значение, вычисленное из DNS-имени сервера.]{#packet-path-dns-mac explanation="Имена DNS не кодируют MAC следующего локального перехода."}
::option[Адрес выбранного локального шлюза.]{#packet-path-local-gateway .correct explanation="Кадр доставляется следующему переходу, а IP-заголовок указывает на конечную точку."}
:::

## Обработка на каждом маршрутизаторе

Маршрутизатор удаляет входящее канальное обрамление, проверяет и обрабатывает IP-заголовок, уменьшает TTL или Hop Limit, ищет назначение, применяет политику и создаёт новое обрамление для исходящего канала. Для IPv4 обработка контрольной суммы заголовка учитывает изменившийся TTL. Если поле переходов достигает нуля, маршрутизатор отбрасывает пакет и может вернуть сообщение ICMP об истечении времени.

:::single-choice{#packet-path-router-change}
Какое поле IP изменяется каждым обычным маршрутизируемым переходом?

::option[Имя пользователя приложения.]{#packet-path-username explanation="Для базовой пересылки маршрутизаторам не нужны данные учётной записи приложения."}
::option[IPv4 TTL или IPv6 Hop Limit.]{#packet-path-hop-field .correct explanation="Каждый маршрутизатор уменьшает поле, чтобы ограничить петли маршрутизации."}
::option[Транспортный порт назначения во всех случаях.]{#packet-path-port explanation="Обычная маршрутизация сохраняет транспортные конечные точки; NAT может быть отдельным преобразованием."}
:::

## Промежуточные устройства и MTU

Обычная маршрутизация сохраняет исходный и конечный IP-адреса, но NAT может их переписывать, а туннели — оборачивать исходный пакет. Межсетевые экраны могут беззвучно отбрасывать трафик или отклонять его. MTU каналов также различаются; маршрутизаторы IPv4 иногда могут фрагментировать пакеты, тогда как маршрутизаторы IPv6 не фрагментируют пересылаемые пакеты и полагаются на обнаружение MTU пути.

:::single-choice{#packet-path-address-change-exception}
Когда сквозные IP-адреса могут измениться по пути?

::option[Каждый раз, когда коммутатор Ethernet изучает исходный MAC.]{#packet-path-switch-learning-ip explanation="Обучение коммутатора влияет на таблицу канальной пересылки, а не на IP-адреса конечных точек."}
::option[Когда политика NAT преобразует заголовки пакета.]{#packet-path-nat-change .correct explanation="Преобразование — функция промежуточного устройства сверх обычной маршрутной пересылки."}
::option[Каждый раз при истечении записи кэша DNS.]{#packet-path-dns-expiry explanation="Существующие пакеты уже содержат числовые адреса."}
:::

## Обратный путь

Назначение выполняет собственный поиск маршрута для ответа. Обратный путь может использовать другие маршрутизаторы из-за политики маршрутизации, балансировки нагрузки или сбоев. Межсетевые экраны с состоянием и NAT должны учитывать наблюдаемый поток, поэтому асимметрия может иметь эксплуатационное значение, даже если IP её допускает.

:::single-choice{#packet-path-return-symmetry}
Обязан ли ответ проходить через те же маршрутизаторы в обратном порядке?

::option[Да, поскольку IP записывает полный исходящий маршрут в каждом пакете.]{#packet-path-records-route explanation="Обычные IP-пакеты не несут обязательный полный обратный маршрут."}
::option[Да, если источник и назначение не имеют общего имени хоста.]{#packet-path-hostname-symmetry explanation="Имена не обеспечивают симметрию пути."}
::option[Нет; каждое направление маршрутизируется независимо.]{#packet-path-independent-return .correct explanation="Политики и топология могут создавать асимметричный, но действительный путь."}
:::

## Итоги

Теперь вы можете проследить меняющееся канальное состояние вокруг маршрутизируемого IP-пакета.

1. Разрешайте конечный хост только тогда, когда он находится в локальном канале.
2. Помещайте трафик вне локального канала в кадр для выбранного локального шлюза.
3. Следуйте поиску маршрута и обработке ограничения переходов на каждом маршрутизаторе.
4. Учитывайте NAT, фильтрацию, туннели и ограничения MTU.
5. Рассматривайте обратное направление как независимый маршрут.
