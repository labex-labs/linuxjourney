Браузер открывает страницу, которую отдаёт веб-сервер в Docker. Где работает этот сервер? Что будет со страницей, если его остановить? Начнём с программы, которая отвечает на запросы браузера.

## Программа внутри контейнера

**Веб-сервер** — это программа, которая отвечает на запросы страниц. Представьте, что браузер и небольшой веб-сервер с именем `web` находятся на одной машине. Docker запускает сервер в **контейнере**. В нём программа видит свой набор файлов и других ресурсов. Примеры уже подготовлены, поэтому проходить курс можно без установки Docker.

:::single-choice{#docker-containers-page-request} Что возвращает содержимое страницы, когда браузер её запрашивает?

::option[Веб-сервер, работающий в контейнере.]{#docker-containers-page-server .correct explanation="Серверная программа принимает запрос и возвращает страницу."}
::option[Файлы, которые описывают запуск контейнера.]{#docker-containers-page-files explanation="Эти файлы задают настройки запуска. На запрос отвечает работающая программа."}
::option[Список контейнеров Docker на машине.]{#docker-containers-page-list explanation="Список показывает, что запускает Docker. Он не отдаёт веб-страницы."}
:::

## Контейнер и его хост

Машину, на которой работают контейнеры, называют **хостом**. Если Docker запускает контейнеры Linux на Linux, программы внутри них работают как процессы этого хоста. **Процесс** — это запущенная программа. Несколько контейнеров могут работать на одном хосте, но каждый видит лишь ограниченный набор ресурсов. В Docker Desktop контейнеры Linux работают внутри виртуальной машины Linux, которой управляет Docker.

:::single-choice{#docker-containers-shared-host} Два контейнера Linux работают на одном хосте Linux. Что из этого следует?

::option[Их программы обязательно видят одни и те же файлы.]{#docker-containers-host-shared-files explanation="На одном хосте каждый контейнер может видеть свой набор файлов."}
::option[Их программы могут работать на этом хосте как отдельные процессы.]{#docker-containers-host-separate-processes .correct explanation="Один хост может выполнять программы в разных контейнерах."}
::option[Каждому контейнеру нужно запустить отдельную машину с Linux.]{#docker-containers-host-separate-machines explanation="Контейнеры Linux могут работать как процессы на одном хосте. Отдельная машина для каждого не нужна."}
:::

## Как создаётся контейнер из образа

Docker создаёт контейнер из **образа**. Это пакет с программой и нужными ей файлами. Из одного образа веб-сервера можно создать `web` и `demo`. После запуска в каждом контейнере та же серверная программа выполняется в своём процессе. Каждый контейнер можно остановить независимо от другого.

:::single-choice{#docker-containers-two-from-image} Вы останавливаете demo, пока web ещё работает. Что произойдёт с web?

::option[Он приостановится до повторного запуска demo.]{#docker-containers-two-paused explanation="В каждом контейнере работает своя программа. В этом примере остановка demo не прерывает работу web."}
::option[Его придётся заново создать из образа.]{#docker-containers-two-recreate explanation="Контейнер web создан отдельно и может продолжить работу."}
::option[Он продолжит работу в своём контейнере.]{#docker-containers-two-independent .correct explanation="Оба контейнера созданы из одного образа и работают независимо."}
:::

## Проверка сервиса до и после остановки

Допустим, браузер уже может отправлять запросы к `web`. Пока контейнер работает, браузер получает страницу. После остановки новый запрос больше не получает страницу от этого сервера. Образ по-прежнему доступен для создания другого контейнера. Чтобы браузер мог открыть страницу, серверная программа должна работать, а браузер должен иметь возможность с ней связаться. В одном из следующих уроков вы узнаете, как открыть доступ к контейнеру из браузера.

:::single-choice{#docker-containers-stopped-server} Образ по-прежнему доступен, но web остановлен. Что нужно, чтобы именно web снова отвечал?

::option[Снова запустить в нём серверную программу.]{#docker-containers-stopped-program .correct explanation="Образ предоставляет файлы. Для обработки новых запросов нужен работающий сервер."}
::option[Переименовать образ, чтобы он мог отдавать страницы.]{#docker-containers-stopped-rename explanation="Смена имени образа не запускает остановленный сервер."}
::option[Передать браузеру ещё одну копию образа сервера.]{#docker-containers-stopped-browser-image explanation="Браузер отправляет запросы. Серверная программа работает в контейнере."}
:::

## Итоги

Теперь вы можете объяснить, как контейнер запускает программу на хосте.

1. Определить, какая программа отвечает на запрос браузера.
2. Объяснить, как контейнеры могут работать на одном хосте.
3. Описать, как из одного образа создать несколько контейнеров.
4. Отправить новый запрос и проверить, отвечает ли сервер, который раньше был доступен.
