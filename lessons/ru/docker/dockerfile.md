Вы уже запускали контейнер из готового образа веб-сервера. Чтобы отдавать собственную страницу, можно собрать образ, который уже её содержит. **Dockerfile** — это текстовый файл с инструкциями по сборке образа.

## С чего начинается базовый образ

**Базовый образ** предоставляет исходные файлы и программы. Этот Dockerfile берёт за основу образ Nginx, добавляет страницу и задаёт команду, которую контейнер выполняет по умолчанию. Храните Dockerfile и файл `index.html` в одном учебном каталоге. Для страницы достаточно одной строки, например `<h1>Hello from Docker</h1>`.

```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
CMD ["nginx", "-g", "daemon off;"]
```

`FROM nginx:alpine` выбирает исходный образ, в котором уже есть Nginx. Docker использует его при сборке нового образа.

:::single-choice{#dockerfile-base-image-purpose} Какая строка предоставляет Nginx до добавления вашей страницы?

::option[`COPY index.html /usr/share/nginx/html/index.html`]{#dockerfile-base-image-copy explanation="COPY добавляет страницу. Сам сервер находится в базовом образе."}
::option[`FROM nginx:alpine`]{#dockerfile-base-image-from .correct explanation="FROM выбирает исходный образ, который уже содержит сервер."}
::option[Строка, начинающаяся с `CMD`.]{#dockerfile-base-image-cmd explanation="CMD определяет команду по умолчанию при запуске. Программа сервера предоставляется базовым образом."}
:::

## Добавление файла

`COPY` читает `index.html` среди файлов, переданных для сборки. Инструкция записывает страницу по пути справа, откуда эта версия образа Nginx отдаёт страницу по умолчанию. Если вы позднее отредактируете локальную страницу, пересоберите образ, чтобы включить изменения.

:::single-choice{#dockerfile-copy-after-edit} После сборки вы поменяли заголовок в локальном файле index.html. Как включить изменение в новый образ?

::option[Запустить ещё один контейнер из существующего образа.]{#dockerfile-copy-edit-run explanation="Он запустится со страницей, уже упакованной в этот образ."}
::option[Изменить только имя существующего контейнера.]{#dockerfile-copy-edit-rename explanation="Имя контейнера не меняет содержимое образа."}
::option[Пересобрать образ с обновлённой страницей.]{#dockerfile-copy-edit-rebuild .correct explanation="Во время сборки COPY прочитает текущий локальный файл и добавит его в новый образ."}
:::

## Настройка команды запуска

`CMD` задаёт команду по умолчанию для нового контейнера. В примере Nginx продолжает работать на переднем плане внутри контейнера. При этом сам контейнер можно запустить в фоне относительно терминала командой `docker run -d`.

:::single-choice{#dockerfile-cmd-start-time} Когда используется команда по умолчанию из CMD в этом примере?

::option[При запуске контейнера с его командой по умолчанию.]{#dockerfile-cmd-when-start .correct explanation="Docker использует команду по умолчанию из образа при запуске контейнера."}
::option[Когда Docker копирует страницу в образ.]{#dockerfile-cmd-when-copy explanation="COPY добавляет страницу во время сборки. В этот момент сервер не запускается."}
::option[Когда Docker заканчивает запись образа.]{#dockerfile-cmd-when-build explanation="При сборке команда запуска сохраняется, чтобы использовать её позже."}
:::

## Сборка образа и запуск контейнера

Запустите сборку в каталоге, где находятся оба файла. Параметр `-t` присваивает образу ссылку `journey-web:1`. Точка в конце указывает Docker брать файлы для сборки из текущего каталога.

```bash
$ docker build -t journey-web:1 .
$ docker run -d --name custom-web -p 127.0.0.1:8082:80 journey-web:1
```

Вторая команда запускает контейнер. Если порт 8082 свободен, откройте `http://127.0.0.1:8082` в браузере на хосте Docker, чтобы увидеть свою страницу.

:::single-choice{#dockerfile-build-versus-run} Сборка завершилась успешно, но вторая команда ещё не выполнялась. Что уже готово?

::option[Образ существует, и из него можно создать контейнер.]{#dockerfile-build-ready-image .correct explanation="В результате сборки появился образ. Следующая команда запустит из него контейнер."}
::option[Контейнер с указанным именем уже отдаёт вашу страницу.]{#dockerfile-build-ready-container explanation="Сервер начнёт работать после запуска контейнера из образа."}
::option[Docker уже опубликовал порт для доступа из браузера.]{#dockerfile-build-ready-port explanation="Сопоставление портов задаётся в docker run. Сборка эту связь не настраивает."}
:::

## Итоги

Теперь вы можете прочитать небольшой Dockerfile и проследить путь от локальной страницы до работающего сервера.

1. Найти базовый образ в `FROM`.
2. Описать, откуда `COPY` читает файл и куда записывает его.
3. Распознать `CMD` как команду контейнера по умолчанию.
4. Собрать образ и запустить из него контейнер.
