Работает ли ещё веб-сервер, который вы запустили в Docker? Проверьте это командой `docker ps`. Образ Docker содержит программу и нужные ей файлы. Контейнер — экземпляр, созданный из этого образа. Команда показывает список контейнеров на момент запуска.

## Список запущенных контейнеров

По умолчанию `docker ps` показывает запущенные контейнеры. В примерах оставлено несколько столбцов из подготовленной среды. Чтобы читать этот вывод, устанавливать Docker не обязательно. Если вы работаете в терминале, вводите команду после приглашения `$`.

```text
$ docker ps
IMAGE         STATUS         NAMES
nginx:alpine  Up 4 minutes   web
nginx:alpine  Up 30 seconds  demo
```

Если Docker выводит лишь заголовки столбцов, список запущенных контейнеров пуст. Остановленные контейнеры при этом могут оставаться в системе.

:::single-choice{#docker-ps-running-list} После `docker ps` Docker вывел только заголовки столбцов. Что можно заключить?

::option[Нет образов, из которых можно запустить контейнеры.]{#docker-ps-running-list-images explanation="Команда выводит список контейнеров. Образы могут быть доступны и при пустом списке запущенных контейнеров."}
::option[Список запущенных контейнеров пуст.]{#docker-ps-running-list-empty .correct explanation="По умолчанию показаны только запущенные контейнеры. Остановленные могут оставаться в системе."}
::option[Нет остановленных контейнеров, которые можно проверить.]{#docker-ps-running-list-stopped explanation="Вывод по умолчанию не включает остановленные контейнеры. Из пустого списка ничего о них не известно."}
:::

## Как читать имена и состояния

Сначала найдите нужный контейнер в столбце `NAMES`. В столбце `IMAGE` у обеих строк один образ, `nginx:alpine`. Найдите справа `web` и прочитайте `STATUS` в той же строке. `Up 4 minutes` означает, что контейнер работает около четырёх минут.

:::single-choice{#docker-ps-name-column} В какой строке показан контейнер, который работает около 30 секунд?

::option[В строке с именем `demo`.]{#docker-ps-name-demo .correct explanation="Найдите Up 30 seconds в STATUS и прочитайте demo в NAMES на той же строке."}
::option[В строке с именем `web`.]{#docker-ps-name-web explanation="В строке web указано Up 4 minutes. Оба контейнера используют один образ, но запустились в разное время."}
::option[В обеих строках с образом `nginx:alpine`.]{#docker-ps-name-image-reference explanation="У каждой строки своё состояние. Общий образ не означает одинаковое время запуска."}
:::

## Как показать завершившиеся контейнеры

Если нужного контейнера нет в списке, попробуйте `docker ps -a`. Параметр `-a` — это сокращение от `--all`. Он добавляет в вывод остановленные контейнеры, которые всё ещё существуют. В примере также есть заранее подготовленная задача `preview`.

```text
$ docker ps -a
IMAGE         STATUS                         NAMES
nginx:alpine  Up 4 minutes                   web
nginx:alpine  Up 30 seconds                  demo
busybox:1.36  Exited (0) 2 minutes ago       report
busybox:1.36  Exited (1) About a minute ago  preview
```

В контейнере выполняется основная программа, например веб-сервер или скрипт. `Exited` означает, что программа завершилась. Число в скобках — **код завершения**, который программа вернула при выходе. Ноль обычно означает успех, а ненулевое значение чаще всего указывает на ошибку. У задачи `report` указано `Exited (0)`, что соответствует успешному завершению.

На снимке LabEx выведены лишь имена и состояния четырёх контейнеров из примера. Значения времени зависят от того, когда запущена команда.

:::single-choice{#docker-ps-exit-code-reading} Какой контейнер стоит проверить на наличие ошибки, если судить по коду завершения?

::option[`report`, потому что он завершился.]{#docker-ps-exit-code-report explanation="Короткая задача может завершиться после выполнения. Нулевой код обычно означает успех."}
::option[`demo`, потому что он запустился позже других работающих контейнеров.]{#docker-ps-exit-code-demo explanation="Up показывает, как давно выполняется программа. У этой строки нет кода завершения."}
::option[`preview`, потому что он завершился с кодом 1.]{#docker-ps-exit-code-preview .correct explanation="У preview указано Exited (1). Это повод изучить ошибку, хотя само состояние не объясняет её причину."}
:::

## Следующая проверка

Код завершения помогает выбрать, что проверить дальше. Чтобы увидеть, напечатал ли `preview` сообщение об ошибке, укажите его имя после `docker logs`. Команда покажет вывод, собранный Docker для этого контейнера.

```bash
$ docker logs preview
```

Если веб-сервер работает, можно проверить доступность страницы для посетителя. Откройте страницу на том компьютере, с которого нужен доступ. `Up` описывает программу внутри контейнера. Успешный запрос в браузере подтверждает доступность страницы с проверенного компьютера.

::option[Открыть страницу на компьютере коллеги.]{#docker-ps-next-check-visitor-browser .correct explanation="Так вы проверите подключение, которым коллега действительно будет пользоваться."}
::option[Ещё раз выполнить `docker ps` на компьютере с Docker.]{#docker-ps-next-check-status-again explanation="Список подтвердит, что web продолжает работать. Доступ с компьютера коллеги проверяет запрос из его браузера."}
::option[Ещё раз открыть страницу на компьютере с Docker.]{#docker-ps-next-check-host-browser explanation="Это повторяет проверку с первого компьютера. Подключение коллеги может работать иначе."}
:::

## Итоги

Теперь вы можете найти контейнер в списке, прочитать его состояние и выбрать следующую проверку.

1. Вывести запущенные контейнеры с помощью `docker ps`.
2. Найти контейнер по имени и прочитать его состояние.
3. Показать завершившиеся контейнеры с помощью `docker ps -a`.
4. Обратиться к журналам или сделать запрос в браузере, если состояния недостаточно.
