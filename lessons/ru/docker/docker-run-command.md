У вас есть образ веб-сервера. Чтобы запустить сервер, выполните `docker run`. Docker создаст и запустит контейнер из этого образа. Начните с короткой команды, чтобы увидеть, когда терминал снова станет доступен.

## Запуск короткой задачи

BusyBox — небольшой образ с основными командами Linux. В примере `echo` печатает сообщение. После ссылки на образ укажите команду, которую нужно выполнить в контейнере. Если образа нет локально, Docker обычно загружает его. Символ `$` обозначает приглашение терминала. Если Docker сначала скачивает образ, перед показанной строкой могут появиться сообщения о загрузке.

```text
$ docker run busybox:1.36 echo Hello
Hello
```

Вы увидите результат в терминале. После завершения `echo` контейнер остановится, а терминал снова покажет приглашение.

:::single-choice{#docker-run-command-short-task} Что выполняется внутри контейнера в этом примере?

::option[`busybox:1.36` как команда оболочки.]{#docker-run-command-short-image explanation="BusyBox — образ, в котором есть нужные инструменты. Команда указана после ссылки на образ."}
::option[`echo Hello` с помощью инструментов из образа.]{#docker-run-command-short-echo .correct explanation="После ссылки на образ указано, что запустить нужно echo и какой текст она должна вывести."}
::option[`docker run` как вторая команда Docker.]{#docker-run-command-short-docker explanation="Команда docker run выполняется в вашем терминале и запускает команду внутри контейнера."}
:::

## Как задать имя контейнера

Укажите `--name` перед ссылкой на образ, чтобы дать контейнеру узнаваемое имя. В этой команде контейнер с короткой задачей получает имя `report`.

```bash
$ docker run --name report busybox:1.36 echo Ready
```

Контейнер сохраняет имя после остановки. При создании другого контейнера в той же среде Docker выбирайте свободное имя.

:::single-choice{#docker-run-command-name-choice} Задача report завершилась, но контейнер ещё существует. Вы хотите создать второй контейнер из того же образа. Что можно изменить?

::option[Выбрать новое имя контейнера и оставить ту же ссылку на образ.]{#docker-run-command-name-new .correct explanation="Свободное имя позволяет Docker создать отдельный контейнер из того же образа."}
::option[Изменить тег образа и сохранить имя контейнера.]{#docker-run-command-name-change-tag explanation="Старый контейнер по-прежнему занимает имя, даже если выбрать другой образ."}
::option[Изменить сообщение и сохранить имя контейнера.]{#docker-run-command-name-change-message explanation="Сообщение — это входные данные для echo. Его изменение не освобождает имя report."}
:::

## Запуск сервера в фоновом режиме

Образ может содержать команду по умолчанию. Если после `nginx:alpine` не указать команду, запустится веб-сервер. Добавьте `-d` для запуска **в фоновом режиме**. Сервер продолжит работу, а терминал снова будет принимать команды.

```bash
$ docker run -d --name web nginx:alpine
```

Docker выведет длинный идентификатор запущенного контейнера. В следующем уроке вы проверите, продолжает ли работать сервер.

Короткие задачи выводят сообщения в терминале. При запуске сервера в фоне Docker возвращает идентификатор контейнера.

:::single-choice{#docker-run-command-detach-meaning} Docker вывел идентификатор, и появилось приглашение терминала. Что позволяет сделать этот режим?

::option[Использовать терминал только после завершения работы сервера.]{#docker-run-command-detach-wait explanation="В фоновом режиме терминал доступен, пока сервер продолжает работать."}

## Как распознать новый контейнер

Каждый успешный вызов `docker run` создаёт новый контейнер. Если снова использовать тот же образ сервера и выбрать свободное имя, Docker создаст второй контейнер. Первый сохранит своё имя и состояние.

:::single-choice{#docker-run-command-second-instance} Контейнер web работает. Что сделает `docker run -d --name demo nginx:alpine`, если имя demo свободно?

::option[Переименует работающий контейнер web в demo.]{#docker-run-command-second-rename explanation="Docker run создаёт новый контейнер. Имя прежнего контейнера web не изменится."}
::option[Добавит к образу ещё один тег demo.]{#docker-run-command-second-tag explanation="Этот параметр задаёт имя контейнера. Ссылка на образ остаётся nginx:alpine."}
::option[Запустит отдельный контейнер с именем demo.]{#docker-run-command-second-new .correct explanation="Docker создаст из этого образа новый контейнер и назовёт его demo."}
:::

## Итоги

Теперь вы можете прочитать команду docker run и определить, что создаст Docker.

1. Определить образ и необязательную команду для запуска внутри контейнера.
2. Задать имя через `--name`, чтобы потом найти нужный контейнер.
3. Описать, что происходит после выполнения короткой задачи.
4. Использовать `-d`, чтобы вернуться к приглашению терминала, пока сервер работает.
