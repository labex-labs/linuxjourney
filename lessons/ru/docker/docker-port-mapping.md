Веб-сервер может работать в контейнере, но браузеру нужен способ до него добраться. **Порт** — это номер, по которому компьютер направляет входящие сетевые запросы нужному сервису. Docker может опубликовать порт хоста и перенаправлять полученные запросы на порт внутри контейнера.

## Как читать сопоставление портов

В этом примере Nginx принимает веб-запросы на порту 80 внутри контейнера. Контейнер `web` из предыдущего примера был создан без опубликованного порта. Дайте новому контейнеру другое имя и задайте сопоставление при создании с помощью `-p`.

```bash
$ docker run -d --name published-web -p 127.0.0.1:8080:80 nginx:alpine
```

`8080:80` означает перенаправление с **порта хоста** 8080 на **порт контейнера** 80. Браузер подключается к порту хоста, а сервер принимает запрос на порту контейнера. Адрес `127.0.0.1` привязывает сопоставление к адресу обратной петли, по которому хост обращается к самому себе.

Используйте изолированную учебную среду. В версиях Docker Engine до 28.0.0 другие машины того же сегмента локальной сети в некоторых случаях могут обращаться к портам, опубликованным на localhost. [Документация Docker о публикации портов](https://docs.docker.com/engine/network/port-publishing/)

:::single-choice{#docker-port-mapping-request-target} Если указано `127.0.0.1:9090:80`, к какому порту должен подключиться браузер на хосте Docker?

::option[К порту 9090 на хосте.]{#docker-port-mapping-target-outer .correct explanation="Среднее число задаёт порт хоста, к которому подключается браузер."}
::option[К порту 80 на хосте.]{#docker-port-mapping-target-inner explanation="Порт 80 — это порт назначения внутри контейнера."}
::option[К порту 9090 внутри контейнера.]{#docker-port-mapping-target-wrong-side explanation="В этом примере сервер получает запрос на порту 80 внутри контейнера."}
:::

## Проверка с хоста

Откройте `http://127.0.0.1:8080` в браузере на машине, где Docker опубликовал порт. Если Docker работает на удалённой машине, адрес `127.0.0.1`, введённый на ноутбуке, укажет на этот ноутбук. Если вы занимаетесь в браузерной лаборатории, используйте способ доступа, предусмотренный в учебной среде.

:::single-choice{#docker-port-mapping-local-browser} Docker опубликовал порт 8080 на отдельной учебной машине. Куда ведёт `127.0.0.1`, если ввести адрес в браузере на ноутбуке?

::option[На отдельную учебную машину.]{#docker-port-mapping-local-lab explanation="Адрес указывает на учебную машину, только если используется на ней самой."}
::option[На веб-контейнер Docker.]{#docker-port-mapping-local-container explanation="Браузер подключается по адресу своей машины. Сопоставление портов может направить его запрос в контейнер."}
::option[На ваш ноутбук.]{#docker-port-mapping-local-laptop .correct explanation="Адрес обратной петли указывает на машину, где работает браузер."}
:::

## Как проверить, что опубликовал Docker

Столбец `PORTS` в выводе `docker ps` может показать сопоставление. Стрелка идёт от адреса и порта хоста к порту контейнера. Суффикс `/tcp` обозначает используемый сетевой протокол.

```text
$ docker ps
STATUS         PORTS                   NAMES
Up 2 minutes   127.0.0.1:8080->80/tcp   published-web
```

В строке может стоять только `80/tcp`. Если нет адреса хоста и стрелки, в этой записи не указан опубликованный порт хоста.

![Терминал LabEx с перенаправлением порта хоста 8080 на порт контейнера 80 и ответом HTTP 200](https://cdn.jsdelivr.net/gh/labex-labs/linuxjourney@master/images/lessons/docker/docker-port-mapping/loopback-mapping.png)

На снимке список отфильтрован до `published-web`. Запрос с помощью `curl` запускается на хосте Docker и подтверждает, что опубликованный адрес отвечает успешно.

:::single-choice{#docker-port-mapping-read-listing} В строке указано `80/tcp` без стрелки. Что можно заключить?

::option[Docker опубликовал порт 80 на хосте.]{#docker-port-mapping-listing-host explanation="При публикации виден порт хоста и стрелка к порту контейнера."}
::option[В строке есть порт контейнера, но не указан опубликованный порт хоста.]{#docker-port-mapping-listing-container .correct explanation="Запись обозначает порт 80 внутри контейнера. В ней нет ни адреса хоста, ни стрелки перенаправления."}
::option[Docker опубликовал порт 8080 на хосте.]{#docker-port-mapping-listing-default explanation="В записи нет порта хоста. Docker не выводит из неё порт 8080."}
:::

## Выбор адреса для проверки

Если страница не открывается, сравните введённый адрес с левой стороной сопоставления. `Up` показывает, что Docker запустил программу. Стрелка показывает, куда направляется запрос. Проверить, отдаёт ли сервер страницу, можно запросом из браузера.

:::single-choice{#docker-port-mapping-correct-misdirected} На хосте Docker вы пробуете порт 8080, но страница не открывается. В списке указано `127.0.0.1:8081->80/tcp`. Что попробовать дальше?

::option[Открыть `http://127.0.0.1:80`.]{#docker-port-mapping-misdirected-80 explanation="Порт 80 находится на стороне контейнера."}
::option[Открыть `http://127.0.0.1:8081`.]{#docker-port-mapping-misdirected-8081 .correct explanation="Используйте опубликованный порт хоста слева от стрелки."}
::option[Снова попробовать `http://127.0.0.1:8080`.]{#docker-port-mapping-misdirected-8080 explanation="В списке указан порт хоста 8081. Повторный запрос к 8080 не проверит это сопоставление."}
:::

## Итоги

Теперь вы можете прочитать сопоставление портов и выбрать правильный адрес для браузера.

1. Отличить порт хоста от порта контейнера.
2. Объяснить, куда ведёт `127.0.0.1`.
3. Распознать опубликованный порт в списке контейнеров.
4. Проверить сервис через опубликованный порт хоста.
