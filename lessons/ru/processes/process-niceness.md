Linux может одновременно выполнять потоки на разных ядрах CPU и делить время одного ядра между большим числом готовых потоков. Планировщик принимает решения согласно политике планирования, приоритету, привязке и нагрузке. Значение nice — один из входных параметров обычных политик разделения времени.

## Интерпретация значений nice

Общепринятый диапазон nice — от `-20` до `19`:

- Меньшее значение даёт задаче больший вес планирования относительно сопоставимых задач.
- Большее значение делает её «приятнее», предоставляя меньший относительный вес.
- Стандартное значение обычно равно `0`.

Niceness не резервирует процент CPU и не гарантирует немедленное выполнение. Его влияние наиболее заметно, когда сопоставимые готовые задачи конкурируют за время CPU. Политики реального времени, cgroups, привязка CPU, ожидание ввода-вывода и другие механизмы могут доминировать в наблюдаемом поведении.

:::single-choice{#process-niceness-lower-value} Какое значение nice даёт больший относительный вес CPU при одинаковой обычной политике планирования?

::option[`10`]{#process-niceness-value-ten explanation="Положительное значение является более nice и обычно имеет меньший вес, чем ноль или отрицательное значение."}
::option[`19`]{#process-niceness-value-nineteen explanation="Это самый nice конец обычного диапазона с относительно малым весом."}
::option[`-5`]{#process-niceness-value-minus-five .correct explanation="Меньшие значения nice соответствуют большему относительному весу среди сопоставимых обычных задач."}
:::

## Просмотр niceness

В `top` значение nice отображает столбец `NI`. Его также можно запросить через `ps`:

```bash
$ ps -o pid,ni,pri,stat,cmd -p 3245
```

`NI` — видимое пользователю значение nice. Столбец `PRI` или похожий может быть производным приоритетом планировщика, шкала которого зависит от инструмента и класса планирования, поэтому не считайте два столбца взаимозаменяемыми.

:::single-choice{#process-niceness-top-column} Какой столбец `top` обычно показывает значение nice?

::option[`PID`]{#process-niceness-column-pid explanation="PID обозначает процесс, а не его поправку планирования."}
::option[`TTY`]{#process-niceness-column-tty explanation="TTY обозначает связь с управляющим терминалом."}
::option[`NI`]{#process-niceness-column-ni .correct explanation="NI — общепринятое сокращение значения nice процесса или потока."}
:::

## Запуск команды через `nice`

Используйте `nice`, чтобы запустить новую команду с изменённым значением:

```bash
$ nice -n 5 long-computation
```

Запрошенную поправку и поддерживаемый синтаксис можно проверить в локальном руководстве. Непривилегированный пользователь обычно может сделать команду более nice, увеличив значение. Для меньшего nice и, следовательно, более благоприятного веса планирования нужны соответствующие привилегии или настроенные ограничения ресурсов.

:::single-choice{#process-niceness-nice-command} Что делает `nice -n 5 long-computation`?

::option[При наличии разрешения запускает команду со значением nice 5.]{#process-niceness-start-five .correct explanation="nice запускает новую команду с запрошенной поправкой планирования."}
::option[Меняет PID 5 на минимально возможное значение nice.]{#process-niceness-pid-five explanation="Операнд после `-n` — значение nice, а не целевой PID."}
::option[Гарантирует команде ровно пять процентов одного CPU.]{#process-niceness-five-percent explanation="Значения nice выражают относительный вес и не резервируют фиксированные проценты CPU."}
:::

## Изменение существующего процесса через `renice`

Для уже работающего процесса используйте `renice`:

```bash
$ renice -n 10 -p 3245
```

Команда запрашивает значение nice `10` для PID `3245`. Сначала проверьте цель, поскольку PID могут использоваться повторно, а затем подтвердите итоговое значение. Права зависят от владения, привилегий, ограничений ресурсов и системной политики. Обычно вы можете увеличить nice собственного процесса; обратное уменьшение без привилегий может быть запрещено.

Лаборатория [Управление и мониторинг процессов Linux](https://labex.io/ru/labs/comptia-manage-and-monitor-linux-processes-590864) предоставляет контролируемую среду для просмотра и изменения nice. Сравнивайте конкурирующие задачи с нагрузкой на CPU, а не ожидайте заметной разницы в простаивающей системе.

## Итоги

Теперь вы можете интерпретировать и изменять niceness, не считая его гарантией CPU.

1. Читайте меньшие значения nice как больший относительный вес планирования.
2. Проверяйте `NI` отдельно от производных полей приоритета.
3. Используйте `nice` при запуске команды.
4. Используйте `renice` для существующего проверенного процесса.
