Процесс — работающий экземпляр программы вместе с его памятью, учётными данными, открытыми ресурсами и состоянием выполнения. Linux обозначает каждый живой процесс числовым идентификатором процесса, или PID. PID уникален среди процессов, существующих одновременно, но после завершения процесса ядро может использовать его повторно.

## Создание простого снимка

Запустите `ps` без параметров, чтобы увидеть снимок, выбранный стандартными правилами реализации: обычно это процессы, связанные с текущими терминалом и пользователем:

```text
$ ps
    PID TTY          TIME CMD
  41230 pts/4    00:00:00 bash
  51224 pts/4    00:00:00 ps
```

Типичные поля:

- `PID`: идентификатор процесса
- `TTY`: управляющий терминал или `?`, если он не связан
- `TIME`: накопленное время CPU, а не прошедшее календарное время
- `CMD`: имя команды или командная строка в зависимости от выбранного формата

Точные столбцы и правила выбора по умолчанию различаются между реализациями `ps` и средами.

## Перечисление процессов параметрами в стиле BSD

`ps` в Linux принимает несколько стилей параметров. Параметры в стиле BSD обычно записываются без начального дефиса:

```bash
$ ps aux
```

В этом сочетании:

- `a` расширяет выбор процессами других пользователей, имеющими терминалы.
- `x` также включает процессы без управляющих терминалов и в сочетании с `a` дополнительно расширяет выбор.
- `u` выбирает ориентированный на пользователя формат вывода с полями вроде `USER`, `%CPU`, `%MEM`, `VSZ` и `RSS`.

Поскольку значения параметров могут взаимодействовать, интерпретируйте полное сочетание, а не считайте каждую букву независимой командой.

:::single-choice{#ps-command-aux-user-format} Какой параметр в `ps aux` запрашивает ориентированный на пользователя формат вывода?

::option[`u`]{#ps-command-aux-u .correct explanation="Параметр u в стиле BSD выбирает набор столбцов, ориентированный на пользователя."}
::option[`x`]{#ps-command-aux-x explanation="Параметр x влияет на выбор процессов, особенно без управляющих терминалов."}
::option[`a`]{#ps-command-aux-a explanation="Параметр a расширяет выбор за пределы процессов терминала текущего пользователя."}
:::

## Использование параметров стандартного стиля

Распространённая команда стандартного стиля `ps -ef` записывает параметры с начальным дефисом:

```bash
$ ps -ef
```

- `-e` выбирает каждый процесс, видимый вызывающей стороне.
- `-f` запрашивает полный формат списка.

Вывод обычно включает `UID`, `PID`, `PPID`, время запуска и сведения о команде. `PPID` — идентификатор родительского процесса. Этот список сам по себе не является иерархическим; когда важна структура родителей и потомков, используйте поддерживаемый параметр вроде `--forest` или отдельное средство просмотра `pstree`.

:::single-choice{#ps-command-ef-selection} Что запрашивает `-e` в `ps -ef`?

::option[Обновление каждую секунду до прерывания.]{#ps-command-e-refresh explanation="ps создаёт снимок; непрерывное обновление предоставляют инструменты вроде top."}
::option[Выбор каждого процесса, видимого вызывающей стороне.]{#ps-command-e-every .correct explanation="Параметр стандартного стиля -e расширяет снимок до всех доступных для выбора процессов."}

:::

## Мониторинг активности во времени

`ps` завершается после создания одного снимка. Для интерактивного представления с периодическим обновлением используйте `top`:

```bash
$ top
```

`top` помогает находить меняющихся потребителей CPU и памяти, но его значения являются образцами и могут колебаться. Подтвердите предполагаемую проблему несколькими наблюдениями и соотнесите проценты с числом CPU машины, учётом памяти и рабочей нагрузкой.

:::single-choice{#ps-command-snapshot-versus-top} Какой представленный здесь инструмент по умолчанию периодически обновляет список процессов?

::option[`top`]{#ps-command-top-refresh .correct explanation="top — интерактивный монитор, обновляющий представление через интервалы."}
::option[`ps -ef`]{#ps-command-ps-ef-snapshot explanation="Команда выводит полный снимок процессов и завершается."}
::option[`ls -l`]{#ps-command-ls-files explanation="ls -l отображает записи файловой системы, а не живой монитор процессов."}
:::

## Итоги

Теперь вы можете выбрать представление процессов и интерпретировать его основные идентификаторы.

1. Рассматривайте PID как повторно используемый идентификатор текущего живого процесса.
2. Используйте простой `ps` для небольшого стандартного снимка.
3. Используйте `ps aux` или `ps -ef` для более широкого выбора и подробных столбцов.
4. Используйте `top`, когда важны изменения во времени.
