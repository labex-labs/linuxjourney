Контейнер может записывать файлы в собственный слой для записи. Если удалить контейнер, Docker удалит и этот слой. **Именованный том** — это хранилище, которым Docker управляет отдельно. Тот же том можно подключить к новому контейнеру.

## Описываем том для упражнения

Сохраните этот отдельный пример в учебном каталоге под именем `compose.volume.yaml`. Он подключает хранилище `notes` к пути `/data` в контейнере с инструментами. В конце файла раздел `volumes` объявляет именованный том.

```yaml
services:
  toolbox:
    image: busybox:1.36
    volumes:
      - notes:/data
volumes:
  notes:
```

Определение сервиса указывает, где именно том будет смонтирован внутри контейнера. Объявление верхнего уровня указывает Compose, что этим томом нужно управлять вместе с проектом.

:::single-choice{#compose-volumes-attached-path} По какому пути внутри контейнера с инструментами доступен именованный том?

::option[По пути /notes.]{#compose-volumes-attached-path-b explanation="Notes — имя тома. Путь монтирования внутри контейнера указан после двоеточия."}
::option[По пути /data.]{#compose-volumes-attached-path-a .correct explanation="Правая часть записи notes:/data — путь внутри контейнера."}
::option[По любому пути внутри контейнера.]{#compose-volumes-attached-path-c explanation="Том смонтирован только в указанном каталоге."}
:::

## Записываем и читаем из разных контейнеров

Параметр `-f` выбирает другой файл, а `-p` задаёт отдельное имя проекта. Команда `run --rm` создаёт контейнер для одного запуска и сразу после завершения удаляет его. Выполните команды в отдельном учебном каталоге. Первая команда перезаписывает тестовый файл `/data/note.txt`.

```bash
$ docker compose -p journey-volume -f compose.volume.yaml run --rm toolbox sh -c 'echo ready > /data/note.txt'
$ docker compose -p journey-volume -f compose.volume.yaml run --rm toolbox cat /data/note.txt
```

Второй контейнер должен вывести `ready`. Он монтирует тот же том, что и первый.

:::single-choice{#compose-volumes-persistence} Почему второй контейнер может прочитать файл, хотя первый уже удалён?

::option[Оба контейнера подключили один и тот же именованный том.]{#compose-volumes-persistence-b .correct explanation="Файл был записан в отдельное хранилище, смонтированное по пути /data."}
::option[Оба контейнера сохранили слой для записи первого контейнера.]{#compose-volumes-persistence-a explanation="Слой был удалён вместе с первым контейнером."}
::option[BusyBox автоматически добавил файл в свой образ.]{#compose-volumes-persistence-c explanation="Запуск контейнера не меняет исходный образ."}
:::

## Выбираем, какие данные сохранять

Файл вроде `/tmp/note.txt` за пределами смонтированного каталога остаётся привязанным к контейнеру, если по этому пути не подключено другое хранилище. Проверяйте пути, прежде чем рассчитывать на сохранность файла. При удалении самого тома его данные могут исчезнуть. Резервная копия хранится отдельно и позволяет восстановить данные, если том потерян.

:::single-choice{#compose-volumes-inside-mount} Какой файл следующий контейнер с инструментами увидит через этот том?

::option[/tmp/note.txt из слоя для записи первого контейнера.]{#compose-volumes-inside-mount-a explanation="Этот путь находится за пределами смонтированного каталога."}
::option[Файл, сохранённый в томе с другим именем.]{#compose-volumes-inside-mount-b explanation="Чтобы увидеть этот файл, новый контейнер должен подключить другой том."}
::option[/data/note.txt, который записал первый контейнер.]{#compose-volumes-inside-mount-c .correct explanation="Через том, смонтированный по пути /data, оба контейнера получают доступ к одному и тому же файлу."}
:::

## Итоги

Теперь вы можете объяснить, почему файл иногда остаётся доступным после удаления записавшего его контейнера.

1. Находите имя тома и путь монтирования.
2. Проверяйте сохранность файла, читая его из другого контейнера.
3. Различайте удаление тома и замену контейнера.
