Браузер на хосте Docker подключается к веб-сервису по опубликованному адресу. Другой контейнер в проекте использует иной путь. Обычно Compose подключает сервисы одного проекта к общей сети, где они могут находить друг друга по имени сервиса.

## Запрашиваем страницу из контейнера с инструментами

Вернитесь в учебный каталог с файлом `compose.yaml`. Если контейнер с инструментами завершился после предыдущего урока, запустите его командой `docker compose start toolbox`. Когда оба сервиса работают, используйте `docker compose exec`, чтобы выполнить команду в уже запущенном контейнере с инструментами. Команда BusyBox `wget` запрашивает страницу. Параметр `-q` скрывает сообщения о ходе загрузки, а `-O -` выводит страницу в терминал.

```bash
$ docker compose exec -T toolbox wget -q -O - http://web:80/
```

Параметр `-T` отключает выделение интерактивного терминала. В URL указаны имя веб-сервиса и порт внутри контейнера. При успешном запросе вы увидите HTML страницы Nginx.

:::single-choice{#compose-service-discovery-sibling-url} Какой адрес должен использовать другой сервис в той же сети Compose, чтобы обратиться к веб-контейнеру?

::option[`http://web:80/`]{#compose-service-discovery-sibling-url-c .correct explanation="В общей сети имя web указывает на нужный сервис, который принимает запросы на порту 80."}
::option[`http://127.0.0.1:8080/`]{#compose-service-discovery-sibling-url-a explanation="Адрес обратной петли указывает на сетевое окружение самого сервиса, отправляющего запрос."}
::option[`http://web:8080/`]{#compose-service-discovery-sibling-url-b explanation="В этом примере веб-сервер принимает запросы на порту 80 внутри сети."}
:::

## Выбираем адрес для подключения с хоста

Откройте на хосте Docker `http://127.0.0.1:8080/`, если вы сохранили исходное сопоставление портов. Если вы изменили порт хоста в предыдущем уроке, укажите его в адресе браузера. Контейнер с инструментами по-прежнему использует `http://web:80/`, потому что подключается из сети Compose, где доступно имя сервиса `web`.

:::single-choice{#compose-service-discovery-host-url} Допустим, вы заменили порт хоста на 8081. Какой адрес из примера тоже нужно изменить?

::option[URL, по которому контейнер с инструментами обращается к web на порту 80.]{#compose-service-discovery-host-url-b explanation="Этот путь всё ещё ведёт напрямую к порту внутри веб-контейнера."}
::option[Оба адреса из примера.]{#compose-service-discovery-host-url-c explanation="Изменился только порт на стороне хоста."}
::option[Адрес, который используется в браузере на хосте.]{#compose-service-discovery-host-url-a .correct explanation="Браузер подключается через новый опубликованный порт хоста."}
:::

## Используем постоянное имя сервиса

При замене контейнера его сетевой адрес может измениться. Имя сервиса Compose при этом сохраняется. Клиент может снова узнать адрес по имени и подключиться заново. Открытое подключение к старому контейнеру может оборваться.

:::single-choice{#compose-service-discovery-replacement} Веб-контейнер был пересоздан и получил другой адрес. Что можно использовать для следующего запроса из контейнера с инструментами?

::option[Старый адрес, скопированный из контейнера.]{#compose-service-discovery-replacement-a explanation="Новый экземпляр может получить другой сетевой адрес."}
::option[Прежнее имя веб-сервиса и тот же порт контейнера.]{#compose-service-discovery-replacement-b .correct explanation="В сети проекта это имя может указывать на текущий контейнер."}
::option[Имя самого контейнера с инструментами.]{#compose-service-discovery-replacement-c explanation="Это имя обозначает сервис, который отправляет запрос."}
:::

## Итоги

Теперь вы можете выбирать адрес сервиса в зависимости от того, откуда идёт запрос.

1. Внутри сети проекта используйте имя сервиса и порт контейнера.
2. Для браузера на хосте используйте опубликованный адрес.
3. После замены контейнера снова определите адрес по имени сервиса.
