При расчёте подсетей длина префикса применяется к 32 битам адреса IPv4. Рассуждение в двоичном виде помогает избежать ошибок на границах префикса, не совпадающих с границами десятичных октетов.

## Определение сетевого адреса

Возьмём адрес `192.168.1.165/24`:

```text
address  11000000.10101000.00000001.10100101
mask     11111111.11111111.11111111.00000000
network  11000000.10101000.00000001.00000000
```

Побитовое И сохраняет биты адреса там, где в маске стоит единица, и обнуляет биты узла. Результат — `192.168.1.0/24`.

:::single-choice{#subnet-math-network-operation} Какая операция позволяет получить сетевой адрес IPv4 из адреса и маски?

::option[Конкатенация десятичных строк.]{#subnet-math-concatenation explanation="Объединение напечатанных октетов не применяет биты префикса."}
::option[Вычитание транспортных портов.]{#subnet-math-port-subtraction explanation="Порты не связаны с сетевым префиксом."}
::option[Побитовое И.]{#subnet-math-bitwise-and .correct explanation="Сетевые биты сохраняются, а позиции узла, которым соответствуют нули маски, обнуляются."}
:::

## Подсчёт адресов

Для префикса `/p` часть узла содержит `32 - p` бит. Общее количество адресов равно:

```text
2^(32 - p)
```

Следовательно, `/24` содержит `2^8 = 256` адресов. В традиционной широковещательной подсети значение части узла из одних нулей является сетевым адресом, а из одних единиц — направленным широковещательным адресом; для обычных одноадресных узлов остаётся 254 адреса.

:::single-choice{#subnet-math-24-total} Сколько всего адресов содержит подсеть IPv4 `/24`?

::option[24]{#subnet-math-total-24 explanation="Длина префикса обозначает число сетевых битов, а не адресов."}
::option[256]{#subnet-math-total-256 .correct explanation="Восемь бит узла дают 2^8 различных значений адреса."}
::option[254]{#subnet-math-total-254 explanation="Это традиционное число доступных адресов узлов после исключения двух специальных адресов, а не общее количество."}
:::

## Определение границы блока

Для `/26` маска равна `255.255.255.192`. Размер блока в последнем октете составляет `256 - 192 = 64`, поэтому границы подсетей проходят по значениям 0, 64, 128 и 192. Адрес `192.168.1.165/26` находится в диапазоне:

```text
network:   192.168.1.128
broadcast: 192.168.1.191
range:     192.168.1.129 through 192.168.1.190
```

:::single-choice{#subnet-math-165-network} Каков сетевой адрес для `192.168.1.165/26`?

::option[`192.168.1.0`]{#subnet-math-network-zero explanation="Это первый блок `/26`, охватывающий значения от 0 до 63."}
::option[`192.168.1.165`]{#subnet-math-network-self explanation="В указанном адресе присутствуют ненулевые биты узла внутри `/26`."}
::option[`192.168.1.128`]{#subnet-math-network-128 .correct explanation="Значение 165 входит в блок от 128 до 191."}
:::

## Учёт исключений для префиксов

Сокращённая формула `2^host_bits - 2` подходит не всегда. Префиксы IPv4 `/31` определены для соединений «точка — точка», где оба адреса могут быть конечными точками и направленный широковещательный адрес не нужен. `/32` обозначает один маршрут к узлу или адрес интерфейса. Возможность назначения адресов зависит от сетевой технологии и способа использования протокола.

:::single-choice{#subnet-math-31-exception} Почему нельзя вычитать два адреса для каждого префикса IPv4?

::option[При любом префиксе адреса IPv4 не содержат битов узла.]{#subnet-math-no-host-bits explanation="В большинстве префиксов для узла остаётся один или несколько битов."}
::option[В соединениях «точка — точка» с `/31` оба адреса могут использоваться как конечные точки.]{#subnet-math-31-both .correct explanation="В модели «точка — точка» не нужны традиционные резервы для сетевого и направленного широковещательного адресов."}
::option[Все сети IPv4 используют групповую адресацию вместо одноадресной.]{#subnet-math-all-multicast explanation="Обычная одноадресная адресация остаётся основой IPv4."}
:::

## Проверка вычислений

Проверьте ручной расчёт независимым инструментом или библиотекой, а затем сопоставьте результат с реальной конфигурацией интерфейсов и маршрутов. Математически корректный префикс всё равно может пересекаться с другой подсетью или нарушать план распределения адресов.

## Итоги

Теперь вы можете вычислять границы подсетей IPv4 и учитывать распространённые исключения.

1. Определяйте сетевой адрес с помощью побитового И.
2. Вычисляйте общее число адресов по количеству битов узла.
3. Используйте размеры блоков, чтобы находить сетевые и широковещательные границы.
4. Обрабатывайте `/31` и `/32` в соответствии с их назначением.
5. Сверяйте математические результаты с фактическим планом адресации.
