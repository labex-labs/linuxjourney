Бесклассовая междоменная маршрутизация представляет диапазон адресов с помощью длины префикса, не опираясь на исторические классы адресов. CIDR поддерживает выделение диапазонов переменного размера, разбиение на подсети и агрегацию маршрутов как для IPv4, так и для IPv6.

## Чтение префиксной записи

В `10.42.3.17/24` первые 24 бита образуют сетевой префикс, а восемь бит остаются для позиций внутри диапазона. Каноническая сеть — `10.42.3.0/24`; при настройке интерфейса указанный адрес узла всё равно можно записать вместе с префиксом.

:::single-choice{#cidr-prefix-meaning} Что задаёт `/24` в значении CIDR для IPv4?

::option[Двадцать четыре начальных бита сетевого префикса.]{#cidr-24-prefix-bits .correct explanation="Оставшиеся восемь из 32 бит IPv4 изменяются внутри префикса."}
::option[Двадцать четыре доступных адреса в каждой подсети.]{#cidr-24-addresses explanation="`/24` содержит 256 значений адреса."}
::option[Порт назначения TCP для сети.]{#cidr-24-port explanation="CIDR и транспортные порты не зависят друг от друга."}
:::

## Вычисление размера диапазона

Префикс IPv4 `/23` оставляет девять битов узла и потому охватывает `2^9 = 512` адресов. Выровненный префикс `123.12.24.0/23` включает диапазон:

```text
first: 123.12.24.0
last:  123.12.25.255
```

При традиционном широковещательном использовании первый адрес является сетевым, а последний — направленным широковещательным. Не применяйте бездумно сокращённое правило «минус два» для доступных узлов к соединениям «точка — точка» `/31` и маршрутам к узлу `/32`.

:::single-choice{#cidr-23-total} Сколько всего адресов IPv4 содержит `/23`?

::option[512]{#cidr-total-512 .correct explanation="Девять изменяемых битов создают 2^9 комбинаций."}
::option[23]{#cidr-total-23 explanation="Число префикса обозначает количество фиксированных битов, а не адресов."}
::option[510]{#cidr-total-510 explanation="Это традиционное число доступных адресов после исключения специальных конечных значений, а не полный размер диапазона."}
:::

## Проверка выравнивания

Префикс должен начинаться на своей двоичной границе. При фиксированных предыдущих октетах `/23` продвигается блоками по два значения в третьем октете, поэтому `123.12.24.0/23` выровнен, а `123.12.25.0/23` канонизируется в тот же диапазон `123.12.24.0/23`.

:::single-choice{#cidr-canonical-25} Какова каноническая сеть `/23`, содержащая `123.12.25.0`?

::option[Только `123.12.25.0/23`, начинающаяся с 25.]{#cidr-25-unaligned explanation="Последний бит префикса объединяет значения третьего октета в выровненные пары."}
::option[`123.12.0.0/23`]{#cidr-third-zero explanation="Эта запись описывает другой диапазон `/23`."}
::option[`123.12.24.0/23`]{#cidr-24-canonical .correct explanation="Значения третьего октета 24 и 25 имеют общий выровненный 23-битный префикс."}
:::

## Агрегация маршрутов

CIDR позволяет объявить один агрегированный маршрут для нескольких смежных, одинаковых по размеру и правильно выровненных префиксов. Например, `192.0.2.0/25` и `192.0.2.128/25` объединяются в `192.0.2.0/24`. Агрегация безопасна, только если объявляющий маршрутизатор способен правильно достигать всего агрегированного диапазона либо применяет политику, предотвращающую петли и чёрные дыры.

:::single-choice{#cidr-aggregate-two-25s} Какой агрегированный префикс охватывает обе половины `192.0.2.0/24`?

::option[`192.0.2.0/26`]{#cidr-aggregate-26 explanation="`/26` охватывает лишь 64 адреса — меньше любой из половин."}
::option[`192.0.3.0/25`]{#cidr-aggregate-other explanation="Этот префикс находится за пределами указанного диапазона."}
::option[`192.0.2.0/24`]{#cidr-aggregate-24 .correct explanation="Два смежных выровненных диапазона `/25` различаются только следующим битом и имеют общий префикс `/24`."}
:::

## Маршрутизация по самому длинному префиксу

При пересечении маршрутов для пересылки обычно выбирается подходящий маршрут с самым длинным совпадающим префиксом. Маршрут `/24` конкретнее охватывающего его `/16`, а маршрут по умолчанию `/0` побеждает только тогда, когда не найден другой подходящий, более конкретный маршрут.

:::single-choice{#cidr-route-specificity} Какой подходящий маршрут конкретнее для назначения `10.42.3.8`?

::option[`10.42.3.0/24`]{#cidr-route-24 .correct explanation="Совпадение по 24 битам длиннее и потому конкретнее, чем `/8`."}
::option[`10.0.0.0/8`]{#cidr-route-8 explanation="Этот маршрут совпадает, но фиксирует меньше битов назначения."}
::option[`0.0.0.0/0`]{#cidr-default explanation="Маршрут по умолчанию — наименее конкретный возможный префикс IPv4."}
:::

## Итоги

Теперь вы можете использовать запись CIDR как для диапазонов адресов, так и для выбора маршрута.

1. Интерпретируйте число после косой черты как количество начальных битов префикса.
2. Вычисляйте полный размер диапазона по числу оставшихся битов.
3. Канонизируйте префикс до его выровненной сетевой границы.
4. Агрегируйте только смежные выровненные диапазоны с корректной достижимостью.
5. При поиске маршрута отдавайте предпочтение самому длинному подходящему префиксу.
