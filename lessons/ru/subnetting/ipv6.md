IPv6 использует 128-битные адреса и был разработан для поддержки значительно большего адресного пространства, а также обновлённого поведения пакетов и обнаружения соседей. IPv4 и IPv6 — отдельные протоколы; в переходный период узлы с двойным стеком могут работать с обоими.

## Чтение записи IPv6

Адрес IPv6 записывается как восемь 16-битных шестнадцатеричных групп:

```text
2001:0db8:0000:0000:0000:0000:0000:0025
```

Начальные нули в каждой группе можно опустить, а одну непрерывную последовательность нулевых групп — сократить с помощью `::`:

```text
2001:db8::25
```

`::` может встречаться только один раз, иначе количество пропущенных групп было бы неоднозначным. `2001:db8::/32` зарезервирован для примеров в документации.

:::single-choice{#ipv6-double-colon-rule}
Почему `::` может встречаться в адресе IPv6 не более одного раза?

::option[Несколько маркеров `::` сделали бы развёртывание неоднозначным.]{#ipv6-compression-ambiguity .correct explanation="Один маркер сокращения можно развернуть ровно до нужного для восьми числа групп."}
::option[Адрес IPv6 содержит только один нулевой бит.]{#ipv6-one-zero explanation="Адрес может содержать множество нулевых битов и групп."}
::option[Этот маркер выбирает нулевой порт TCP.]{#ipv6-port-zero explanation="Сокращение адреса не связано с транспортными портами."}
:::

## Типы адресов и области действия

К важным адресам и диапазонам относятся:

- `::1/128`: loopback на локальном узле.
- `fe80::/10`: одноадресные link-local-адреса; обычно присутствуют на интерфейсах IPv6.
- `2000::/3`: выделенное в настоящее время пространство глобальных одноадресных адресов.
- `ff00::/8`: групповая адресация.

В IPv6 нет широковещательного адреса; групповая адресация и Neighbor Discovery решают задачи, для которых IPv4 часто использует широковещание. Для link-local-назначения может потребоваться зона интерфейса, например `fe80::1%eth0`, поскольку один и тот же префикс существует в каждом канале.

:::single-choice{#ipv6-link-local-scope}
Какова обычная область действия адреса `fe80::/10`?

::option[Все узлы глобального Интернета.]{#ipv6-global-link-local explanation="Для глобально маршрутизируемой области служат глобальные одноадресные адреса."}
::option[Только файл зоны DNS.]{#ipv6-dns-only explanation="Link-local-адреса назначаются интерфейсам и используются в сетях."}
::option[Один локальный канал.]{#ipv6-one-link .correct explanation="Маршрутизаторы не пересылают обычный link-local-трафик между каналами."}
:::

## Префиксы и адреса интерфейса

В записи CIDR для IPv6 используется длина префикса от `/0` до `/128`. `/64` — стандартный размер большинства подсетей LAN, поддерживающий Stateless Address Autoconfiguration. Один интерфейс может одновременно иметь link-local-адрес, стабильный глобальный адрес, временный адрес для конфиденциальности и другие адреса, каждый со своим предпочтительным и действительным сроком жизни.

:::single-choice{#ipv6-address-multiplicity}
Почему у одного интерфейса может отображаться несколько адресов IPv6?

::option[IPv6 требует отдельного адреса для каждой шестнадцатеричной цифры.]{#ipv6-one-per-digit explanation="Цифры являются формой представления, а не отдельными назначениями интерфейса."}
::option[Одновременно могут существовать адреса разных областей действия и ролей конфиденциальности или срока жизни.]{#ipv6-several-roles .correct explanation="Наличие link-local-адреса и одного или нескольких глобальных либо временных адресов нормально."}
::option[Каждый адрес обозначает отдельную физическую сетевую карту.]{#ipv6-separate-card explanation="Один интерфейс может владеть несколькими адресами."}
:::

## Обнаружение соседей и маршрутизаторов

Neighbor Discovery в IPv6 использует ICMPv6 для разрешения адресов, обнаружения дублирующихся адресов, поиска маршрутизаторов и получения сведений о достижимости. Router Advertisements могут предоставлять префиксы и информацию о маршрутизаторе по умолчанию. Узлы могут сочетать SLAAC с DHCPv6 для получения других параметров; обычно DHCPv6 не предоставляет маршрутизатор по умолчанию.

Блокировка всего ICMPv6 нарушает важнейшие функции протокола. Политика межсетевого экрана должна разрешать необходимые типы сообщений с подходящей областью действия, а не считать ICMPv6 необязательным.

:::single-choice{#ipv6-default-router-source}
Как узел IPv6 обычно динамически узнаёт маршрутизатор по умолчанию?

::option[Из Router Advertisements.]{#ipv6-router-advertisements .correct explanation="Router Discovery является частью Neighbor Discovery на основе ICMPv6."}
::option[Из широковещательного адреса Ethernet.]{#ipv6-ethernet-broadcast explanation="IPv6 не использует широковещательный IP-адрес."}
::option[Из трёхэтапного рукопожатия TCP.]{#ipv6-tcp-handshake explanation="TCP устанавливает транспортное состояние после того, как маршрутизация уже доступна."}
:::

## Проверка и тестирование IPv6

Проверяйте адреса, маршруты и соседей независимо:

```bash
$ ip -6 address show
$ ip -6 route show
$ ip -6 neighbor show
$ ping -6 -c 3 2001:db8::25
```

Вместо показанного адреса для документации используйте реально назначенный тестовый адрес. Приложение с двойным стеком может успешно работать через IPv4 при неисправном IPv6 или наоборот, поэтому проверяйте каждое семейство и его DNS-записи `A` или `AAAA` отдельно.

:::single-choice{#ipv6-dual-stack-test}
Почему IPv4 и IPv6 для службы с двойным стеком следует проверять отдельно?

::option[Каждый пакет IPv6 сначала должен стать широковещательным пакетом IPv4.]{#ipv6-becomes-ipv4 explanation="Нативные IPv6 и IPv4 используют разные пути протоколов."}
::option[У двух семейств могут различаться DNS, маршруты, фильтры и неисправности.]{#ipv6-independent-paths .correct explanation="Успешный переход на резервное семейство может скрыть неисправность предпочтительного."}
::option[Инструменты IPv6 не умеют отображать состояние интерфейсов.]{#ipv6-tools-cannot explanation="Команды `ip -6` показывают состояние адресов, маршрутов и соседей."}
:::

Теперь вы можете читать и проверять распространённое состояние интерфейсов и маршрутизации IPv6.

2. Различайте области loopback, link-local, глобальной и групповой адресации.
3. Ожидайте несколько адресов IPv6 с разными сроками жизни на одном интерфейсе.
4. Сохраняйте необходимый трафик Neighbor Discovery и Router Advertisement.
5. Проверяйте пути IPv4 и IPv6 для служб с двойным стеком независимо.
