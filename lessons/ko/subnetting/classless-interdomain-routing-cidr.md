CIDR(Classless Inter-Domain Routing)은 과거의 주소 클래스에 의존하지 않고 접두사 길이로 주소 범위를 나타냅니다. CIDR은 IPv4와 IPv6에서 가변 크기 할당, 서브넷팅 및 경로 집계를 지원합니다.

## 접두사 표기 읽기

`10.42.3.17/24`에서 앞 24비트는 네트워크 접두사이고 범위 안의 위치에 8비트가 남습니다. 정규 네트워크는 `10.42.3.0/24`이며 인터페이스를 설정할 때는 제공된 호스트 주소에 접두사를 붙여 쓸 수 있습니다.

:::single-choice{#cidr-prefix-meaning} IPv4 CIDR 값에서 `/24`는 무엇을 지정합니까?

::option[앞쪽 네트워크 접두사 비트 24개입니다.]{#cidr-24-prefix-bits .correct explanation="IPv4 32비트 중 나머지 8비트가 접두사 안에서 변합니다."}
::option[모든 서브넷에서 사용 가능한 주소 24개입니다.]{#cidr-24-addresses explanation="/24에는 전체 주소 값 256개가 있습니다."}
::option[네트워크의 TCP 목적지 포트입니다.]{#cidr-24-port explanation="CIDR과 전송 포트는 독립적입니다."}
:::

## 범위 크기 계산하기

IPv4 접두사 `/23`은 호스트 비트 9개를 남기므로 `2^9 = 512`개의 전체 주소를 포함합니다. 정렬된 `123.12.24.0/23` 접두사의 범위는 다음과 같습니다.

```text
first: 123.12.24.0
last:  123.12.25.255
```

전통적인 브로드캐스트 사용에서는 첫 주소가 네트워크 주소이고 마지막 주소가 지향성 브로드캐스트입니다. `/31` 지점 간 링크나 `/32` 호스트 경로에 “2를 빼는” 사용 가능 호스트 단축 공식을 무작정 적용하지 마십시오.

:::single-choice{#cidr-23-total} IPv4 `/23`에는 총 몇 개의 주소가 있습니까?

::option[512개입니다.]{#cidr-total-512 .correct explanation="변하는 비트 9개로 2^9개 조합을 만듭니다."}
::option[23개입니다.]{#cidr-total-23 explanation="접두사 숫자는 주소 수가 아니라 고정된 비트 수입니다."}
::option[510개입니다.]{#cidr-total-510 explanation="특수 끝점을 뺀 전통적인 사용 가능 수이며 전체 범위 크기가 아닙니다."}
:::

## 정렬 확인하기

접두사는 이진 경계에서 시작해야 합니다. 앞쪽 옥텟이 고정된 경우 `/23`은 셋째 옥텟에서 2단위 블록으로 증가하므로 `123.12.24.0/23`은 정렬됐지만 `123.12.25.0/23`은 같은 `123.12.24.0/23` 범위로 정규화됩니다.

:::single-choice{#cidr-canonical-25} `123.12.25.0`을 포함하는 정규 `/23` 네트워크는 무엇입니까?

::option[25에서 시작하는 `123.12.25.0/23`뿐입니다.]{#cidr-25-unaligned explanation="마지막 접두사 비트는 셋째 옥텟 값을 정렬된 쌍으로 묶습니다."}
::option[`123.12.0.0/23`]{#cidr-third-zero explanation="다른 /23 범위를 설명합니다."}
::option[`123.12.24.0/23`]{#cidr-24-canonical .correct explanation="셋째 옥텟 값 24와 25는 같은 정렬된 23비트 접두사를 공유합니다."}
:::

## 경로 집계하기

CIDR은 연속되고 크기가 같으며 올바르게 정렬된 여러 접두사를 하나의 집계로 광고할 수 있습니다. 예를 들어 `192.0.2.0/25`와 `192.0.2.128/25`는 `192.0.2.0/24`로 결합됩니다. 광고하는 라우터가 전체 집계에 올바르게 도달할 수 있거나 루프와 블랙홀을 막는 정책이 있을 때만 안전합니다.

:::single-choice{#cidr-aggregate-two-25s} `192.0.2.0/24`의 양쪽 절반을 모두 포함하는 집계는 무엇입니까?

::option[`192.0.2.0/26`]{#cidr-aggregate-26 explanation="/26은 주소 64개만 포함하므로 각 절반보다 작습니다."}
::option[`192.0.3.0/25`]{#cidr-aggregate-other explanation="제시된 주소 범위 밖에 있습니다."}
::option[`192.0.2.0/24`]{#cidr-aggregate-24 .correct explanation="연속되고 정렬된 두 /25 범위는 다음 비트만 다르며 /24 접두사를 공유합니다."}
:::

## 최장 접두사 라우팅

경로가 겹칠 때는 일반적으로 일치하는 접두사가 가장 긴 적격 경로를 선택해 전달합니다. `/24` 경로는 이를 포함하는 `/16`보다 구체적이고, 기본 경로 `/0`은 더 구체적인 적격 경로가 없을 때만 선택됩니다.

:::single-choice{#cidr-route-specificity} 목적지 `10.42.3.8`에 대해 어느 적격 경로가 더 구체적입니까?

::option[`10.42.3.0/24`]{#cidr-route-24 .correct explanation="24비트 일치는 /8보다 길어 더 구체적입니다."}
::option[`10.0.0.0/8`]{#cidr-route-8 explanation="일치하지만 더 적은 목적지 비트를 고정합니다."}
::option[`0.0.0.0/0`]{#cidr-default explanation="기본 경로는 가능한 가장 덜 구체적인 IPv4 접두사입니다."}
:::

## 요약

이제 주소 범위와 경로 선택에 CIDR 표기법을 사용할 수 있습니다.

1. 슬래시 값을 앞쪽 접두사 비트 수로 해석합니다.
2. 남은 비트에서 전체 범위 크기를 계산합니다.
3. 접두사를 정렬된 네트워크 경계로 정규화합니다.
4. 유효한 연결 범위를 가진 연속되고 정렬된 범위만 집계합니다.
5. 경로 조회 중 가장 긴 적격 접두사를 우선합니다.
