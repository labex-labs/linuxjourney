クラスレスドメイン間ルーティング（CIDR）は、従来のアドレスクラスに依存せず、プレフィックス長を使ってアドレス範囲を表します。CIDR は、IPv4 と IPv6 で可変サイズの割り当て、サブネット化、経路集約を可能にします。

## プレフィックス表記を読む

`10.42.3.17/24` では、先頭24ビットがネットワークプレフィックスで、範囲内の位置を表す8ビットが残ります。正規のネットワークは `10.42.3.0/24` ですが、インターフェースを設定するときは、指定したホストアドレスにプレフィックスを付けて記述できます。

:::single-choice{#cidr-prefix-meaning} IPv4 の CIDR 値にある `/24` は何を指定しますか？

::option[先頭から24個のネットワークプレフィックスビット。]{#cidr-24-prefix-bits .correct explanation="IPv4 の32ビットのうち、残り8ビットがプレフィックス内で変化します。"}
::option[すべてのサブネットで利用可能な24個のアドレス。]{#cidr-24-addresses explanation="`/24` には合計256個のアドレス値があります。"}
::option[ネットワークの TCP 宛先ポート。]{#cidr-24-port explanation="CIDR とトランスポート層のポートは互いに独立しています。"}
:::

## 範囲の大きさを計算する

IPv4 の `/23` プレフィックスではホストビットが9個残るため、合計 `2^9 = 512` 個のアドレスを含みます。境界に揃ったプレフィックス `123.12.24.0/23` の範囲は次のとおりです。

```text
first: 123.12.24.0
last:  123.12.25.255
```

従来のブロードキャスト用途では、先頭がネットワークアドレス、末尾がディレクテッドブロードキャストです。ただし、「2を引く」という利用可能ホスト数の近道を、ポイントツーポイント用の `/31` やホストルート用の `/32` に無条件で適用してはいけません。

:::single-choice{#cidr-23-total} `/23` に含まれる IPv4 アドレスの総数はいくつですか？

::option[512]{#cidr-total-512 .correct explanation="変化する9ビットから 2^9 通りの組み合わせが得られます。"}
::option[23]{#cidr-total-23 explanation="プレフィックスの数値は固定ビット数であり、アドレス数ではありません。"}
::option[510]{#cidr-total-510 explanation="これは特別な両端のアドレスを除いた従来の利用可能数であり、範囲全体の大きさではありません。"}
:::

## 境界との整合を確認する

プレフィックスは2進数上の境界から始まる必要があります。`/23` は、それより前のオクテットが固定されている場合、第3オクテットで2ずつ進みます。そのため、`123.12.24.0/23` は境界に揃っていますが、`123.12.25.0/23` を正規化すると同じ `123.12.24.0/23` の範囲になります。

:::single-choice{#cidr-canonical-25} `123.12.25.0` を含む正規の `/23` ネットワークはどれですか？

::option[25から始まる `123.12.25.0/23` だけ。]{#cidr-25-unaligned explanation="最後のプレフィックスビットは、第3オクテットの値を境界の揃ったペアにまとめます。"}
::option[`123.12.0.0/23`]{#cidr-third-zero explanation="これは別の `/23` 範囲を表します。"}
::option[`123.12.24.0/23`]{#cidr-24-canonical .correct explanation="第3オクテットの24と25は、境界の揃った同じ23ビットプレフィックスを共有します。"}
:::

## 経路を集約する

CIDR では、連続し、同じ大きさで、正しい境界に揃った複数のプレフィックスを一つの集約経路として広告できます。たとえば、`192.0.2.0/25` と `192.0.2.128/25` は `192.0.2.0/24` にまとめられます。集約が安全なのは、広告するルーターが集約範囲全体へ正しく到達できるか、ループやブラックホールを防ぐポリシーを持つ場合だけです。

:::single-choice{#cidr-aggregate-two-25s} `192.0.2.0/24` の前半と後半の両方を含む集約経路はどれですか？

::option[`192.0.2.0/26`]{#cidr-aggregate-26 explanation="`/26` は64個のアドレスしか含まず、どちらの半分よりも小さい範囲です。"}
::option[`192.0.3.0/25`]{#cidr-aggregate-other explanation="これは指定されたアドレス範囲の外です。"}
::option[`192.0.2.0/24`]{#cidr-aggregate-24 .correct explanation="連続して境界の揃った二つの `/25` 範囲は次の1ビットだけが異なり、`/24` プレフィックスを共有します。"}
:::

## 最長プレフィックスによるルーティング

経路が重複する場合、転送では通常、適用可能な経路のうち一致するプレフィックスが最も長いものを選びます。`/24` の経路は、それを含む `/16` より具体的です。一方、デフォルトルート `/0` が選ばれるのは、より具体的な適用可能経路がない場合だけです。

:::single-choice{#cidr-route-specificity} 宛先 `10.42.3.8` に対して、より具体的な適用可能経路はどれですか？

::option[`10.42.3.0/24`]{#cidr-route-24 .correct explanation="24ビットの一致は `/8` より長いため、より具体的です。"}
::option[`10.0.0.0/8`]{#cidr-route-8 explanation="これは一致しますが、固定する宛先ビットが少ない経路です。"}
::option[`0.0.0.0/0`]{#cidr-default explanation="デフォルトルートは、IPv4 で最も具体性の低いプレフィックスです。"}
:::

## まとめ

アドレス範囲と経路選択の両方で CIDR 表記を使えるようになりました。

1. スラッシュの後の値を、先頭からのプレフィックスビット数として解釈する。
2. 残りのビット数から範囲全体の大きさを計算する。
3. プレフィックスを境界に揃った正規のネットワークへ変換する。
4. 到達性が正しい、連続して境界の揃った範囲だけを集約する。
5. 経路検索では、適用可能な最長プレフィックスを優先する。
