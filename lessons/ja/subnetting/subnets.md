サブネットとは、ネットワークプレフィックスによって定義される IP アドレス範囲です。同じサブネットのホストは同一のローカルリンク上にあることが多いものの、物理的な近さが定義なのではありません。VLAN、トンネル、オーバーレイ、ルーテッドリンクによってトポロジーは変わります。

## プレフィックスとマスク

IPv4 の24ビットプレフィックスは、`/24` またはマスク `255.255.255.0` で表せます。2進表記では、一般的に有効なサブネットマスクは連続する1の後に0が続きます。

```text
11111111.11111111.11111111.00000000
```

アドレス `192.168.1.8/24` のネットワークプレフィックスは `192.168.1.0/24` です。状況によっては `192.168.1.0/255.255.255.0` という記述も解釈されますが、標準的で簡潔なのは CIDR プレフィックス表記です。

:::single-choice{#subnets-mask-24} `/24` に対応するドット区切り10進表記のマスクはどれですか？

::option[`255.255.255.0`]{#subnets-mask-correct .correct explanation="完全なオクテット3個に、先頭から連続する24個の1ビットが入っています。"}
::option[`255.255.0.255`]{#subnets-noncontiguous explanation="ネットワークビットが連続していないため、一般的な `/24` マスクではありません。"}
::option[`0.0.0.24`]{#subnets-prefix-as-octet explanation="プレフィックス長をマスクの最後のオクテットに入れるわけではありません。"}
:::

## 宛先が同一リンク上かを判断する

Linux は、インターフェースに設定されたアドレスとプレフィックスから接続経路を作成します。単に10進表記の先頭3オクテットを比較するのではなく、利用可能な経路と宛先を照合します。`/20` のようにオクテット境界でないプレフィックスでは、区切りがオクテットの途中にあります。

接続経路と、あるアドレスに対する判断は次のコマンドで確認できます。

```bash
$ ip route show
$ ip route get 192.168.1.50
```

:::single-choice{#subnets-on-link-decision} Linux ホストは、直接送信するかルーター経由で送信するかをどう判断しますか？

::option[末尾が `.1` のアドレスは常にローカルだと見なす。]{#subnets-dot-one explanation="ホスト番号に関する慣習は、設定されたプレフィックスや経路の代わりにはなりません。"}
::option[プレフィックスとルーティングポリシーを参照する。]{#subnets-route-policy .correct explanation="選択された経路によって、宛先が同一リンク上にあるか、どのインターフェースまたはネクストホップを使うかが決まります。"}
::option[接続後、宛先アプリケーションにサブネットマスクを問い合わせる。]{#subnets-ask-application explanation="ルート選択は、そのようなアプリケーション間のやり取りより前に行う必要があります。"}
:::

## サブネット間のルーティング

適切なインターフェースと経路を持つルーターは、サブネット間でトラフィックを転送できます。デフォルトゲートウェイとは、デフォルトルートによって選択されるネクストホップにすぎません。最初の利用可能なアドレスである必要も、末尾が `.1` である必要もありません。

サブネットを分離すると、ルーティングやフィルタリングのポリシーを適用する場所ができますが、自動的にセキュリティ境界になるわけではありません。制限的なポリシーなしに転送が許可されていれば、異なるサブネットのホスト同士も通信できます。

:::single-choice{#subnets-security-boundary} サブネットを二つ作るだけで、その間のトラフィックは自動的に遮断されますか？

::option[はい。ルーターは異なるプレフィックスを接続できないから。]{#subnets-never-route explanation="異なるプレフィックスを接続することこそ、ルーティングの主要な役割です。"}
::option[いいえ。許可されるトラフィックはルーティングとフィルタリングのポリシーで決まる。]{#subnets-policy-required .correct explanation="セグメンテーションはポリシーを適用可能にしますが、それ自体がポリシーを定義するわけではありません。"}
::option[はい。ただし両方でホストアドレス `.1` を使う場合を除く。]{#subnets-dot-one-security explanation="ホスト番号に関する慣習は転送を制御しません。"}
:::

## サブネット化する理由

サブネット化には、アドレス割り当ての整理、リンク層のブロードキャスト範囲の制限、障害ドメインの分離、ポリシー境界の提供といった用途があります。その一方で、ルーティング、ファイアウォール、DHCP、監視、文書化が複雑になることもあります。小さいほど常に速いと思い込まず、実際の規模、成長、冗長性、セキュリティ要件に合わせてプレフィックスを設計してください。

:::single-choice{#subnets-design-tradeoff} サブネット化に実際に伴うトレードオフはどれですか？

::option[ブロードキャストドメインを小さくすれば、ルーティングも文書化も不要になる。]{#subnets-no-complexity explanation="境界を増やすほど、通常は経路、ポリシー、アドレス、サービスをさらに管理する必要があります。"}
::option[セグメンテーションで構成を整理できる一方、ポリシーは複雑になる場合がある。]{#subnets-tradeoff .correct explanation="サブネット境界は制御に役立ちますが、保守すべき運用状態も増やします。"}
::option[どのサブネットでもインターネットまでの遅延は必ず等しくなる。]{#subnets-equal-latency explanation="遅延は経路や負荷の状況によって決まります。"}
:::

## まとめ

IPv4 プレフィックスを、ローカル配送やルーティングポリシーと関連付けられるようになりました。

1. 連続したサブネットマスクを CIDR プレフィックス長で表す。
2. アドレスのビットとマスクからネットワークプレフィックスを求める。
3. 経路を使って、同一リンク上への配送かネクストホップへの配送かを判断する。
4. サブネットの分離を、保証ではなくポリシーを適用する機会として扱う。
